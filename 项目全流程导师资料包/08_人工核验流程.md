# 08 人工核验流程

本文件是你可以照着做的验收清单。每一步都写了在哪里操作、运行什么命令、看哪里、正常现象是什么、失败时查什么、截图截哪里。

## 8.1 准备环境

### Windows 本机

操作位置：PowerShell。

```powershell
cd "D:\Luo_docs\竞赛\研创赛\memguardos"
python --version
git rev-parse --short HEAD
```

正常现象：

1. 当前目录进入 `memguardos`。
2. Python 可用。
3. Git HEAD 输出类似 `e0f0a7d`。

截图：截 PowerShell 命令和输出。建议文件名：`01_windows_git_head.png`。

失败处理：

1. 如果 `python` 不存在，检查 Python 安装和 PATH。
2. 如果不是 git 仓库，确认你进入的是 `memguardos` 根目录。

### openKylin 虚拟机

操作位置：Windows PowerShell 通过 SSH。

```powershell
ssh -i "$HOME\.ssh\id_ed25519" luo@192.168.73.128 "cd ~/memguardos && pwd && .venv/bin/python --version"
```

正常现象：输出 `/home/luo/memguardos` 和 Python 版本。

截图：`02_openkylin_ssh_env.png`。

失败处理：

1. 如果 SSH 连不上，确认虚拟机开机、IP 是否仍是 `192.168.73.128`。
2. 如果 `.venv/bin/python` 不存在，说明虚拟环境缺失，需要重新安装依赖。

## 8.2 自动测试核验

### 本地 pytest

```powershell
python -m pytest -q
```

正常现象：输出 `70 passed`。

截图：`03_pytest_70_passed.png`。

通过标准：没有 `failed`、`error`、`xfailed` 等失败项。

失败时检查：

1. 先看失败用例名。
2. 再打开 `tests/test_core.py` 或对应测试文件。
3. 如果是环境相关，先跑 `python -m memguard.cli.memctl doctor`。

### 竞赛就绪自检

```powershell
python scripts\check_competition_ready.py --output docs\competition_ready.json --markdown docs\竞赛就绪自检报告.md
```

正常现象：`ok: true`，`total: 136`，`passed: 136`，`failed: 0`，`warnings: 0`。

截图：`04_competition_ready_136.png`。

失败时检查：

1. `category` 告诉你哪类失败。
2. `name` 是具体失败项。
3. `detail` 会说明缺什么或指标不达标。

### Web 控制台 smoke

```powershell
python scripts\web_dashboard_smoke.py
```

正常现象：所有字段为 true，特别是：

```json
"page_ok": true,
"auth_required_for_diagnostics": true,
"token_session_storage_ok": true,
"html_security_headers_ok": true,
"json_security_headers_ok": true
```

截图：`05_web_dashboard_smoke.png`。

失败时检查：

1. `memguard/web/dashboard.py`。
2. `scripts/web_dashboard_smoke.py`。
3. 端口是否被占用。

## 8.3 基础功能核验

### 写入偏好记忆

```powershell
python -m memguard.cli.memctl ingest --text "以后回答 Linux 命令时直接给命令和风险提示。"
```

正常现象：输出 JSON，包含：

```json
"stored": true,
"type": "preference"
```

截图：`06_ingest_preference.png`。

失败时检查：

1. `memguard/service.py::ingest_text`
2. `memguard/extraction/semantic.py`
3. `memguard/ingestion/quality.py`

### 检索记忆

```powershell
python -m memguard.cli.memctl search "Linux 命令回答偏好"
```

正常现象：返回至少一条相关结果，summary 中能看到刚才写入的意思。

截图：`07_search_preference.png`。

失败时检查：

1. 是否使用同一 namespace。
2. `memguard/retrieval/hybrid.py`
3. `memguard/store/sqlite_meta.py::search_text`

### 构建 RAG 上下文

```powershell
python -m memguard.cli.memctl build-context "openKylin 服务内存限制" --top-k 5 --token-budget 1200
```

正常现象：输出含 `context`、`budget`、`explainability`、`selection_trace`。

截图：`08_build_context_explainability.png`。

通过标准：能看到上下文内容和解释字段。

失败时检查：

1. `memguard/service.py::build_context`
2. 是否已有相关记忆。

## 8.4 敏感检测核验

### 高风险阻断

```powershell
python -m memguard.cli.memctl ingest --text "API_KEY=sk-1234567890abcdef"
```

正常现象：输出 `stored: false`，`reason: sensitive_block`。

截图：`09_sensitive_block.png`。

答辩解释：高风险凭据不会进入长期记忆。

### 中风险脱敏

```powershell
python -m memguard.cli.memctl ingest --text "我的联系电话是 13800138000"
python -m memguard.cli.memctl search "联系电话"
```

正常现象：存储内容中出现 `[REDACTED:phone_cn]`。

截图：`10_redaction_phone.png`。

失败时检查：`memguard/sensitivity/detector.py`。

## 8.5 精准遗忘核验

先写入：

```powershell
python -m memguard.cli.memctl ingest --text "temporary project codename blue-river"
```

dry-run：

```powershell
python -m memguard.cli.memctl forget "忘掉 temporary project codename"
```

正常现象：只返回候选，不删除。

确认删除并 compact：

```powershell
python -m memguard.cli.memctl forget "忘掉 temporary project codename" --yes --compact
```

验证：

```powershell
python -m memguard.cli.memctl verify-forget "temporary project codename"
```

正常现象：`irreversible_ok: true` 或等价验证通过。

截图：

1. `11_forget_dry_run.png`
2. `12_forget_confirm_compact.png`
3. `13_verify_forget.png`

失败时检查：

1. `memguard/forgetting/planner.py`
2. `memguard/service.py::forget`
3. `memguard/store/mmap_store.py`
4. `memguard/store/sqlite_meta.py::mark_deleted`

## 8.7 Web 控制台人工验收

启动：

```powershell
python -m memguard.cli.memctl web --host 127.0.0.1 --port 8765
```

打开浏览器：

```text
http://127.0.0.1:8765
```

操作步骤：

1. 截总览页，确认状态卡片、审计链、检索后端、SDK、OS 资源。
2. 切到“写入”，输入一条偏好，点击写入。
3. 切到“检索”，搜索关键词。
4. 切到“RAG 上下文”，构建上下文。
5. 切到“精准遗忘”，先 dry-run，再确认。
6. 切到“诊断”，点击导出诊断包。

1. `15_web_overview.png`
2. `16_web_ingest.png`
3. `17_web_search.png`
4. `18_web_context.png`
5. `19_web_forget.png`
