# 03 项目结构

## 3.1 根目录总览

当前项目根目录是 `D:\Luo_docs\竞赛\研创赛\memguardos`。你可以把它理解成一个完整软件工程，而不是只有一段脚本。根目录里最重要的部分是：

| 路径 | 类型 | 作用 |
|---|---|---|
| `README.md` | 项目入口文档 | 评委或开发者第一眼了解项目。 |
| `pyproject.toml` | Python 项目配置 | 定义包名、版本、Python 版本、依赖和命令入口。 |
| `memguard/` | 主程序源码 | 所有核心功能都在这里。 |
| `scripts/` | 脚本 | 安装、测试、打包、证据采集、openKylin 验证。 |
| `tests/` | 自动测试 | pytest 测试用例。 |
| `data/` | 输入样例和 benchmark | demo 数据、评测数据、真实风格样例。 |
| `docs/` | 文档和证据 | 设计、部署、测试、答辩、openKylin 证据。 |
| `native/` | 原生增强源码 | BPF LSM、Peony、UKUI 插件。 |
| `dist/` | 生成产物 | 正式提交包、完整仓库包、.deb 包等。 |
| `PROJECT_INDEX.md` | 文件索引 | 已整理的中文项目文件说明。 |

## 3.2 程序入口在哪里

项目有多个入口，分别对应不同使用场景：

| 入口 | 用途 | 对应文件 |
|---|---|---|
| `memctl` | 命令行操作入口。 | `memguard/cli/memctl.py` |
| `memguardd` | 后台 daemon 服务入口。 | `memguard/daemon.py` |
| Web 控制台 | 本地浏览器操作入口。 | `memguard/web/dashboard.py` |
| Unix socket API | 给本地 Agent 调用的 JSON API。 | `memguard/api/server.py` |
| 评测入口 | 跑 benchmark 和性能测试。 | `memguard/eval/run_eval.py` |
| 演示 smoke | 快速跑写入、检索、遗忘、审计。 | `scripts/demo_smoke.py` |
| 竞赛自检 | 检查文档、源码、指标、证据。 | `scripts/check_competition_ready.py` |
| 提交包生成 | 生成竞赛提交 zip。 | `scripts/package_submission.py` |

`pyproject.toml` 中的 `[project.scripts]` 把 `memctl` 映射到 `memguard.cli.memctl:main`，把 `memguardd` 映射到 `memguard.daemon:main`。所以你在终端里运行 `memctl ingest ...`，最后会进入 `memguard/cli/memctl.py` 的 `main()` 函数。

## 3.3 核心源码目录

### 3.3.1 `memguard/service.py`

这是最核心的服务编排文件。你可以把它理解成“大脑调度中心”。它负责把输入接入、质量检查、敏感检测、抽取、存储、检索、遗忘、审计串起来。

关键函数：

| 函数 | 作用 |
|---|---|
| `ingest_text()` | 写入一条文本记忆。 |
| `ingest_tool_result()` | 导入工具执行结果。 |
| `ingest_config()` | 导入结构化配置。 |
| `ingest_shell_history()` | 导入 shell 历史。 |
| `ingest_os_event()` | 导入 OS 事件。 |
| `search()` | 检索记忆。 |
| `batch_search()` | 并发批量检索。 |
| `build_context()` | 构建 RAG 上下文包。 |
| `hierarchical_graph_search()` | 层次图谱检索。 |
| `forget()` | 规划或执行精准遗忘。 |
| `verify_forget_probe()` | 验证明文是否还残留。 |
| `verify_audit()` | 验证审计链。 |

### 3.3.2 `memguard/models.py`

这里定义记忆的数据结构，比如 `MemoryRecord`、`MemorySource`、`Sensitivity`、`VersionInfo`、`AuditInfo`。如果评委问“记忆到底长什么样”，就看这个文件。

### 3.3.3 `memguard/extraction/`

这是抽取模块，核心文件是 `semantic.py` 和 `entity.py`。

| 文件 | 作用 |
|---|---|
| `semantic.py` | 判断输入是偏好、知识还是敏感策略，并给出 summary、subtype、confidence。 |
| `entity.py` | 从文本中抽取实体和简单关系，用于图谱检索。 |

### 3.3.4 `memguard/sensitivity/`

这是敏感治理模块。

| 文件 | 作用 |
|---|---|
| `detector.py` | 内置手机号、邮箱、API key、私钥、敏感路径等检测。 |
| `custom_patterns.py` | 自定义敏感规则和自然语言规则生成。 |

### 3.3.5 `memguard/store/`

这是存储模块。

| 文件 | 作用 |
|---|---|
| `mmap_store.py` | 追加式段文件，保存完整记忆版本和 tombstone。 |
| `sqlite_meta.py` | SQLite 元数据、FTS、图谱关系、审计链。 |

### 3.3.6 `memguard/retrieval/`

这是检索模块。

| 文件 | 作用 |
|---|---|
| `hybrid.py` | 混合检索，结合 FTS、hash-vector、图谱、跨语言 token。 |
| `conflict.py` | 处理偏好冲突，避免旧偏好压过新偏好。 |
| `kylin_sdk.py` | openKylin Kylin embedding/vector SDK 探测和调用。 |

### 3.3.7 `memguard/forgetting/`

`planner.py` 用自然语言遗忘请求生成候选计划。它不会直接删除，而是先找候选、给出分数和匹配关键词，等待确认。

### 3.3.8 `memguard/os_guard/`

这是操作系统机制适配模块。

| 文件 | 作用 |
|---|---|
| `events.py` | 解析 OS 事件。 |
| `auditd.py` | 生成 auditd 规则。 |
| `auditd_events.py` | 解析 auditd 日志。 |
| `cgroup.py` | 检查 cgroup 状态。 |
| `journald.py` | 连接 systemd/journald 日志。 |
| `doctor.py` | 系统诊断。 |

### 3.3.9 `memguard/api/` 和 `memguard/web/`

`api/server.py` 是本地 Unix socket JSON API。`web/dashboard.py` 是本地 Web 控制台。控制台现在有 Bearer Token、sessionStorage、CSP、安全响应头和 smoke 覆盖。
