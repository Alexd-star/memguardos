# 02 术语词典

本词典从当前项目文档、代码、测试输出和证据包中整理。每个术语都尽量按“中文意思、通俗解释、技术含义、本项目含义、人工核验、截图证据、答辩解释”来写。你遇到不懂的词，先查这个文件。

## 2.2 项目核心术语

| 术语 | 中文意思 | 通俗解释 | 技术含义 | 本项目含义 | 如何人工核验 | 截图证据 | 答辩解释 |
|---|---|---|---|---|---|---|---|
| Agent | 智能体 | 能读信息、做计划、调用工具、执行任务的 AI 助手。 | LLM + 工具调用 + 状态管理的系统。 | MemGuardOS 服务对象是 Linux OS Agent。 | 看 README 项目定位；运行 `build-context`。 | README 和命令输出截图。 | “我们做的是给 OS Agent 用的长期记忆基础设施。” |
| Memory | 记忆 | 系统记住的偏好、知识或策略。 | 结构化记录，包含内容、类型、来源、版本、敏感等级。 | `MemoryRecord` 定义在 `memguard/models.py`。 | 运行 `memctl ingest` 后看 JSON。 | 记忆 ID、type、subtype 截图。 | “记忆不是原始聊天记录，而是结构化、可审计记录。” |
| Preference memory | 偏好记忆 | 用户喜欢系统怎样回答或怎样做。 | memory_type 为 preference。 | 由 `HybridMemoryExtractor.extract()` 判断。 | 输入“以后回答 Linux 命令时先给风险”。 | `type: preference` 截图。 | “偏好记忆让 Agent 知道用户长期习惯。” |
| Knowledge memory | 知识记忆 | 可复用事实、流程、故障经验。 | memory_type 为 knowledge。 | 工具轨迹、OS 事件、技术事实通常归为知识。 | 导入工具结果或 systemd 文本。 | `type: knowledge` 截图。 | “知识记忆用于以后检索和 RAG。” |
| Sensitive policy | 敏感策略记忆 | 安全相关规则或策略。 | memory_type 为 sensitive_policy。 | 例如 RAG 脱敏预算、禁止存储高风险凭据。 | 运行敏感检测样例。 | 输出中的 `sensitive_policy`。 | “安全策略让系统知道哪些信息需要保护。” |
| RAG | 检索增强生成 | 先查资料再让模型回答。 | Retrieval-Augmented Generation。 | `build-context` 生成给 LLM 的上下文包。 | `memctl build-context "openKylin 服务内存限制"`。 | context、explainability 截图。 | “我们重点做的是生成前记忆治理，不是大模型本身。” |
| Token budget | token 预算 | 给模型的上下文长度限制。 | 估算上下文 token 数，避免超长。 | `build_context(... token_budget=...)`。 | 加 `--token-budget 1200`。 | 输出 `budget` 字段。 | “上下文在预算内选择记忆，减少无关和超长输入。” |
| Explainability | 可解释性 | 为什么选中这些记忆。 | 输出来源分布、类型分布、选择轨迹。 | `build-context` 返回 `explainability`。 | 查看 JSON 中 `selection_trace`。 | 截 `explainability`。 | “评委能看到系统不是黑盒乱选。” |

| Precise forgetting | 精准遗忘 | 按自然语言请求精准删除相关记忆。 | 候选规划、确认、tombstone、索引清理、compact。 | `MemGuardService.forget()`。 | `memctl forget "忘掉 temporary project codename"`。 | dry-run 和 confirm 输出。 | “不是简单删除，而是可验证遗忘流程。” |

## 2.4 需要特别小心的术语

有些词听起来很厉害，但当前项目不能乱用：

1. “企业级 RBAC”：当前没有完整企业多用户权限系统，只能说本地 token 和 socket 权限。
2. “生产级内核拦截”：当前 BPF LSM 是安全测试路径，不是生产全系统策略。
3. “默认大模型抽取”：默认不是 LLM 抽取，是可解释规则和轻量策略。
4. “全量桌面行为采集”：当前覆盖 shell、工具结果、OS/auditd 等，不是捕获所有桌面行为。
5. “其他项目指标”：不要把非 MemGuardOS 的示例词、数据库指标或平台输出混进本项目答辩材料。当前项目的真实口径以 pytest、竞赛就绪自检、评测 JSON、openKylin 证据和提交包审计为准。
