# 11 风险审查

本文件站在严格评委和老师角度看项目，重点不是夸项目，而是指出哪些地方容易被追问，以及你应该怎么答。

## 11.1 已知边界和风险点

| 风险点 | 严重程度 | 真实情况 | 应对方式 |
|---|---|---|---|
| 默认抽取器不是大模型 | 中 | 默认是可解释规则和轻量语义信号。 | 主动解释端侧、离线、可复现，保留 LLM 增强接口。 |
| benchmark 是自建 | 中 | 当前用例/种子 217，不是官方海量数据集。 | 强调真实风格样例和可复现；不要说覆盖所有真实世界。 |
| Web 控制台不是完整企业 UI | 低-中 | 是本地运维控制台，不是 SaaS 后台。 | 强调 OS Agent 本地组件定位。 |
| 没有完整 RBAC/SSO | 中 | 只有本地 token 和 socket 权限。 | 不夸大，说明本地安全边界和未来扩展。 |
| BPF LSM 不是生产级全系统拦截 | 高 | 当前是安全测试路径。 | 只说指定测试文件强制拒绝验证，不说默认拦截系统登录链路。 |
| Peony/UKUI 不是完整商业插件体系 | 中 | 有源码、构建、可见性和 smoke。 | 说“桌面入口和闭环验证”，不说“完整桌面安全产品”。 |
| Kylin SDK 不是唯一主路径 | 中 | 已真实探针，可选增强，保留 fallback。 | 说“可选增强 + fallback”，不要说“全部依赖 SDK”。 |
| openKylin 证据和当前复跑测试数不同 | 低 | 证据包 68 passed，当前 VM 可 70 passed。 | 说明采集时间和代码同步差异，提交前可再刷新证据。 |
| 混入其他项目示例指标 | 高 | 本项目真实指标是 pytest、自检、评测 JSON、openKylin 证据和提交包审计。 | 平台摘要、PPT、答辩稿只写 MemGuardOS 真实口径。 |
| 过多文档可能让人找不到重点 | 中 | docs 很多。 | 推荐阅读顺序：项目介绍、符合性、测试报告、证据索引、答辩稿。 |

## 11.2 硬编码和假输出审查

当前项目有一些固定测试数据和 demo 数据，这不是“假输出”，但答辩要讲清楚它们的用途。

| 项目 | 是否硬编码 | 解释 |
|---|---|---|
| `data/demo/*.json` | 是 demo 样例 | 用于可复现演示，不是生产数据。 |
| `data/benchmarks/*.jsonl` | 是固定 benchmark | 用于可重复评测，不能说覆盖所有真实输入。 |
| `docs/evidence/latest/*` | 是采集证据 | 是 openKylin 已采集输出，不是运行时代码返回的假结果。 |
| `scripts/check_competition_ready.py` 阈值 | 是项目自检阈值 | 用来做质量门禁，不等于官方评分。 |
| Web 控制台能力卡片 | 有固定展示文案 | 只是说明能力和证据，不是伪造实时指标。 |

如何回答：  
“项目区分了 demo 数据、benchmark 数据、运行时输出和证据文件。demo 和 benchmark 是为了可复现；真正功能可以现场运行命令得到输出。”

## 11.4 评委最可能问穿的问题

### 问：你们的抽取为什么不用大模型？

答：默认链路选择可解释规则和结构化信号，是为了端侧部署、离线可复现和比赛现场稳定。项目保留 `MEMGUARD_EXTRACTOR_COMMAND` 和 LLM adapter，可以接本地 NER 或 LLM JSON 增强，但默认不依赖外部 API，避免不可控和不可复验。

### 问：指标都是 1.0000，会不会过拟合？

答：这是项目自建 benchmark 上的结果，不能说覆盖所有真实世界输入。我们通过真实风格 shell history、auditd 日志、工具失败修复轨迹、配置冲突、中文遗忘难例来降低玩具化风险。答辩中应承认 benchmark 边界，并强调可复现和证据链。

### 问：精准遗忘是不是只是删除数据库行？

答：不是。流程包括 dry-run 候选、确认删除、tombstone、SQLite 内容清除、FTS 删除、图谱边删除、compact 段文件和 verify-forget 明文探针验证。

### 问：Kylin SDK 是不是主检索路径？

答：在 openKylin 中已完成真实 embedding 探针和可选增强证据；默认链路仍保留 FTS/hash/graph fallback。这样设计是为了端侧稳定，SDK 可用时增强，不可用时系统仍能工作。

### 问：BPF LSM 是不是完整安全产品？

答：不是。当前是安全测试路径，对指定测试文件做强制拒绝验证，并支持 JSON denylist 生成静态 header。没有宣称默认拦截 `/etc/shadow`、SSH、sudo 或 PAM 链路。

### 问：Web 控制台能不能公网部署？

答：不建议。当前是 localhost 本地运维控制台，有 Bearer Token、sessionStorage、安全响应头，但没有企业级公网鉴权、TLS、SSO、RBAC、限流。公网部署需要额外安全架构。

## 11.5 待核验事项

以下不是代码缺失，而是最终提交/答辩前需要人工确认：

1. 最终演示视频是否录制完成。
2. openKylin 桌面 Peony 和 UKUI 当前会话是否仍可见。
3. 最新提交包是否上传的是 `memguardos_competition_submission_*.zip`，而不是 full repository 包。
4. 平台摘要、答辩 PPT、视频中的指标是否与最新证据一致。
5. 是否误用了其他项目示例指标，或把非本项目的测试数字写进平台摘要、PPT、答辩稿。
