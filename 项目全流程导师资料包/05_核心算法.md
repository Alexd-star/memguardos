# 05 核心算法

本项目没有一个单独叫“总算法”的文件，而是由几个算法模块组成：抽取、敏感检测、混合检索、RAG 上下文构建、精准遗忘、审计链。答辩时可以说“核心算法链路是多源输入治理 + 可解释记忆建模 + 混合检索 + 可验证遗忘”。

## 5.1 可解释语义抽取算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/extraction/semantic.py` |
| 核心类/函数 | `HybridMemoryExtractor.extract()` |
| 目的 | 判断一段输入应该成为偏好记忆、知识记忆还是安全策略记忆。 |
| 输入 | 文本 `text`，来源类型 `source_kind`。 |
| 输出 | `ExtractionDecision`，包含 `memory_type`、`subtype`、`summary`、`confidence`、`signals`。 |
| 关键变量 | 关键词信号、来源信号、程序性轨迹信号、安全策略信号。 |

### 处理步骤

1. 读取输入文本和来源类型。
2. 根据来源判断基本倾向。例如 `tool_result` 更容易是知识/程序性记忆，`manual_config` 可能是偏好或配置知识。
3. 根据关键词判断意图。例如“以后”“偏好”“回答风格”偏向 preference；“修复”“步骤”“systemd”“pytest”偏向 knowledge；“脱敏”“不要保存”“敏感”偏向 sensitive_policy。
4. 如果工具结果包含 `state_before`、`state_after`、`lesson`，则识别为状态-动作-结果程序性记忆。
5. 生成摘要、子类型和置信度。
6. 返回可解释信号 `signals`，便于答辩解释为什么这样分类。

### 简单手工样例

输入：

```text
以后回答 Linux 命令时直接给命令和风险提示。
```

手工理解：

1. “以后”表示长期偏好。
2. “回答 Linux 命令时”表示回答风格场景。
3. “直接给命令和风险提示”表示输出格式偏好。

算法结果应接近：

```json
{
  "memory_type": "preference",
  "subtype": "output_style",
  "summary": "偏好记忆：以后回答 Linux 命令时直接给命令和风险提示",
  "signals": ["preference_intent", "tool_preference_intent"]
}
```

### 边界情况

| 情况 | 处理 |
|---|---|
| 空文本 | 质量校验阶段拒绝。 |
| 同时包含偏好和安全策略 | 可能归为 sensitive_policy 或带多个 signals。 |
| 大模型增强失败 | 默认规则结果继续生效，不依赖外部 API。 |
| 输入很模糊 | 置信度较低，但仍会给出解释信号。 |

## 5.2 敏感检测与脱敏算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/sensitivity/detector.py` |
| 核心类/函数 | `SensitiveDetector.classify()`、`SensitiveDetector.redact()` |
| 目的 | 防止凭据、私钥、PII、高风险路径进入长期记忆。 |
| 输入 | 文本和 source_uri。 |
| 输出 | `Sensitivity`，包含 level、labels、redacted。 |

### 处理步骤

1. 用正则检测邮箱、手机号、身份证、银行卡、API key、AWS key、private key 等。
2. 用 OS 路径规则检测 `.ssh`、`.env`、`.aws/credentials`、`.kube/config`、`/etc/shadow` 等。
3. 结合文本内容和来源路径判断风险等级。
4. high 风险直接阻断，不写入长期记忆。
5. medium/low 风险替换为 `[REDACTED:xxx]` 后再存储。
6. 写入审计记录。

### 简单手工样例

输入：

```text
我的联系电话是 13800138000
```

结果：

1. 正则识别中国手机号。
2. 标签为 `phone_cn`。
3. 风险为 medium。
4. 存储文本变成：

```text
我的联系电话是 [REDACTED:phone_cn]
```

### 边界情况

| 情况 | 处理 |
|---|---|
| API key | high，阻断存储。 |
| `.ssh/id_rsa` 来源路径 | high，阻断存储。 |
| 普通中文短语 | 不应被误判为姓名。 |
| 自定义规则过宽 | `custom_patterns.py` 会做校验。 |

## 5.3 混合检索算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/retrieval/hybrid.py`、`memguard/store/sqlite_meta.py` |
| 核心函数 | `MemGuardService.search()`、`SQLiteMetaStore.search_text()` |
| 目的 | 找出与查询最相关的记忆。 |
| 输入 | 查询文本 query、top-k。 |
| 输出 | 排序后的记忆列表。 |

### 检索信号

1. SQLite FTS：关键词全文检索。
2. hash-vector：稳定轻量向量相似度。
3. 图谱关联：实体和关系命中。
4. 跨语言 token：中英文技术词扩展。
5. 时间有效性：只返回未删除、当前有效记忆。
6. 冲突处理：新偏好优先，避免旧偏好误导。

### 简单手工样例

已存入：

```text
以后回答 openKylin 服务问题时，先给 systemctl 命令。
```

查询：

```text
openKylin 服务怎么检查
```

可能命中原因：

1. `openKylin` 关键词命中。
2. `服务` 和 `systemctl` 是相关技术词。
3. 类型是偏好记忆，适合回答风格。
4. 记忆未删除，时间窗口有效。

输出会包含 `score`、`match_source`、`summary`、`tier` 等字段。

## 5.4 RAG 上下文构建算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/service.py` |
| 核心函数 | `build_context()` |
| 目的 | 把检索结果整理成给 LLM 使用的安全上下文。 |
| 输入 | query、limit、max_chars、token_budget。 |
| 输出 | context package，包含 memories、budget、explainability。 |

### 处理步骤

1. 先调用 `search()` 找相关记忆。
2. 过滤删除记忆和高风险内容。
3. 对中低风险内容保持脱敏。
4. 估算 token/字符预算。
5. 选择能放入预算的记忆。
6. 生成 `source_distribution`、`type_distribution`、`tier_distribution`。
7. 生成 `selection_trace`，解释每条候选纳入或过滤原因。

### 不能证明什么

`build-context` 能证明系统能构建生成前上下文，但不能证明某个外部 LLM 回答一定正确。因为 MemGuardOS 默认不调用外部 LLM，它负责的是记忆治理和上下文准备。

## 5.5 精准遗忘算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/forgetting/planner.py`、`memguard/service.py` |
| 核心函数 | `ForgetPlanner.plan()`、`MemGuardService.forget()` |
| 目的 | 根据自然语言请求定位并删除相关记忆。 |
| 输入 | 遗忘请求，例如“忘掉 temporary project codename”。 |
| 输出 | dry-run 候选或确认删除结果。 |

### 处理步骤

1. 从遗忘请求中提取关键词和实体。
2. 检索可能相关的记忆。
3. 计算候选分数和匹配关键词。
4. 如果没有 `--yes`，只返回候选，不删除。
5. 如果确认执行，写 tombstone。
6. 清理 SQLite 内容、FTS 索引、图谱边。
7. 如果加 `--compact`，压缩段文件，清理旧明文。
8. 用 `verify-forget` 检查明文是否残留。

### 简单手工样例

先写入：

```text
temporary project codename blue-river
```

执行 dry-run：

```powershell
python -m memguard.cli.memctl forget "忘掉 temporary project codename"
```

系统找到候选，因为关键词 `temporary`、`project`、`codename` 都命中。确认执行：

```powershell
python -m memguard.cli.memctl forget "忘掉 temporary project codename" --yes --compact
```

最后：

```powershell
python -m memguard.cli.memctl verify-forget "temporary project codename"
```

应该看到不可逆验证通过。

## 5.6 审计哈希链算法

| 项目 | 内容 |
|---|---|
| 文件 | `memguard/store/sqlite_meta.py` |
| 核心函数 | `add_audit()`、`verify_audit_chain()` |
| 目的 | 证明关键操作记录没有被篡改。 |
| 输入 | event_type、memory_id、detail。 |
| 输出 | prev_hash、event_hash、created_at。 |

每条审计事件计算：

```text
event_hash = SHA256(prev_hash | event_type | memory_id | detail | created_at)
```

如果有人改了中间某条记录，后面的哈希链会对不上，`verify-audit` 会返回失败。

### 人工演示

```powershell
python -m memguard.cli.memctl verify-audit
```

正常输出：

```json
{
  "ok": true,
  "checked": 14,
  "head_hash": "..."
}
```

答辩解释：

“审计链不是只把日志打印出来，而是每条日志都包含前一条日志的哈希。只要中间被改动，后续验证就会失败。”
