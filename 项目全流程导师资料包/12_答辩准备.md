# 12 答辩准备

## 12.1 1 分钟项目介绍

老师好，我们的项目叫 MemGuardOS，面向研究生操作系统开源创新大赛赛题 3“面向 Linux 的智能体记忆提取与精准遗忘机制”。项目解决的问题是：Linux OS Agent 在长期工作中会接触命令、配置、日志、工具调用结果和用户偏好，普通聊天历史无法判断哪些应该记住、哪些应该脱敏、哪些应该遗忘。MemGuardOS 提供一套端侧记忆基础设施，把多源输入提取为偏好记忆、知识记忆和安全策略记忆，经过敏感检测、轻量存储、混合检索后，为 Agent 构建可解释、已脱敏的 RAG 上下文；当用户要求遗忘时，系统会先生成候选，再确认删除、写 tombstone、清理索引、compact 段文件并通过审计链验证。项目已在 openKylin 上验证 systemd、cgroup、auditd、Kylin SDK、BPF LSM 测试路径、Peony 和 UKUI 桌面入口，并提供测试报告和证据包。

## 12.2 3 分钟项目讲解

我们的项目从一个实际问题出发：AI Agent 越来越多地参与 Linux 开发和运维工作，它会运行 `pytest`、查看 `journalctl`、修改配置、读日志、调用系统工具。如果这些过程只保存在普通对话里，Agent 很难长期复用经验，也很难处理隐私和遗忘请求。

MemGuardOS 的核心链路分为五层。第一层是多源接入，支持普通文本、文件、结构化配置、shell history、工具执行结果、OS 事件和 auditd 日志。第二层是安全治理，先做输入质量检查，再识别 API key、私钥、手机号、身份证、`.ssh`、`.env`、`/etc/shadow` 等敏感内容，高风险直接阻断，中低风险脱敏。第三层是记忆建模，系统会把输入识别为偏好记忆、知识记忆或安全策略记忆，并记录摘要、子类型、置信度、实体关系和来源。第四层是轻量存储和检索，项目使用 mmap 追加式段文件保存完整版本，用 SQLite 保存元数据、FTS、图谱和审计链，检索时结合全文、hash-vector、图谱关联、跨语言 token 和冲突处理。第五层是精准遗忘，用户用自然语言提出遗忘请求后，系统先 dry-run 给出候选和匹配原因，确认后写 tombstone、删除 FTS 和图谱索引、compact 段文件，并用明文探针验证遗忘结果。

操作系统机制方面，项目不是纯应用层 demo。我们提供 systemd daemon、cgroup 资源限制、journald 日志、auditd 敏感路径接入、BPF LSM 安全测试文件强制拒绝、Peony 文件右键入口、UKUI 控制中心入口，以及 Kylin embedding/vector SDK 探针和可选增强。当前证据中，openKylin 10k 负载 P95 为 10.844 ms，P99 为 106.095 ms，RSS 为 149284 KB；当前本地 pytest 为 70 passed，竞赛自检为 136/136 passed。

需要强调的是，我们没有把项目夸大成完整企业 SaaS。默认抽取链路是端侧可解释规则，不依赖外部 LLM API；Kylin SDK 是可选增强，fallback 仍然稳定；BPF LSM 是安全测试路径，不是生产级全系统拦截。我们的目标是在 openKylin/Linux 上做出一套可运行、可测试、可审计、可解释的智能体记忆与精准遗忘原型。

## 12.3 核心算法讲解稿

核心算法可以概括为“输入治理、语义记忆建模、混合检索、可验证遗忘”。输入进入系统后，`MemGuardService.ingest_text()` 先调用质量校验，避免空输入和低质量文本进入记忆；然后调用 `SensitiveDetector.classify()` 检测 PII、凭据和敏感路径，高风险阻断，中低风险脱敏；接着 `HybridMemoryExtractor.extract()` 根据来源、关键词、程序性轨迹信号和安全策略信号判断记忆类型，输出 preference、knowledge 或 sensitive_policy，并给出 subtype、summary 和 signals。之后系统把完整版本追加到 mmap 段文件，把可检索元数据、FTS 和图谱关系写入 SQLite，同时写审计哈希链。

检索时，系统不是单纯关键词搜索。`MemGuardService.search()` 会结合 SQLite FTS、稳定 hash-vector、实体图谱、跨语言技术词和冲突处理，对未删除且当前有效的记忆排序。构建 RAG 上下文时，`build_context()` 会在 token 预算内选择记忆，并返回 `explainability` 和 `selection_trace`，说明来源分布、类型分布、层级分布和每条候选为什么被纳入或过滤。

遗忘时，`ForgetPlanner.plan()` 先从自然语言请求中提取关键词和实体，匹配候选记忆。没有确认时只 dry-run，不删除；确认后 `forget()` 写 tombstone，清理 SQLite 内容、FTS 和图谱边；如果带 `--compact`，还会重写段文件，清理旧明文。最后 `verify-forget` 用明文探针检查是否仍有残留，`verify-audit` 校验审计链。

## 12.4 测试结果解释稿

当前本地 `python -m pytest -q` 输出 70 passed，说明项目在测试覆盖范围内通过了核心功能和回归测试。竞赛就绪自检为 136/136 passed，说明文档、源码、评测指标、openKylin 证据、提交包脚本和工程卫生都满足项目设定的门禁。Web 控制台 smoke 覆盖页面打开、写入、检索、诊断导出、鉴权、请求大小限制、sessionStorage token 和安全响应头。提交包审计和归档包 smoke 证明正式 zip 不缺关键文件、不混入禁入材料，并且解压后仍能运行核心演示。

这些测试能证明项目在当前代码、当前样例和当前证据范围内稳定可复现，但不能证明所有真实输入都一定正确，也不能证明它已经是完整商业产品。所以答辩时应该说“测试和证据覆盖了赛题核心链路”，而不是说“已经覆盖所有真实场景”。

## 12.5 截图证据讲解稿

展示截图时建议按“版本、功能、OS 机制、交付”四段讲。第一段展示 Git HEAD 和 pytest，证明代码版本和测试通过。第二段展示写入、检索、RAG 上下文、精准遗忘和审计链，证明核心功能闭环。第三段展示 openKylin 的 systemd、cgroup、Kylin SDK、Peony/UKUI、BPF LSM 证据，证明项目与操作系统环境结合。第四段展示竞赛自检、提交包审计和归档包 smoke，证明正式提交材料可复验。

每张截图都要一句话收束。例如看到 `verify-audit ok=true`，就说“这张图证明审计哈希链当前可校验”；看到 `irreversible_ok=true`，就说“这张图证明遗忘后旧明文不再从段文件中恢复”；看到 Kylin SDK dim=768，就说“这张图证明 openKylin 端侧 embedding SDK 做过真实推理探针”。

## 12.6 评委可能追问 30 问

1. 问：这个项目和普通 RAG 有什么区别？  
   答：普通 RAG 主要做检索增强，MemGuardOS 还做多源记忆提取、敏感治理、精准遗忘、审计链和 Linux/openKylin 系统机制。

2. 问：为什么默认不调用大模型抽取？  
   答：为了端侧可复现、离线稳定和现场可验证；项目保留本地/外部模型增强接口。

3. 问：规则抽取泛化不够怎么办？  
   答：默认规则是稳定基线，后续可通过 `MEMGUARD_EXTRACTOR_COMMAND` 接 NER/LLM JSON 增强，失败自动回退。

4. 问：精准遗忘如何证明不是假删除？  
   答：有 tombstone、元数据清理、FTS 删除、图谱删除、compact 和 `verify-forget` 明文探针。

5. 问：审计链有什么用？  
   答：每条审计记录包含前一条哈希，篡改中间记录会导致 `verify-audit` 失败。

6. 问：敏感信息如何处理？  
   答：高风险阻断，中低风险脱敏；包括 API key、私钥、手机号、身份证、敏感 OS 路径等。

7. 问：Kylin SDK 是否真正调用？  
   答：openKylin 证据中有真实 embedding 探针，返回 768 维；检索中作为可选增强，fallback 保持稳定。

8. 问：为什么还需要 fallback？  
   答：端侧环境可能 SDK 未安装或运行时不稳定，fallback 保证项目可运行和可复验。

9. 问：BPF LSM 做到了什么？  
   答：对安全测试文件实现强制拒绝验证，并支持 JSON denylist 生成；不宣称全系统生产拦截。

10. 问：Peony/UKUI 的意义是什么？  
    答：证明项目能进入 openKylin 桌面工作流，不只是命令行脚本。

11. 问：Web 控制台安全吗？  
    答：默认 localhost，支持 Bearer Token，token 存 sessionStorage，带 CSP 和安全响应头；不建议公网部署。

12. 问：有没有企业 RBAC？  
    答：没有完整 RBAC/SSO，当前定位是本地 OS Agent 记忆模块。

13. 问：benchmark 为什么都是 1.0000？  
    答：这是自建可复现实验集上的结果，覆盖真实风格样例，但不声称覆盖所有真实世界。

14. 问：如何避免测试数据写死？  
    答：功能可以现场用新输入运行；demo/benchmark 是复现实验用，不是唯一输出来源。

15. 问：如何证明提交包没漏文件？  
    答：`inspect_submission_package.py` 检查必需文件、禁入文件、本机路径和 manifest。

16. 问：如何证明 zip 解压后能跑？  
    答：`smoke_submission_archive.py` 会解压正式包并运行 compileall、demo smoke、Web smoke。

17. 问：openKylin 上能跑吗？  
    答：有 `docs/evidence/latest/` 证据，VM 当前也可 `.venv/bin/python -m pytest -q`。

18. 问：为什么 openKylin 证据是 68 passed，本地是 70 passed？  
    答：采集时间和同步状态不同；最终提交前可重新采集并统一口径。

19. 问：mmap + SQLite 为什么合适？  
    答：轻量、端侧可运行、无需大型数据库；段文件保存版本，SQLite 做索引和审计。

20. 问：如何处理旧偏好冲突？  
    答：记忆有版本和时间有效性，冲突处理优先新、手动、证据更强的记忆。

21. 问：RAG 上下文怎么控制长度？  
    答：`token_budget` 和 `max_chars` 控制预算，`selection_trace` 说明选择过程。

22. 问：如何看每条记忆来源？  
    答：MemoryRecord 有 source kind/uri，RAG explainability 有来源分布。

23. 问：如何导入工具执行经验？  
    答：`ingest-tool-result` 支持 command、cwd、exit_code、stdout、state_before、state_after、lesson。

24. 问：程序性记忆是什么？  
    答：状态-动作-结果经验，例如“修改前状态、执行命令、执行结果、经验教训”。

25. 问：如果用户误删怎么办？  
    答：默认先 dry-run，只有 `--yes` 才执行；审计记录保留操作证据。

26. 问：删除后还能回滚吗？  
    答：遗忘是隐私语义上的删除，不建议把遗忘当普通回滚；更新和回滚是另一个版本管理能力。

27. 问：项目有没有外部 API 花费？  
    答：默认没有；只有显式使用 `generate-answer` 的外部 provider 才会产生 API 调用。

28. 问：为什么你们的材料里只写 pytest、自检、评测 JSON 和 openKylin 证据？  
    答：这些是 MemGuardOS 当前代码能够直接复现的真实指标。我们不把其他项目或示例输出混进答辩材料，避免口径混乱。

29. 问：项目最大亮点是什么？  
    答：多源 Agent 记忆、可解释 RAG、可验证精准遗忘、审计链和 openKylin OS 机制证据闭环。

30. 问：项目还可以怎么提升？  
    答：未来可扩大真实数据集、增强本地模型抽取、完善桌面插件产品化、增加企业级权限和更深内核策略。
