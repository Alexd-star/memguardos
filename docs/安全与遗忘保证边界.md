# MemGuardOS 安全与遗忘保证边界

本文说明 MemGuardOS 在企业交付和赛题答辩中可以承诺的安全能力、精准遗忘能力，以及不能夸大的边界。该文档面向评委、运维人员、系统管理员和后续维护者，用于统一表述口径，避免把用户态记忆治理能力误说成介质级销毁能力。

## 1. 遗忘能力的准确含义

MemGuardOS 的精准遗忘针对的是系统自己管理的智能体记忆数据。用户通过自然语言提出遗忘请求后，系统先执行 dry-run 候选分析，展示哪些记忆可能被影响；用户确认后，系统对命中的记忆写入 tombstone，关闭旧事实的时间有效窗口，从 SQLite 元数据、FTS 全文索引、图谱索引和检索缓存中移除可访问记录，并可通过 compact 对 mmap 段文件执行重写压缩。执行完成后，`verify-forget` 可以用明文探针检查目标文本是否仍能通过 MemGuardOS 的受管路径被访问。

这套流程可以证明“MemGuardOS 管理的记忆副本不再参与检索、RAG 上下文构造和图谱召回”，也能通过审计哈希链证明是谁、在什么时候、以什么请求触发了遗忘。它不是简单隐藏搜索结果，而是把候选规划、确认、删除、压缩、验证和审计串成闭环。

## 2. 受管数据范围

精准遗忘覆盖以下 MemGuardOS 受管对象：

| 对象 | 覆盖方式 | 验证方式 |
|---|---|---|
| SQLite 元数据 | 标记删除、关闭时间窗口、记录 superseded_by | `memctl list`、`temporal_status`、审计链 |
| SQLite FTS 索引 | 删除或重建对应全文索引项 | `search` 和 `verify-forget` |
| 记忆图谱索引 | 删除相关实体关系边 | `hierarchical_graph_search`、图谱查询 |
| mmap 段文件 | 写入 tombstone，可选 compact 重写段文件 | `verify-forget` 明文探针 |
| 检索缓存 | 记忆版本号变化后自动失效 | `memory_revision` 与搜索结果 |
| Agent 交互载荷 | 按 agent/session/turn/topic/time 过滤清理 | `forget_agent_interactions` 影响范围报告 |

## 3. 不覆盖的外部残留

MemGuardOS 不应宣称清除了以下外部残留：

| 外部对象 | 原因 | 建议处理 |
|---|---|---|
| OpenHands 或其他 Agent 自带会话日志 | 外部 Agent 可能有独立持久化目录 | 按 Agent 官方文档删除对应会话、缓存和日志 |
| LLM 服务商日志 | 云端服务保留策略不由本地系统控制 | 使用本地模型或在服务商控制台关闭/申请删除 |
| shell history、终端滚屏、桌面剪贴板历史 | 属于用户环境或桌面系统状态 | 单独清理 shell history、剪贴板和终端日志 |
| VM 快照、磁盘备份、归档包 | 已经复制到系统外部 | 重新生成备份或执行备份介质清理 |
| 文件系统未分配空间、SSD 闪存磨损均衡区 | 用户态逻辑删除不能保证法证不可恢复 | 按组织安全流程执行介质级清除 |

因此，在答辩或交付材料中，推荐表述为：“系统保证 MemGuardOS 受管记忆路径中的逻辑不可访问和可审计遗忘；对外部 Agent 日志、虚拟机快照、磁盘备份和介质级法证恢复给出残留清单和独立清理建议。”

## 4. 与介质清除标准的关系

NIST SP 800-88 Rev.2 将介质清除目标描述为让目标数据在给定努力水平下不可访问。该定义涉及存储介质、组织安全策略、清除方法、验证方法和销毁流程。MemGuardOS 当前实现属于用户态应用层的逻辑遗忘与索引清理，不等同于磁盘清除、SSD 安全擦除或物理销毁。

这种边界并不削弱赛题实现价值。赛题关注的是面向 openKylin 的智能体记忆提取、治理、检索和精准遗忘机制；MemGuardOS 在该范围内提供可复现、可验证、可审计的实现。同时，系统通过 `external_residue` 字段主动报告不覆盖对象，说明项目具备企业交付中的风险透明度。

## 5. 安全交付能力

为支持企业级交付，项目提供以下安全制品：

- `native/bpf_lsm/memguard_lsm_policy.example.json`：BPF LSM 路径 denylist 演示策略。它的边界是“对已知敏感路径或测试路径做内核态打开拦截”，不是任意文件内容级 DLP。内容级 PII、凭据和密钥识别仍由用户态 `SensitiveDetector`、自定义规则、审计链和遗忘流程组合完成。
- `scripts/backup_memguard.py`：创建包含 `memory.segment`、`memory.sqlite3` 和 `manifest.json` 的可校验备份包，数据库复制使用 SQLite Online Backup API。
- `scripts/restore_memguard.py`：恢复前校验 manifest、SHA-256、文件大小和路径安全，发现重复条目、缺失文件或 hash 不一致时拒绝恢复。
- `scripts/check_slo.py`：检查严格资源对照报告中的相同 workload、成功率、P95/P99 延迟、峰值 RSS 和平均 CPU 使用率。
- `scripts/sign_release.py`：生成 SHA256SUMS 和 release attestation；如果本机存在可用 minisign 或 GPG 签名密钥，则生成真实签名，否则明确标记 `not_configured`，不伪造签名。
- `config/nginx/memguardos.conf`：提供 HTTPS 反向代理、内网访问控制、请求体限制和安全响应头模板。

这些能力不是赛题最低要求，但能增强“可部署、可恢复、可审计、可解释边界”的交付可信度。

## 6. 推荐答辩口径

如果评委问“遗忘是否不可恢复”，建议回答：

> 在 MemGuardOS 管理的数据路径内，我们实现了可验证遗忘：候选 dry-run、用户确认、tombstone、索引清理、compact、明文探针和审计哈希链。它能证明受管记忆不再被检索和用于 RAG 上下文。但我们不会夸大为介质级销毁；外部 Agent 日志、VM 快照、备份和底层磁盘法证恢复需要独立清理流程。系统会在返回结果中给出 `external_residue` 清单，这正是企业交付中应该保留的边界透明度。

## 7. 运维检查建议

正式提交或演示前建议执行：

```powershell
python scripts/run_resource_control.py --output docs/evidence/resource_control_latest/report.json
python scripts/check_slo.py docs/evidence/resource_control_latest/report.json --output docs/evidence/resource_control_latest/slo.json
python scripts/backup_memguard.py --store-path <memory.segment> --db-path <memory.sqlite3> --output docs/evidence/backup_latest/memguardos-backup.zip
python scripts/restore_memguard.py --archive docs/evidence/backup_latest/memguardos-backup.zip --output-dir docs/evidence/backup_latest/restored
python scripts/sign_release.py dist/<submission.zip> --output-dir dist/attestation
```

如果任一步失败，应先修复原因，再录制视频或生成最终证据包。
