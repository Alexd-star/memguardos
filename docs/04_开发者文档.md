# 04 开发者文档

本文档面向继续开发 MemGuardOS 的工程人员，说明开发环境、模块边界、扩展方式、测试要求和提交注意事项。代码结构细节见 [06_代码结构说明.md](06_代码结构说明.md)，算法细节见 [08_算法说明.md](08_算法说明.md)。

## 1. 开发环境

项目使用 Python 3.10+，包配置位于 `pyproject.toml`。核心运行依赖保持为空，目的是让默认链路在 openKylin/Linux 端侧尽量轻量。开发依赖包括 `pytest`、`pytest-cov` 和 `ruff`。

```bash
python -m pip install -e ".[dev]"
python -m ruff check .
python -m pytest -q
```

新增功能应优先补测试，再修改实现。涉及文档链接、提交包边界或正式材料的修改，应额外运行 `scripts/check_docs_links.py`、`scripts/check_competition_ready.py` 和提交包审计脚本。

## 2. 模块边界

`memguard/service.py` 是业务编排层，负责协调抽取、敏感治理、存储、检索、遗忘和审计。开发者不应把具体算法全部塞进 service，而应放到专门模块中。例如，敏感检测属于 `memguard/sensitivity/`，检索融合属于 `memguard/retrieval/`，精准遗忘候选规划属于 `memguard/forgetting/`。

`memguard/store/` 是持久化层。`mmap_store.py` 负责追加式明文段文件，`sqlite_meta.py` 负责元数据、FTS、图谱边、版本和审计链。修改该层必须特别谨慎，因为它影响精准遗忘、compact、审计验证和历史兼容。

`memguard/cli/memctl.py` 是用户入口。新增 CLI 子命令时，应同时考虑 Unix socket API、Web 控制台、用户手册和测试用例是否需要同步补齐。

## 3. 推荐开发流程

1. 阅读相关模块和现有测试，确认修改边界。
2. 为新行为补测试，尤其是安全、遗忘、审计、检索排序和打包边界。
3. 修改实现，保持默认链路离线、可复现、可回退。
4. 更新中文文档，避免代码能力和文档描述不一致。
5. 运行 `ruff`、`pytest`、文档链接检查和竞赛自检。
6. 如果影响正式提交包，重新生成并审计提交包。

## 4. 扩展语义抽取

默认抽取器位于 `memguard/extraction/semantic.py`。它采用可解释规则和轻量策略，适合端侧稳定运行。若要接入 LLM/NER 增强器，应通过显式环境变量或配置开关，不应让默认测试依赖外部服务。增强器输出应是可解析 JSON，失败时必须回退到默认抽取器。

## 5. 扩展检索后端

默认检索由 FTS、hash-vector 和图谱共同完成。Kylin embedding SDK 在 `memguard/retrieval/kylin_sdk.py` 和 `memguard/retrieval/hybrid.py` 中以可选后端形式接入。新增向量后端时，应满足三点：检测失败不影响默认路径，真实推理状态可通过 `sdk-status` 或类似命令解释，检索结果应保留来源和排序解释。

## 6. 扩展 OS 集成

OS 机制相关脚本集中在 `scripts/` 和 `native/`。BPF LSM、auditd、UKUI/Peony 这类能力应保持“安全可验证、默认不破坏系统”的原则。新增内核或桌面集成必须提供 smoke 脚本、openKylin 证据和文档边界说明。

## 7. 代码风格

项目偏向标准库优先、可读性优先和明确边界。新增代码应避免隐式网络依赖、避免把真实私密路径写入正式文档、避免在测试中依赖机器特定状态。错误信息应让用户知道下一步该检查什么，而不是只抛出底层异常。

## 8. 发布前检查

发布前建议执行：

```bash
python scripts/release_preflight.py
python scripts/package_submission.py
python scripts/inspect_submission_package.py
python scripts/smoke_submission_archive.py
```

`release_preflight.py` 是完整工程仓库中的自检工具，不进入正式竞赛提交包主体。若它失败，应先修复失败项，而不是绕过检查。
