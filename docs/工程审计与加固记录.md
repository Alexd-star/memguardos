# 工程审计与加固记录

日期：2026-05-19

本文记录对 MemGuardOS 功能、代码、框架、算法与实现成熟度的复核结论。目标是找出“不够成熟、像原型、容易被评委追问”的部分，并把能立刻补齐的内容落实到代码、测试和 openKylin 证据。

## 1. 审计结论

| 类别 | 审计结论 | 当前处理 |
|---|---|---|
| OS 服务成熟度 | 原 `memguardd.service` 只执行一次 `doctor` 后退出，不能算真正常驻服务 | 已改为 `python3 -m memguard.daemon --interval 60`，openKylin 验证为 `active (running)` |
| 配置与规则健壮性 | 自定义敏感正则若写坏会触发 `re.error`，属于生产级风险 | 已加入正则名称、长度、编译、空匹配、过宽匹配校验；CLI 返回失败码 |
| 数据质量 | 手动配置导入会接收空值，缺少质量报告 | 已加入配置叶子节点质量校验，返回 `skipped_count` 与原因 |
| 安全解释性 | RAG 上下文能脱敏，但元数据未保存 `redacted` 状态 | SQLite 增加 `sensitivity_redacted` 字段，上下文包返回结构化敏感状态 |
| Agent 调用方式 | 只有 CLI 不够像系统服务接口 | 新增 Unix domain socket JSON API，并由 daemon 挂载 `/run/memguardos/memguard.sock` |
| 用户行为接入 | 仅有 OS/auditd 与工具结果，容易被追问“用户行为数据”证据不足 | 新增 `ingest-history`，从 shell history 中提取有价值的工具行为轨迹 |
| API 调用权限 | 本地 socket 只靠文件权限，正式环境仍偏弱 | 新增可选 `--auth-token-file`，本地 Agent 请求可带 `token` 鉴权 |
| 生成链路 | 只有 prompt 渲染，容易被问“能不能真的接 LLM” | 新增默认关闭的 `generate-answer` adapter，支持 dry-run、本地命令和兼容端点 |
| 提交整洁度 | 测试产生 `__pycache__` 和 `.pytest_cache`，最终包不能带 | 已加入 `make clean`，并清理缓存目录 |

## 2. 已修复问题

### 2.1 systemd 服务从一次性命令升级为常驻 daemon

修复前，`scripts/memguardd.service` 的 `ExecStart` 是 `python3 -m memguard.cli.memctl doctor`，服务会很快退出，只能证明 systemd 可以启动命令。

修复后，新增 `memguard/daemon.py`，服务启动后写入 `daemon_started` 审计事件，并定期写入 `daemon_heartbeat`。daemon 默认健康检查只报告 cgroup 与运行状态，不探测用户态 Kylin socket，避免 root 服务启动时产生 SDK 噪声。

openKylin 证据：

```text
Active: active (running)
CGroup: /system.slice/memguardd.service
python3 -m memguard.daemon --interval 60
MemoryMax=536870912
cpu.max=50000 100000
```

### 2.2 自定义敏感正则校验

修复后新增 `PatternValidationError` 与 `validate_pattern()`，校验名称格式、正则长度、可编译性、不得匹配空串、不得明显过宽。`patterns add` 会输出结构化失败原因并返回非零码，拒绝事件写入 `pattern_reject` 审计。

### 2.3 手动配置质量校验

`ingest-config` 现在会跳过空路径、空值和非叶子值，并在返回结果中报告 `skipped_count` 与原因。`config_ingest` 审计事件记录 entries、stored、blocked、skipped。

### 2.4 脱敏状态进入元数据和上下文包

SQLite `memory` 表增加 `sensitivity_redacted` 字段，`build-context` 的每条 memory 返回结构化敏感状态，例如：

```json
{
  "sensitivity": {
    "level": "medium",
    "labels": ["phone_cn"],
    "redacted": true
  }
}
```

### 2.5 提交清理能力

`Makefile` 增加 `make clean`，用于清理 `__pycache__` 和 `.pytest_cache`。

### 2.6 本地 Agent API

新增 `memguard/api/server.py`，支持 Unix domain socket JSON 请求：

- `health`
- `ingest`
- `search`
- `build_context`

systemd 服务通过 `/run/memguardos/memguard.sock` 暴露本地 API。这样 OS Agent 可以通过本地 socket 调用记忆系统，而不必只依赖 CLI。演示环境中 socket mode 为 `0666`，便于普通用户验证；正式环境可改为专用用户组 `0660`，并使用 `--auth-token-file` 要求请求携带本地令牌。

### 2.7 shell 用户行为轨迹

新增 `memguard/ingestion/behavior.py` 和 CLI 命令 `ingest-history`，用于把 `.bash_history` 等 shell 历史转换成 `user_behavior` 来源的记忆。实现会过滤 `ls`、`cd`、`history` 等低价值噪声，保留 `pytest`、`rg`、`git`、`systemctl`、`journalctl`、`ssh`、`scp`、`pip`、`make` 等对智能体偏好和调试习惯有价值的命令。

## 3. 当前仍非企业级满配的部分

| 不足 | 影响 | 当前策略 |
|---|---|---|
| 没有真实 LSM 强制拦截器 | OS 安全深度不如内核级方案 | 使用 auditd 真实 OS 审计事件满足“不停留于应用层正则”，并补充默认关闭的 bpftrace openat 探针脚本 |
| Kylin embedding SDK 推理超时 | 不能宣称主检索由 SDK embedding 驱动 | 保留 SDK 探测和 vector SDK C++ 探针，主路径使用稳定 fallback |
| 没有 HTTP API | 当前提供 Unix domain socket JSON API，未暴露网络接口 | 本地 OS Agent 场景优先使用 Unix socket，避免引入网络攻击面 |
| 抽取器以规则为主 | 泛化能力弱于大模型 schema extractor | 规则路径稳定、可复现；已补可选 LLM 生成 adapter，后续可扩展到 schema 抽取 |
| benchmark 规模仍偏小 | 1.0000 指标可能被质疑样本少 | 已有 hard cases 和基线；后续继续扩大样本 |
| UKUI 深度插件未实现 | 少一个 openKylin 生态加分点 | 已补通知 smoke；不宣称 Peony/控制中心深度插件 |
| 多用户 RBAC 未实现 | 不适合直接作为公网或多人平台服务 | 当前定位是本机 OS Agent 记忆模块；Unix socket 权限和 token 鉴权满足本地原型 |
