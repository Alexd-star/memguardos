# 11 配置说明

本文档说明 MemGuardOS 的主要配置来源、默认值和生效方式。由于项目强调端侧轻量化，配置主要来自 CLI 参数、环境变量、namespace 数据目录和 systemd 单元。

## 1. Python 包配置

`pyproject.toml` 定义项目名、版本、Python 要求、命令入口和开发依赖。`memctl` 指向 `memguard.cli.memctl:main`，`memguardd` 指向 `memguard.daemon:main`。修改版本号或入口时，应同步更新 README、CHANGELOG、打包脚本和交付说明。

## 2. namespace 配置

namespace 通过 CLI 的 `--namespace` 参数传入。默认 namespace 是兼容旧路径的默认空间。每个 namespace 拥有独立数据目录、段文件、SQLite 数据库、自定义敏感规则和审计链。namespace 名称会经过安全规范化，避免路径穿越。

## 3. 环境变量

| 变量 | 作用 | 默认行为 | 风险 |
|---|---|---|---|
| `MEMGUARD_EMBEDDING_BACKEND` | 选择检索 embedding 后端。 | 默认稳定 fallback。 | 强制外部后端可能导致超时或不可复现。 |
| `MEMGUARD_EXTRACTOR_COMMAND` | 可选语义抽取增强命令。 | 不启用外部增强。 | 命令输出必须可信且可解析。 |
| `MEMGUARD_LLM_PROVIDER` 类配置 | 可选生成接口。 | 默认不调用 LLM。 | 远程端点可能产生费用和隐私风险。 |

具体变量名称以源码和 README 当前版本为准。新增环境变量应写入本文档和用户手册。

## 4. systemd 配置

`scripts/memguardd.service` 是默认 daemon 服务，`scripts/memguardd@.service` 是 namespace 模板服务。它们用于 openKylin 复验 systemd、cgroup、服务状态和 journald 日志。修改服务单元时，应复跑 openKylin 证据采集。

## 5. 敏感规则配置

内置敏感规则在 `memguard/sensitivity/detector.py`。用户自定义规则通过 `memguard/sensitivity/custom_patterns.py` 保存到 namespace 对应规则文件。自定义正则必须先校验，避免灾难性回溯或误伤大量正常文本。

## 6. BPF LSM 策略配置

BPF LSM 的 denylist 示例来自 `data/demo/bpf_lsm_policy.json`，由 `scripts/generate_bpf_lsm_policy.py` 生成静态头文件。该机制适合安全测试和可审查策略演示，不建议未经评估就扩大到系统关键文件。

## 7. 配置回滚建议

配置修改前应记录当前状态。systemd 修改可通过重新安装旧单元并 `systemctl daemon-reload` 回滚。自定义敏感规则可删除或替换 namespace 规则文件。运行时数据变更尤其是 compact 前应备份数据目录。
