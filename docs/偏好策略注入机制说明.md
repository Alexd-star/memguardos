# MemGuardOS 偏好策略注入机制说明

## 1. 设计目的

MemGuardOS 将偏好记忆视为 OS Agent 运行策略的一部分，而不是普通知识证据。知识记忆适合通过检索召回，偏好记忆则需要经过作用域选择、冲突裁决和阶段化注入。这样做的原因很直接：用户说“以后查代码优先用 rg”时，这条信息不一定和下一次查询文本相似，但它应当在工具选择阶段稳定生效；用户说“危险命令必须先确认”时，它的优先级又必须高于“为了效率少问我”这类偏好。

本机制在代码中主要由 `MemGuardService.build_agent_context()` 与 `memguard/integrations/context_injector.py` 支撑，文档中称为 **Policy Pinning Layer**。这里的 pinning 不是把所有偏好无条件塞进提示词，而是在 session、project、task_type、agent、global 等作用域内选择可用偏好，并按 Agent 执行阶段决定是否注入。

## 2. 三阶段注入策略

| 阶段 | 注入重点 | 不应注入 | 说明 |
|---|---|---|---|
| planning | 工作流、历史案例、相关模板、少量高优先级安全策略 | 低价值风格偏好、与任务无关的工具噪声 | 规划阶段需要知道“做事路线”，不应被大量工具细节淹没。 |
| tool_selection | 工具偏好、安全确认策略、历史工具失败案例、程序性记忆 | 普通知识长文、输出风格 | 工具选择阶段必须强注入 `rg`、`pytest`、`systemctl`、高风险确认等偏好。 |
| response_generation | 输出风格、语言偏好、简洁程度、引用格式、安全提示策略 | 与生成无关的底层工具日志 | 生成阶段关注如何回答，而不是重新规划工具调用。 |

## 3. 优先级与冲突处理

偏好优先级遵循以下原则：

1. 安全策略优先于效率偏好；
2. 当前 session 优先于 project，project 优先于 task_type，task_type 优先于 agent，agent 优先于 global；
3. 新版本偏好优先于旧版本偏好；
4. 被遗忘、过期、污染隔离或来源不可信的偏好不得进入 system block；
5. 同一主题存在冲突时，必须输出 explainability，说明保留哪条、过滤哪条以及原因。

## 4. 可解释输出

每次上下文构建都应提供选择轨迹。当前实现会在 `build_agent_context()` 返回中包含 `explainability`、`filtered`、`stage_policy`、`budget` 等信息。评委可重点核验：

- 被注入偏好是否符合当前阶段；
- 被过滤记忆是否说明原因；
- 被遗忘偏好是否不再出现；
- 安全策略是否优先于效率偏好；
- token 预算是否避免把过多历史全部塞入提示词。

## 5. 已实现与边界

已实现：三阶段上下文、阶段子类型过滤、作用域偏好选择、被遗忘记忆过滤、解释性选择轨迹、token 预算裁剪。

可选增强：更复杂的偏好冲突仲裁模型、学习型作用域权重、管理员界面的偏好冲突人工审批。

边界声明：Policy Pinning Layer 只保证 MemGuardOS 受管记忆进入 Agent 上下文前的选择与过滤，不控制外部 Agent 自己保存的日志、云端模型历史或用户手工复制的提示词。
