# MemGuardOS 四项最终补强实施方案

本文档用于指导最终提交前的四项高价值补强：同 Git HEAD 的 openKylin 证据复跑、真实 Agent 留出场景、Web 控制台产品化抛光、依赖与源码安全扫描。目标不是继续堆叠演示内容，而是把已经完成的功能转化为更可复现、更可解释、更接近企业级交付的证据链。

## 1. 设计依据

`pip-audit` 官方说明将其定位为 Python 环境和依赖文件的已知漏洞审计工具，支持 JSON、Markdown 等机器可读和人工可读输出，并明确它审计的是依赖漏洞，不是源码静态分析。Bandit 官方文档则说明其支持多种报告格式，包括 JSON，适合对 Python 源码进行安全规则扫描。NIST SSDF 1.1 将自动化测试、漏洞扫描和供应链风险管理纳入安全软件开发实践。OpenHands 官方 Hooks 文档说明，生命周期 hooks 可以用于危险命令阻断、质量门禁、工具使用日志和上下文注入；OpenHands SDK 论文也强调事件溯源状态、确定性 replay、类型化工具和可组合运行环境。这些资料共同支持本项目采用“真实 Agent 事件 + 记忆系统 + 安全门禁 + 可复验证据”的补强路线。

## 2. 补强目标

### 2.1 同 Git HEAD 复跑 openKylin 证据

最终提交材料必须能够回答“这些证据是否来自最新代码”。因此，在完成本轮代码和文档更新后，将本地分支推送到 GitHub，再在 openKylin 虚拟机中拉取相同 Git HEAD，重新运行测试、自检、真实 Agent 留出场景和必要证据采集。证据目录中的 `manifest.json` 与 `SHA256SUMS.txt` 必须覆盖全部证据文件，避免出现旧证据与新代码不一致的问题。

验收标准：

- openKylin 项目目录的 `git rev-parse HEAD` 与本地提交一致；
- `python -m pytest -q` 在 openKylin 通过；
- `python scripts/check_competition_ready.py` 在 openKylin 通过；
- 新增留出 Agent 场景有独立证据目录、指标 JSON、报告和哈希清单；
- 文档只声明真实运行过的指标，不夸大未运行内容。

### 2.2 增加真实 Agent 留出场景

当前正式真实 Agent 数据集已经覆盖用户纠正、隐式习惯、冲突覆盖、失败修复、高风险确认、跨会话复用、精准遗忘和角色污染。为了降低“样例过拟合”的质疑，本轮新增独立留出集，不直接修改主数据集的 20 组口径。留出集使用新的 `data/benchmarks/real_agent_behavior_holdout.jsonl`，保持与主 runner 相同 schema，但作为最终前验证集单独运行和报告。

留出集设计原则：

- 每个案例必须来源于用户与 Agent 的交互习惯，而不是泛化的桌面行为；
- 覆盖“偏好形成、偏好冲突、工具失败修复、高风险拒绝、精准遗忘、角色污染防护、跨会话程序性记忆”；
- 每个案例必须使用安全工作区，不允许真实删除、关机、修改系统关键路径；
- 保持 R01 到 R08 的连续编号，便于现有 runner 的数据校验逻辑复用；
- 留出集不参与默认调参，主要用于最终证据和答辩抗质疑。

验收标准：

- 留出集 8 组案例通过 schema 和安全校验；
- `scripts/run_openhands_behavior_suite.py --dataset data/benchmarks/real_agent_behavior_holdout.jsonl --validate-only` 通过；
- openKylin 中真实运行留出集并生成 `metrics.json`；
- 竞赛 readiness 门禁能识别留出集证据。

### 2.3 Web 控制台产品化抛光

Web 控制台已经具备状态查看、写入、检索、RAG 上下文解释、Agent 交互治理、精准遗忘、审计和诊断导出能力。本轮不新增复杂前端框架，继续保持本地可部署、零前端依赖的工程路线，但强化产品表达：让首页更像“运维与治理工作台”，而不是脚本调试页。

优化方向：

- 首页增加“验收清单”和“今日工作流”，把常用操作串成闭环；
- 在 Agent 交互页增加“记忆价值指标”说明，让用户能理解记忆对工具选择、重复尝试和高风险操作的影响；
- 在精准遗忘页强化二次确认和影响范围说明；
- 在诊断页强化“一键导出诊断包”入口；
- smoke 测试加入产品化文案检查，同时继续确保页面不出现竞赛过程话术。

验收标准：

- `scripts/web_dashboard_smoke.py` 通过；
- 页面包含产品化入口、诊断导出、RAG 来源解释、遗忘候选确认和 Agent 工作台；
- 页面不包含“评委、答辩、benchmark 用例/种子”等过程性话术。

### 2.4 增加安全扫描摘要

已有 SBOM 记录核心源码、脚本、原生增强、数据和依赖分组哈希。本轮在 SBOM 之外增加安全扫描报告，使工程交付从“知道有什么”升级为“对已知风险进行自动化检查”。

设计原则：

- Bandit 负责 Python 源码静态安全扫描；
- pip-audit 负责依赖已知漏洞扫描；
- 扫描脚本输出 JSON 和中文 Markdown；
- 工具缺失时可以以显式 `skipped` 状态生成报告，但正式发布门禁优先要求工具存在并运行；
- 检查结果纳入 `check_competition_ready.py` 和发布预检。

验收标准：

- `scripts/run_security_scan.py` 可以生成 `docs/security_scan.json` 和 `docs/安全扫描报告.md`；
- readiness 门禁检查报告存在、可解析、无 high severity Bandit 问题、无已知依赖漏洞；
- 提交包包含安全扫描报告；
- 文档准确说明 pip-audit 的边界：它审计依赖已知漏洞，不等同于源码安全证明。

## 3. 执行顺序

1. 先新增留出集测试和安全扫描测试，确认测试能捕获缺失能力；
2. 实现留出集、扫描脚本、readiness 集成、提交包边界集成；
3. 抛光 Web 控制台并更新 smoke 检查；
4. 本机运行完整验证和打包审计；
5. 提交并推送 GitHub；
6. openKylin 拉取同一 Git HEAD，复跑测试、readiness 和留出真实 Agent 证据；
7. 复制证据回仓库，刷新 manifest 和 SHA256；
8. 再次本机完整验证、打包、提交、推送。

## 4. 最终口径

完成后可以在答辩中表述为：MemGuardOS 已完成主数据集真实 OpenHands 闭环、独立留出场景验证、openKylin 原生机制证据、Web 控制台治理工作台、SBOM 与安全扫描门禁。若某个外部模型或 openKylin SDK 在特定环境中超时，应如实说明其属于外部运行时限制，并展示 fallback、诊断和可复跑脚本，不能把 fallback 夸大为 SDK 主路径。
