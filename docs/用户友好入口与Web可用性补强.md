# 用户友好入口与 Web 可用性补强

本文记录本轮针对“长命令过多、普通用户不易理解、Web 按钮反馈不充分、openKylin 落地需要复核”的补强内容。

## 设计目标

MemGuardOS 保留 `memctl` 作为管理员和脚本化复验入口，同时新增更面向普通用户和评委演示的 `memguard` 入口。`memguard` 不替代底层管理命令，而是把常见动作包装为短命令和可读输出，让用户能直接理解系统是否记住、是否检索到、是否注入上下文、遗忘前会影响哪些内容。

Web 控制台继续作为本机治理入口。页面不直接暴露内部调试时间、堆栈或长 JSON 作为主路径，按钮执行时必须有明确反馈，异常时给出下一步处理入口，系统维护页负责聚合管理员需要的审计、检索、策略和导出报告。

## 三入口定位

| 入口 | 面向对象 | 主要用途 |
|---|---|---|
| `memguard` | 普通用户、评委演示 | 状态、写入、检索、上下文、遗忘预览、轻量证据、交互式工作台 |
| Web 控制台 | 普通用户、管理员、评委 | 图形化查看记忆、偏好依据、Agent 交互、精准遗忘、系统维护和复核中心 |
| `memctl` | 开发者、管理员、自动化脚本 | 完整底层能力、证据采集、openKylin 状态、SDK 探针、审计和批量命令 |

## 本轮实现内容

新增 `memguard` 命令，支持：

- `memguard status`：查看记忆空间、实时记忆数量、审计完整性和检索方式。
- `memguard remember "文本"`：写入一条自然语言记忆，并给出保存结果。
- `memguard memory`：查看最近记忆，不需要用户记住底层 JSON 字段。
- `memguard search "关键词"`：搜索记忆并显示摘要、分数、来源和 ID。
- `memguard context "任务"`：预览 Agent 生成前会获得的受控上下文。
- `memguard forget "请求"`：默认只做影响范围预览；追加 `--yes` 才确认执行。
- `memguard evidence`：输出轻量复核摘要。
- `memguard demo`：运行一轮可读的 Agent 记忆闭环演示，展示记忆注入、工具调用、新增记忆和遗忘验证。
- `memguard shell`：进入交互式记忆工作台，支持 `/status`、`/memory`、`/search`、`/context`、`/forget`、`/evidence`、`/exit`。

Web 控制台补强：

- 增加全局操作状态提示，按钮执行时显示清晰的处理中状态。
- 网络请求加入超时控制，避免按钮长时间无反馈。
- 首页不再显示具体刷新时间，只显示“状态已刷新”，避免调试感。
- 风险处置建议增加“跳转处理”按钮，用户能从建议直接进入系统维护。
- 增加刷新后的关注事项区域，把审计、检索、本机智能检索状态转为可理解的中文提示。
- 系统维护按钮文案改为“校验操作记录”“检查检索方式”“查看记忆策略”“聚合系统状态”“导出系统报告”，减少生硬技术词。

## 核验方式

本轮新增和更新的自动核验包括：

- `tests/test_memguard_user_cli.py`：验证 `memguard` 用户入口、demo 输出、遗忘预览默认不删除。
- `tests/test_web_dashboard_product_ui.py`：验证 Web 控制台具有操作状态、超时控制、跳转处理、无调试时间，以及所有内联按钮都有对应函数。
- `scripts/web_dashboard_smoke.py`：继续覆盖页面加载、权限、写入、检索、抽取解释、审计、诊断导出、Agent 交互、交互遗忘预览和异常输入拒绝。

## openKylin 落地要求

安装包已把 `memguard` 加入 `memguardos-core`，`/usr/bin/memguard` 与 `/usr/bin/memctl` 一样通过 `/opt/memguardos` 中的 Python 包执行。openKylin 上验证时，应检查：

1. `memguard status` 能返回中文状态摘要；
2. `memguard demo` 能展示记忆注入、工具调用、新增记忆和遗忘验证；
3. `memctl web --host 127.0.0.1 --port 8765` 启动后，Web 控制台按钮能返回反馈；
4. 系统维护页按钮不会无提示卡住；
5. 复核中心自动项能逐项运行，桌面项保留人工截图确认。
