# 06 代码结构说明

本文档说明 MemGuardOS 源码目录的职责划分。以下说明根据当前代码结构和文件命名整理，个别底层实现细节以源码为准。

## 1. `memguard/` 主程序包

`memguard/` 是作品主体。它不保存运行时数据，也不保存评测证据，只保存可复用的程序代码。

| 路径 | 作用 |
|---|---|
| `memguard/service.py` | 核心业务编排，承接写入、搜索、上下文、遗忘、审计、诊断等高层能力。 |
| `memguard/models.py` | 记忆对象、来源、敏感等级、版本、审计和时间窗口的数据模型。 |
| `memguard/config.py` | 本地数据目录和 namespace 路径管理。 |
| `memguard/daemon.py` | daemon 入口，提供服务健康快照和 Unix socket 服务启动。 |
| `memguard/cli/memctl.py` | CLI 命令行入口，负责解析用户参数并调用 service/API/Web。 |

## 2. 子包说明

`memguard/api/` 提供本地 Unix socket JSON API。输入是 JSON 请求，输出是 JSON 响应，适合 OS Agent 自动调用。它包含请求大小限制、token 校验、参数约束和错误响应。

`memguard/web/` 提供本地 Web 控制台。它使用标准库 HTTP server 实现，不引入前端构建链，适合离线和评审演示。控制台调用同一套 service 能力，不另建业务逻辑。

`memguard/store/` 是持久化层。`mmap_store.py` 负责追加式段文件读写，`sqlite_meta.py` 负责元数据、脱敏检索副本、FTS、图谱、版本和审计链。该层输入是标准化后的 MemoryRecord 和审计事件，输出是可检索索引、可验证审计链和可重建数据状态。

`memguard/retrieval/` 是检索层。`hybrid.py` 提供默认混合检索，`kylin_sdk.py` 负责 Kylin embedding/vector SDK 探测和可选后端，`conflict.py` 负责同主题偏好冲突处理。该层输入查询文本和候选记录，输出带分数、解释和排序依据的结果。

`memguard/extraction/` 是抽取层。`semantic.py` 负责可解释偏好、知识、策略和程序性记忆抽取，`entity.py` 负责实体和关系抽取。它的输入是清洗后的文本，输出是记忆类型、标签、实体、关系和抽取解释。

`memguard/sensitivity/` 是敏感治理层。`detector.py` 内置 PII、凭据、私钥、银行卡、中文地址和 OS 高风险路径规则，`custom_patterns.py` 支持用户自定义敏感规则和自然语言规则建议。

`memguard/forgetting/` 是精准遗忘层。`planner.py` 根据自然语言请求、关键词、锚点和候选记录计算遗忘候选，并输出解释。真正的删除、compact 和验证由 service 调用存储层完成。

`memguard/ingestion/` 是多源接入层。`config.py` 处理 JSON/YAML 类配置，`behavior.py` 处理 shell history，`tool_result.py` 处理工具执行结果，`quality.py` 做质量校验。

`memguard/os_guard/` 是 OS 适配层，包含 auditd 规则生成、auditd 日志解析、cgroup 状态、journald 日志、OS 事件解析和 doctor 报告。

`memguard/llm/` 是可选生成层。默认不调用外部 LLM，只有显式配置 provider 或本地命令时才生成回答。

`memguard/eval/` 是评测层，负责读取 benchmark 数据、执行指标评测、生成 JSON 和 Markdown 报告。

## 3. `scripts/` 脚本目录

`scripts/` 包含部署、验证、证据采集、打包、SDK 探针和桌面/内核集成脚本。正式提交包只包含与运行和验证直接相关的脚本；`package_submission.py`、`inspect_submission_package.py`、`release_preflight.py`、`check_docs_links.py` 等属于完整工程仓库支撑，不进入正式包主体。

## 4. `native/` 原生目录

`native/bpf_lsm/` 保存 BPF LSM 示例策略和加载器源码。它的定位是安全测试路径验证和可审查 denylist 机制，不是默认生产拦截链路。`native/ukui/` 保存 Peony 右键插件和 UKUI 控制中心插件源码，用于桌面可见入口和运维面板验证。

## 5. `tests/` 测试目录

`tests/test_core.py` 覆盖核心功能，`tests/test_packaging.py` 覆盖提交包边界和证据审计，`tests/test_realistic_benchmark_cases.py` 覆盖真实样例扩充脚本。新增功能时应优先补测试，并避免依赖机器私有状态。
