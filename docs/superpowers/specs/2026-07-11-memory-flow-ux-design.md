# MemGuardOS 记忆操作流与检索体验设计

## 目标

将 Web 控制台和 UKUI 从功能入口集合调整为可连续完成任务的产品界面，同时解决精确重复写入、相似检索结果堆叠和 Kylin SDK 冷启动可能拖慢交互的问题。

## 用户流程

普通用户进入后先看到“记忆服务是否可用”和三项常用动作：查看记忆、搜索记忆、精准遗忘。进入记忆中心后，页面默认展示最近记忆列表；搜索框与类型、范围筛选保持在同一工具栏。结果按相关度排序，前三条直接展示，更多结果折叠。每条结果显示短编号、摘要、类型、来源、作用范围、相关性等级、命中原因和操作。

写入相同内容时不再生成新记录，而是返回已有记忆编号并说明“已存在，无需重复保存”。历史数据库中已经存在的相同记录不会被自动删除；搜索时会折叠为一组并显示包含数量，避免破坏审计证据。

## 检索规则

1. 继续使用 FTS、轻量向量、图谱和可选 Kylin SDK 的混合排序。
2. 结果按照综合相关度降序排列；界面把分数解释为高、中、低相关，不要求用户理解内部浮点分值。
3. 同一记忆编号只出现一次；内容身份相同的历史记录折叠，保留最高分记录并返回折叠数量和关联编号。
4. Web 默认请求 5 条，直接展示前三条，其余按需展开。
5. `auto` 模式下 Kylin SDK 的单次调用必须受剩余延迟预算约束，预算耗尽立即回退 hash，不允许一次冷启动阻塞数秒。

## Web 信息架构

- 总览：一个状态横幅、三个关键数字、三个主要动作、最近记忆与待处理风险。
- Agent 工作台：任务输入、模式选择、执行时间线和结果证明。
- 记忆中心：写入入口、搜索与筛选、最近/搜索结果列表、详情操作。
- 偏好与策略、敏感保护、精准遗忘：保留核心任务，减少重复说明。
- 系统维护、审计与证据、本机验收：仅管理员可见。

## UKUI 边界

UKUI 只展示总体状态、最近记忆行为和关键入口。普通页不承载复杂检索表格和原始结果；点击后进入 Web 对应任务。管理员页继续提供服务控制、SDK、安全审计和报告，但每个分区只保留状态、影响说明和操作。

## 验收

- 精确重复写入只保留一条活动记忆，并返回原记忆编号。
- 搜索结果包含 `rank`、`match_reason`、`duplicate_count` 和可追溯编号。
- Web 结果前三条直接展示，更多结果折叠，完整编号可复制。
- 普通用户总览不再堆放系统健康矩阵、流程说明和多组重复卡片。
- Kylin `auto` 路径遵守配置的 rerank 延迟预算。
- 桌面与 760 px 窄屏无重叠，键盘焦点和状态反馈可见。
