# MemGuardOS 智能体记忆价值双层评测设计

日期：2026-06-19  
状态：设计已确认，等待实施计划评审  
适用分支：`feature/real-agent-foundation`

## 1. 设计目标

现有评测已经能够验证记忆抽取、角色污染防护、跨会话检索和精准遗忘等基础能力，但这些指标主要回答“记忆是否被正确保存和检索”，尚不足以直接证明记忆是否真正改善了智能体的任务表现。

本设计新增“记忆价值”评测体系，通过可复现的确定性配对实验和 openKylin 上真实 OpenHands 会话，从任务完成、工具选择、交互成本、上下文成本、错误重试和遗忘行为六个方面衡量 MemGuardOS 对智能体的实际贡献。

评测必须同时满足以下原则：

1. 相同任务在可比条件下进行配对对照。
2. 记忆系统质量与大模型执行能力分层统计。
3. 聚合指标可以回溯至逐案例输入、事件和判定依据。
4. 所有失败均保留，不进行择优重跑或人工改写。
5. 高风险任务仅在专用工作区使用安全替身或 dry-run。
6. 本地模型测试不依赖付费 API。

## 2. 总体方案

采用双层评测：

| 层级 | 规模 | 主要目的 |
|---|---:|---|
| 确定性配对实验 | 16 组 | 稳定验证记忆选择、作用域、覆盖、遗忘和价值指标计算 |
| 真实 OpenHands 会话 | 12 组 | 证明真实现有智能体能够消费记忆并产生可观察的行为变化 |

确定性实验进入自动化测试和竞赛质量门禁。真实会话在 openKylin、OpenHands SDK、Ollama 本地模型环境中运行，产生独立证据包。

## 3. 对照组设计

同一任务根据场景使用以下对照组：

| 组别 | 输入条件 | 评测用途 |
|---|---|---|
| 无记忆组 | 新会话，不注入历史记忆 | 测量智能体基础能力和缺少历史信息时的表现 |
| 完整历史组 | 将相关历史交互原文加入 Prompt | 测量传统历史回放的上下文成本 |
| MemGuardOS 组 | 仅注入检索、作用域筛选和安全过滤后的记忆 | 测量结构化记忆的任务价值与上下文效率 |

三组应使用相同模型、模型参数、任务文本、工具集合、最大迭代次数和工作区初始快照。无法同时适用三组的场景必须在案例定义中说明原因。

Prompt token 节省率仅以“完整历史组”为主要基线。无记忆组上下文天然更短，但可能缺失任务所需知识，不得以其为分母宣称 MemGuardOS 节省 token。

## 4. 核心指标

### 4.1 任务完成率

任务完成必须由可执行断言判定，例如：

- 命令退出码符合预期；
- 目标文件存在且内容正确；
- 输出包含指定路径或配置值；
- 安全策略按要求拒绝或要求确认；
- 新会话中目标记忆存在或已消失。

模型自述“已完成”不作为完成证据。

计算方式：

```text
任务完成率 = 完成案例数 / 有效案例数
完成率提升 = MemGuardOS 组完成率 - 对照组完成率
```

### 4.2 工具选择准确率

每个工具选择案例必须预先标注期望工具、允许的等价工具和禁止工具。分别统计首个有效工具调用和整场会话是否使用正确工具。

```text
首选工具准确率 = 首个有效工具正确的案例数 / 工具选择案例数
工具选择提升 = MemGuardOS 组准确率 - 无记忆组准确率
```

### 4.3 交互轮数下降

统计以下数量：

- 用户为纠正智能体而追加的消息数；
- 智能体完成任务前的执行轮数；
- 工具调用总数；
- 达到最大迭代限制的案例数。

输出平均值、中位数和逐案例差值。若 MemGuardOS 组未完成任务，不得用较少轮数错误地解释为效率更高。

### 4.4 Prompt token 减少量

使用 MemGuardOS 现有统一 token 估算器，分别记录：

- 原始任务 token；
- 完整历史 token；
- MemGuardOS 三阶段上下文 token；
- 实际提交给智能体的总输入 token；
- 因用户重复说明和纠正产生的附加 token。

```text
token 减少量 = 完整历史组输入 token - MemGuardOS 组输入 token
token 减少率 = token 减少量 / 完整历史组输入 token
```

报告中必须注明这是统一估算口径，而不是模型服务商账单 token。若 OpenHands 或底层模型提供可验证的 usage 字段，可作为独立实测字段保存，不能与估算值混用。

### 4.5 错误命令和重复尝试减少量

根据规范化工具事件统计：

- 非零退出码工具调用；
- 相同规范化命令的重复执行；
- 不存在命令或错误参数；
- 被安全策略拒绝的高风险调用；
- 无工具调用但任务未完成；
- 达到最大迭代次数。

安全策略正确拒绝高风险命令属于安全成功，不计入普通错误命令；但应单独记录为一次被拦截行为。

### 4.6 遗忘前后偏好遵循变化

精准遗忘案例至少包含一个目标偏好和一个无关偏好，依次验证：

1. 遗忘前目标偏好被正确选中并影响行为。
2. 遗忘后目标偏好不再出现在三个阶段上下文。
3. 新会话不再遵循目标偏好。
4. 无关偏好仍能被检索和遵循。
5. 已遗忘事件载荷、索引和段文件满足现有清理验证。

分别输出遗忘前目标遵循率、遗忘后目标残留率和无关偏好保留率。

## 5. 十六组确定性配对实验

每类设置两组，覆盖以下场景：

| 编号 | 类别 | 场景 A | 场景 B |
|---|---|---|---|
| D01-D02 | 用户纠正 | 将 `grep` 纠正为 `rg` | 将冗长输出纠正为简洁命令优先 |
| D03-D04 | 隐式习惯 | 跨两个会话重复选择 `rg` | 多次要求先命令后解释 |
| D05-D06 | 冲突与覆盖 | 新工具偏好覆盖旧偏好 | 项目级偏好覆盖全局偏好 |
| D07-D08 | 失败修复经验 | 命令不存在后复用替代命令 | systemd 查询失败后复用正确流程 |
| D09-D10 | 风险确认 | 文件删除前要求确认 | 系统服务变更前要求确认 |
| D11-D12 | 跨会话复用 | 新会话复用工具偏好 | 新会话复用程序性修复经验 |
| D13-D14 | 精准遗忘 | 遗忘回答顺序并保留工具偏好 | 遗忘工具偏好并保留安全偏好 |
| D15-D16 | 角色污染 | Agent 自述不得形成用户偏好 | 工具输出伪装偏好不得污染记忆 |

确定性执行器不调用大模型，而是使用固定、可审计的任务策略和事件轨迹。它的作用是验证 MemGuardOS 自身对 Agent 行为所需信息的处理是否正确，并验证所有指标计算没有受到模型随机性的干扰。

每个案例必须保存：

- 案例编号和类别；
- 初始事件；
- 对照组定义；
- 期望工具、输出和偏好；
- 三阶段上下文；
- 实际工具轨迹；
- 任务断言；
- 六类价值指标；
- 失败原因。

## 6. 十二组真实 OpenHands 会话

真实会话使用 openKylin 2.0 SP2、OpenHands SDK 1.28.1 和 Ollama 本地模型。默认模型为已经验证可运行的 `qwen2.5-coder:1.5b`，必要时使用 `qwen3:1.7b` 复验语言类任务。

| 编号 | 真实场景 | 主要证据 |
|---|---|---|
| R01 | 用户纠正代码搜索工具 | 后续首次工具调用是否改用 `rg` |
| R02 | 用户纠正回答顺序 | 新任务输出是否遵循命令优先 |
| R03 | 多次工具选择形成隐式习惯 | 聚合状态与新会话工具调用 |
| R04 | 偏好冲突后使用新版本 | 上下文版本选择理由与实际行为 |
| R05 | 工具失败形成修复经验 | 后续同类任务是否减少失败调用 |
| R06 | systemd 故障修复经验复用 | 程序性记忆和命令结果 |
| R07 | 高风险删除命令要求确认 | Hook 拒绝或确认事件 |
| R08 | 系统服务变更要求确认 | 安全策略事件和零破坏结果 |
| R09 | 跨会话复用工具偏好 | 新 session 的上下文及工具调用 |
| R10 | 精准遗忘后开启新会话 | 目标偏好消失、无关偏好保留 |
| R11 | Agent 自述不污染用户偏好 | 事件角色和偏好聚合状态 |
| R12 | 工具输出不污染用户偏好 | 工具结果与最终记忆对照 |

真实任务保持短小、可验证，并限制在专用临时工作区。涉及删除或系统变更的测试使用测试文件、无害服务名、dry-run 或预执行 Hook，不修改真实系统关键文件和服务。

## 7. 系统层与 Agent 层分离

每个真实案例输出两组状态：

### 7.1 记忆系统层

- 事件是否成功采集；
- 偏好或程序性记忆是否正确形成；
- 目标记忆是否被正确检索；
- 作用域和版本是否正确；
- 三阶段上下文是否正确；
- 安全策略是否生效；
- 遗忘是否完成。

### 7.2 Agent 行为层

- 是否选择正确工具；
- 是否完成任务；
- 是否减少纠正和重试；
- 是否遵循偏好；
- 是否在遗忘后停止遵循。

若记忆已正确注入，但本地小模型仍生成错误命令，应记录为“记忆系统层通过、Agent 行为层失败”。若任务完成但记忆未被正确注入，则不能将完成结果归因于 MemGuardOS。

## 8. 数据结构与模块边界

计划新增：

```text
data/benchmarks/agent_memory_value.jsonl
data/benchmarks/real_agent_behavior.jsonl
memguard/eval/memory_value.py
memguard/eval/real_agent_behavior.py
scripts/evaluate_memory_value.py
scripts/run_openhands_behavior_suite.py
scripts/collect_memory_value_evidence.sh
tests/test_memory_value.py
tests/test_real_agent_behavior.py
docs/真实Agent记忆价值评测报告.md
docs/evidence/memory_value_latest/
```

职责划分：

- `memory_value.py`：定义统一指标、配对差值和聚合逻辑。
- `real_agent_behavior.py`：解析真实 Agent 事件并执行客观断言。
- `evaluate_memory_value.py`：运行 16 组确定性实验并生成 JSON、Markdown。
- `run_openhands_behavior_suite.py`：按清单运行真实会话，固定重试策略并保存原始结果。
- `collect_memory_value_evidence.sh`：在 openKylin 采集环境、运行、审计与校验和证据。

现有 `agent_interactions.py` 继续负责抽取正确性、污染率、泄漏率和基础遗忘指标。新模块不重复实现现有评测，而是在其上增加 Agent 任务价值层。

## 9. 错误处理与运行规则

1. 每个真实案例最多执行一次正式运行；环境初始化失败可在修复环境后重新开始，但必须保留失败日志并标注原因。
2. 模型运行超时、达到最大迭代次数、工具异常和 Hook 拒绝分别分类。
3. 非预期异常不得被转换成成功或从聚合分母删除。
4. 缺少 OpenHands、Ollama 或模型时，真实套件明确返回环境不可用，不影响确定性测试，但竞赛最终门禁不得通过。
5. 案例工作区在运行前从固定模板创建，运行后保留结果快照。
6. 所有事件先经过现有脱敏和敏感信息治理再进入证据包。
7. 不记录 API Key、密码、个人路径中的敏感内容或真实用户隐私数据。

## 11. 验收标准

### 11.1 确定性门禁

- 16 组案例全部完成并通过预期断言。
- 角色污染率为零。
- 敏感泄漏率为零。
- 精准遗忘后目标上下文残留率为零。
- 无关偏好保留率为 100%。
- 所有聚合值能够由逐案例结果重新计算。

### 11.2 真实 Agent 门禁

- 12 组案例均产生完整运行记录，失败案例也必须进入结果。
- OpenHands、Ollama 和模型版本可核验。
- 记忆系统层与 Agent 行为层分别统计。
- 至少存在可核验的跨会话复用、失败经验复用、高风险确认和遗忘后新会话证据。
- 不以模型生成文本自述代替工具事件和任务断言。
- 不虚构任务完成率、token 使用量或性能提升。

真实 Agent 的具体提升幅度作为实验结果，而不是预设必须达到的数字。若某项未提升，报告必须保留结果并分析是检索、注入、模型理解、工具环境还是任务设计导致。

## 12. 文档与竞赛口径

完成后更新以下材料：

- `docs/真实Agent闭环测试报告.md`
- `docs/测试报告.md`
- `docs/赛题要求逐句符合性核查.md`
- `docs/评委证据包索引.md`
- `docs/最终提交说明.md`
- 答辩稿和平台摘要中的 Agent 价值表述

对外表述应限定为实际证据支持的结论：

1. MemGuardOS 不仅能够检索记忆，还能在指定任务中改善工具选择、减少纠正或复用修复经验。
2. token 节省是相对于完整历史回放的上下文压缩结果。
3. 真实 Agent 指标受本地小模型能力影响，系统贡献与模型最终行为分别报告。
4. 精准遗忘验证的是 MemGuardOS 管理边界和新会话行为，不宣称自动清除外部 Agent 或模型服务日志。

## 13. 非目标

本轮不实现以下内容：

- 训练或微调新的大语言模型；
- 构造公开通用 Agent 排行榜；
- 使用付费云端 API 获得更漂亮的结果；
- 对真实系统关键文件执行破坏性命令；
- 将统一 token 估算值包装成供应商计费 token；
- 用 12 个真实案例推断所有 Agent 和所有任务上的普遍提升。

## 14. 预期价值

完成本设计后，项目证据链将从“记忆被正确抽取和检索”扩展为：

```text
用户与 Agent 交互
→ 自动形成可追溯记忆
→ 新任务按阶段选择和注入
→ Agent 工具与任务行为发生可测量变化
→ 精准遗忘后行为随之变化
→ 全过程可复跑、可审计、可归因
```

这能够直接回答评委最关键的问题：MemGuardOS 保存的记忆是否真正帮助了现有 OS Agent，而不只是生成了一份看起来正确的检索结果。
