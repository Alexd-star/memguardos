# MemGuardOS openKylin 企业级原生产品设计

## 1. 设计目标

本设计将 MemGuardOS 从“具备 openKylin 原生入口和可复验能力的竞赛原型”提升为“可安装、可操作、可授权、可降级、可卸载、可审计的桌面产品”。完成标准不是目录中存在插件源码，而是普通桌面用户能够从 Peony 或 UKUI 发起任务，理解系统给出的风险和结果，并在失败时获得可执行的修复建议；管理员能够通过 Polkit 完成最小权限操作；交付人员能够使用拆分安装包部署所需组件，并用同一 Git 版本的证据证明结果。

## 2. 方案比较与选择

### 2.1 方案 A：继续扩展单体插件

把扫描、记忆写入、诊断和权限逻辑直接写进 Peony 与 UKUI 插件。它能快速做出可见界面，但会复制 Python 核心逻辑，难以测试，并使桌面插件和记忆语义逐渐不一致，因此不采用。

### 2.2 方案 B：薄原生客户端与稳定 JSON 契约

Peony、UKUI 和托盘只负责展示、确认和调度；扫描、状态、授权请求和审计仍由受测的 CLI/服务完成。原生组件通过稳定 JSON 契约消费结果，所有入口共享同一套敏感检测与记忆治理规则。本方案兼顾桌面体验、可测试性和维护成本，作为最终方案。

### 2.3 方案 C：全部重写为 Qt 原生服务

该方案原生程度最高，但会重写已经稳定的存储、检索和遗忘主链路，风险和工期不符合当前项目阶段，因此不采用。

## 3. 产品架构

系统分为五个清晰边界：

1. `memguard/desktop/` 提供与界面无关的扫描批处理、任务报告和通知事件模型。
2. `memguard/os_guard/` 聚合 systemd、cgroup、Polkit、SDK 和桌面组件状态，输出结构化等级与修复动作。
3. Peony、UKUI 和托盘是薄 Qt 客户端，不自行判断敏感内容，不直接读写数据库。
4. Polkit helper 只接受固定动作标识，不接收任意命令、路径或 shell 片段。
5. Debian 构建产生核心、桌面、Agent 桥接和文档四个二进制包，并保留兼容元包。

## 4. Peony 文件治理流程

右键菜单名称调整为【使用 MemGuardOS 检查记忆内容】，避免在用户确认前暗示一定导入。流程如下：

1. 插件把全部选中文件传给 `memctl desktop scan-files --format json`，不写入记忆。
2. Qt 对话框按文件显示类型、大小、风险等级、敏感标签、脱敏预览和建议动作。
3. 敏感、不可读、超限或二进制文件默认不可导入；安全文本默认未勾选，由用户主动确认。
4. 用户确认后，插件把允许项写入临时 JSON 清单，再调用 `memctl desktop apply-scan --manifest`。
5. 结果对话框显示成功、阻断、跳过和失败数量，并给出审计编号；桌面通知只承担完成提醒，不替代结果页面。

批处理必须限制文件数量、单文件大小和总字节数；路径必须规范化；清单采用一次性随机文件并设置用户私有权限。多文件任务中单项失败不能使已处理结果丢失。

## 5. UKUI 记忆安全中心

控制中心不再以大段命令文本为主要界面，而由以下结构化区域组成：

- 总览：整体健康等级、服务、SDK、审计、资源和桌面集成状态。
- 服务：启动、停止、重启和查看日志。普通检查无需提权，系统操作经 Polkit。
- 记忆：记录数量、最近写入、隔离数量、最近遗忘任务和审计链状态。
- 端侧能力：Kylin embedding/vector 状态、实际使用后端、预热与降级原因。
- 诊断：一键导出带时间、版本、系统和校验和的诊断包。

界面必须具备加载态、空状态、失败态、超时、取消和按钮防重复提交。原始 JSON 可作为“技术详情”折叠显示，但不能成为普通用户唯一可读结果。

### 5.1 openKylin/UKUI 视觉与交互标准

所有原生界面必须遵循目标 openKylin 系统的 UKUI 主题，而不是建立独立品牌皮肤：

- 不硬编码背景色、正文色、强调色、圆角、阴影和中文字体，优先使用 `QPalette`、系统 font、`QStyle` 与 UKUI/Kylin Qt Widgets。
- 图标使用系统主题中的语义名称，并为缺失主题图标提供简洁 fallback；不嵌入风格不一致的彩色 SVG。
- 控制中心沿用 UKUI 设置页的信息密度、分组标题、列表行、开关和按钮层级；危险操作只在最终确认处使用警示语义。
- Peony 对话框沿用文件管理器的原生模态窗口、表格选择、按钮顺序和焦点行为，不创建网页式卡片。
- 支持系统深浅主题、125%/150%/200% 缩放、键盘 Tab/方向键/Enter/Escape 操作、屏幕阅读器可访问名称和中文长文本换行。
- UI 字符串统一为自然中文并兼容 GB18030-2022；技术标识仅在详情区展示。
- 托盘图标与通知使用 UKUI/freedesktop 主题和通知中心，不自行绘制常驻浮窗。

VM 验收至少覆盖当前 openKylin 2.0 SP2 的默认主题、深色主题和 150% 缩放；截图必须能证明文字未截断、控件未重叠、焦点顺序合理。

## 6. Kylin SDK 能力协商

openKylin 环境默认请求 `auto` 后端：已预热且真实推理可用时使用 Kylin embedding 重排；超时、模型不可用或维度异常时在单次请求内降级到 hash，并记录原因。非 openKylin 环境继续默认 hash。系统维护有时效的能力缓存，避免每次检索重复冷探测；托盘和控制中心显示“正在使用 Kylin SDK”“已降级”或“未启用”，不得仅显示库文件存在。

Kylin SDK 不作为唯一硬依赖。企业级可用性的正确含义是优先利用系统能力并可观测降级，而不是系统 SDK 故障时让检索中断。

## 7. Polkit 安全模型

需要提权的操作只有服务安装/刷新、auditd 规则安装和安全 BPF 测试。每项 action 使用独立 helper 或由可信调用方传入固定动作参数；helper 清理环境变量、固定 `PATH`、校验调用动作并使用绝对路径。控制中心通过 `pkexec` 调用，明确展示授权目的和结果。证据必须包含策略安装、授权调用成功、拒绝未知动作和审计记录。

## 8. Debian 分包

- `memguardos-core`：Python 核心、CLI、daemon、systemd 单元和 Polkit helper。
- `memguardos-ukui`：Peony、UKUI、托盘、desktop/autostart 文件，依赖同版本 core。
- `memguardos-agent-bridge`：OpenHands 适配器、桥接脚本和模板服务，依赖同版本 core。
- `memguardos-doc`：中文手册、样例和许可证，`Architecture: all`。
- `memguardos`：兼容元包，依赖上述四包，方便一键完整安装。

分包遵循 Debian 的 `Depends`、`Breaks` 和 `Replaces` 语义，支持从旧单包升级。维护脚本必须幂等，卸载桌面包不能删除用户记忆，purge 核心包也不默认删除用户数据。

## 9. 托盘与通知

托盘展示服务健康、SDK 降级和审计异常，提供打开控制中心、打开 Web 控制台、刷新状态和退出。它使用低频轮询并在状态变化时通知，不能持续弹窗。托盘退出不停止核心服务。通知事件包含稳定事件码，便于测试与去重。

## 10. 状态探针与证据

cgroup 检查必须读取 `memguardd.service` 的 `ControlGroup`、`MemoryMax`、`CPUQuotaPerSecUSec` 和对应 cgroup v2 文件，而不是用当前 CLI 进程是否位于受限 cgroup 来判断服务治理状态。

最终证据包必须记录 Git commit、工作树状态、包版本、包所有权、插件哈希、Polkit 安装与授权、SDK 实际推理、Peony 预览/确认/阻断/批处理、UKUI 状态、托盘状态、服务 cgroup 和完整测试。证据采集在包含 `.git` 的部署树执行，若无 Git 元数据则必须显式传入并校验 `MEMGUARD_SOURCE_REVISION`，禁止写入含糊的 `synchronized_tree_without_git_metadata`。

## 11. 验收门槛

以下条件全部满足才允许标记完成：

1. Peony 多选预览、确认、敏感阻断、部分失败和结果页面实机通过。
2. UKUI 结构化状态和至少一项 Polkit 服务操作实机通过。
3. Kylin SDK `auto` 路径实机证明成功使用和故障降级两条路径。
4. 五个 Debian 包可以独立构建，完整安装、最小安装、升级和卸载通过。
5. 托盘在 UKUI 会话可见，状态变化通知去重有效。
6. cgroup 状态与 `systemctl show` 一致。
7. 当前 Git HEAD 的 openKylin 证据、SHA256 清单和 manifest 一致。
8. Python 测试、Qt 构建、静态检查、提交包审计和 GitHub CI 全部通过。
9. UKUI/Peony/托盘在默认与深色主题下均无硬编码配色冲突，150% 缩放无文字裁切和控件重叠。

## 12. 明确边界

本轮不把本地应用扩展为公网 SaaS，不增加与赛题无关的 Kubernetes、HA 或多租户控制平面；不把 BPF 测试路径包装成通用 DLP；不把应用层精准遗忘包装成介质级安全擦除。这些边界不会降低本轮 openKylin 桌面产品化质量，反而保证交付口径可信。
