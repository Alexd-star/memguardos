# MemGuardOS 检索尾延迟与 Agent 记忆价值增强设计

## 1. 背景与结论

MemGuardOS 当前已经完成 openKylin 原生部署、Kylin SDK 接入、混合检索、程序性记忆、精准遗忘、来源治理、真实 OpenHands 闭环和最终证据采集。最终基线为：openKylin `569 passed, 1 skipped`，竞赛就绪门禁 `242/242`；优化版 10k 检索 Recall@5 为 `1.0`，P95 为 `10.105 ms`，P99 为 `75.255 ms`。

现有证据仍显示三个可稳定改进的问题：

1. Kylin SDK 消融 P95 为 `279.641 ms`，P99 为 `1492.348 ms`。当前查询会对候选文本逐条请求 Kylin embedding，首次查询的尾延迟偏高。
2. 某次常规评测中完整图谱检索 Recall@5 为 `0.9815`，而 `hybrid_no_graph` 为 `1.0`。图谱信号不应无条件改变所有查询的排序。
3. 系统能证明记忆被提取和检索，但还需要更直接地证明记忆持续改善 Agent 的任务完成、工具选择、交互轮数、token 消耗和错误重试。

本轮采用渐进式增强，不重写已有存储、遗忘、审计和 openKylin 集成。核心方案是：持久化 Kylin 向量、多路排名融合、查询意图路由、稳定 Profile Block 和可归因的 Agent 记忆价值遥测。

## 2. 目标与非目标

### 2.1 目标

1. 将 Kylin 候选向量计算从查询热路径迁移到写入后的低优先级路径。
2. 使用独立检索器排名和 Reciprocal Rank Fusion（RRF）取代不可校准信号的直接混加。
3. 仅在关系、多跳、历史状态等查询中启用图谱增强，并保护强精确命中。
4. 为 Agent 提供小型、稳定、可审计的 Profile Block，减少关键偏好漏召回。
5. 记录记忆对 Agent 行为的实际贡献，区分“检索成功”“Agent 采用”和“任务改善”。
6. 所有增强保持离线可运行；Kylin SDK、远程模型和外部 benchmark 均不是默认硬依赖。

### 2.2 非目标

1. 本轮不把 SQLite/mmap 替换为外部向量数据库或图数据库。
2. 不引入公网 SaaS、多节点 HA 或云端必选模型。
3. 不允许通过删除失败样例、放宽标签或只报告最佳单轮结果提升指标。
4. 不把应用层精准遗忘描述为介质级安全擦除。
5. 不在本轮同时重构 UKUI/Web；UI 产品化在检索与 Agent 主链稳定后独立实施。

## 3. 总体架构

```text
记忆写入
  -> 质量与敏感治理
  -> SQLite/mmap/FTS/图谱写入
  -> 写入后向量任务
       -> Kylin embedding
       -> 内容哈希与模型版本校验
       -> 持久化向量缓存

Agent 查询
  -> 查询意图分类
  -> 并行候选生成
       -> FTS
       -> hash-vector
       -> Kylin-vector（可用时）
       -> entity
       -> graph（按需）
  -> 各检索器独立排名
  -> RRF 融合
  -> 强命中保护、治理过滤、冲突处理、去重
  -> Profile Block + Top-K 上下文
  -> Agent 执行
  -> 采用情况、工具结果和任务效果遥测
```

## 4. 持久化 Kylin 向量

### 4.1 数据模型

在 SQLite 中增加独立向量缓存表，不修改现有记忆主表语义：

| 字段 | 作用 |
|---|---|
| `memory_id` | 对应记忆标识 |
| `content_hash` | 规范化候选文本的 SHA-256 |
| `backend` | `kylin_sdk` 等后端名称 |
| `model_revision` | 模型、runtime 或 SDK 可识别版本 |
| `dimension` | 向量维度，Kylin 当前预期为 768 |
| `vector_blob` | 固定端序的 float32 二进制向量 |
| `status` | `ready/pending/failed/stale` |
| `failure_reason` | 最近失败原因，不保存异常栈到普通用户界面 |
| `created_at` | 首次生成时间 |
| `updated_at` | 最近更新或重建时间 |
| `last_used_at` | 最近检索使用时间 |

唯一键为 `(memory_id, backend, model_revision, content_hash)`。内容更新、遗忘或模型版本变化时，旧向量标记为 `stale`；精准遗忘必须同步删除对应向量行。

### 4.2 写入后任务

默认写入成功不等待 Kylin 推理。服务将任务写入受限队列，由低优先级 worker 生成向量。队列要求：

- 同一内容哈希去重；
- 有最大长度和背压；
- 失败采用有限次指数退避；
- SDK 熔断期间不重复提交；
- 服务关闭时不破坏已经写入的主记忆；
- 无 worker 或 SDK 不可用时继续使用 FTS + hash-vector。

本轮先实现单进程有界 worker 和可显式运行的回填命令；systemd 后台回填作为同一接口的部署形式，不引入第二套逻辑。

### 4.3 查询路径

查询时只生成一个 query embedding。候选记忆使用持久化向量；缺少向量的候选不阻塞请求，继续由其他检索器参与融合。若 query embedding 超过延迟预算、维度错误、socket 不可信或 SDK 熔断，则整次查询使用稳定 fallback，并在结构化状态中记录降级原因。

## 5. 多路排名融合与查询路由

### 5.1 独立检索器

每个检索器返回统一结构：

```json
{
  "memory_id": "mem_xxx",
  "retriever": "fts",
  "rank": 1,
  "raw_score": 12.4,
  "evidence": ["exact_service_name"],
  "latency_ms": 1.2
}
```

原始分数仅用于该检索器内部排序，不直接跨检索器相加。

### 5.2 RRF

融合分数采用：

```text
RRF(d) = sum(weight_r / (k + rank_r(d)))
```

默认 `k`、各检索器权重和候选池大小必须集中配置，并由固定数据集和留出集共同选择。配置变更必须触发消融评测，不允许为单个失败案例写 question-id 特例。

### 5.3 查询意图

第一版使用可解释、确定性的意图分类：

- `exact_lookup`：文件名、命令、服务名、错误码；
- `preference`：用户偏好、纠正和当前策略；
- `procedural`：如何操作、失败修复、工具经验；
- `temporal`：当前、之前、最近、某时段；
- `relational`：实体关系、多跳关联；
- `general`：无法可靠归类。

路由只调整检索器权重和是否启用图谱，不直接生成答案。分类置信不足时使用 `general`，避免错误路由造成召回损失。

### 5.4 强命中保护

以下候选在通过治理、scope 和冲突过滤后，不得被弱图谱结果挤出 Top-K：

- 完整命令、文件路径、错误码或服务名精确命中；
- 明确 preference topic/value 命中；
- 当前有效版本的直接实体事实；
- 与查询 session/project scope 完全一致的高信誉记忆。

图谱增强只在 `relational`、`temporal` 或需要多跳证据时参与；图谱结果必须能回溯到原始记忆或 episode。

## 6. Profile Block

Profile Block 是始终可见但有严格大小预算的结构化上下文，不等同于把全部长期记忆塞入 prompt。字段包括：

- 明确用户偏好；
- 当前项目与任务范围；
- 常用且已经多次验证的工具选择；
- 高风险操作确认策略；
- 最近有效纠正；
- 必须遵守的安全约束。

每个字段必须包含来源 memory_id、有效期和信誉等级。Profile 只从 active 且可信的记忆生成；隔离、遗忘、过期或冲突旧版本不得进入。Profile 有字符/token 上限，更新采用确定性优先级，不能由模型无边界改写。

## 7. Agent 记忆价值遥测

每次真实 Agent 运行记录以下阶段：

1. `memory_retrieved`：检索到了什么；
2. `memory_selected`：进入了哪些上下文；
3. `memory_adopted`：Agent 输出或工具参数是否实际采用；
4. `task_effect`：任务是否成功、工具是否正确、重试和交互是否减少；
5. `failure_attribution`：检索缺失、排序错误、上下文被忽略、工具失败或模型行为失败。

核心指标：

- 使用记忆前后任务完成率；
- 工具选择准确率；
- 平均交互轮数；
- prompt token 数；
- 错误命令与重复尝试数；
- 偏好遵循率；
- 检索成功但未采用率；
- 记忆污染率和敏感泄漏率。

所有对照实验使用同一任务、同一模型配置、同一随机种子和同一工具权限。报告配对差值、原始案例和失败归因，不只报告平均值。

## 8. 错误处理与安全边界

- 向量缓存损坏：忽略该行、记录审计并排队重建，不影响主记忆读取。
- 维度或模型版本不一致：标记 `stale`，禁止参与向量检索。
- worker 队列满：保留主记忆，向状态接口暴露积压，不阻塞用户写入。
- SDK 超时：触发现有熔断与 fallback，不在同一请求中无限重试。
- 精准遗忘：主记录、FTS、图谱边、向量缓存、Profile 派生项和查询缓存必须一起失效。
- 隔离记忆：不得生成向量、进入 Profile 或参与任何检索器排名，批准后再构建索引。
- 遥测：默认记录标识、计数、延迟和脱敏摘要，不记录密钥、完整敏感正文或模型隐藏推理。

## 9. 迁移与兼容

数据库迁移必须可重复执行，并兼容没有向量表的旧数据目录。升级后：

1. 现有服务可以立即启动并继续使用旧检索路径；
2. 后台逐步回填 active、可信、未遗忘记忆；
3. 回填可以暂停、恢复和查看进度；
4. 降级到旧版本时不依赖新表即可读取主记忆；
5. `.deb` 升级、卸载 desktop 包和保留用户数据的行为不变。

## 10. 测试与消融

所有行为遵循测试先行。测试层次包括：

1. 单元测试：向量序列化、版本失效、RRF、路由、强命中保护、Profile 预算；
2. 属性测试：融合顺序稳定、重复候选幂等、遗忘后任何路径均不可召回；
3. 故障测试：SDK 超时、缓存损坏、队列满、worker 中止、模型版本变化；
4. 回归测试：现有全量测试、敏感治理、审计链、Peony/UKUI/Web；
5. 消融实验：FTS、当前 hybrid、RRF 无图、RRF 选择性图、Kylin 实时、Kylin 持久化；
6. 外部验证：LongMemEval-V2 small 和 MemoryAgentBench 代表性子集；
7. 实机验证：同一 Git HEAD 在 openKylin 运行全量测试、三轮性能套件和真实 Agent 配对实验。

## 11. 验收标准

### 11.1 强制门禁

- 现有功能测试不得回退；
- 自建集 Recall@5 不低于当前最佳 `1.0` 的可复现实验结果；
- 精准遗忘候选精确率和召回率均不低于 `0.97`；
- 敏感阻断、脱敏和标签 F1 不低于当前结果；
- 三轮并发最差 P95 小于 `500 ms`；
- Kylin P99 目标小于 `500 ms`；未达到时不得进入默认同步关键路径；
- fallback 结果与无 Kylin 基线召回一致；
- 遗忘后向量、Profile、缓存、图谱和原文层均不可继续访问；
- 证据包含失败案例、运行环境、数据哈希、Git HEAD 和原始逐轮值。

### 11.2 Agent 价值目标

相对无记忆对照至少满足以下三项，并给出置信区间或配对原始值：

- 任务完成率提高；
- 工具选择准确率提高；
- 平均交互轮数下降；
- prompt token 下降；
- 错误命令或重复尝试下降；
- 偏好遵循率提高。

不预先写死提升百分比；第一轮基线完成后再设置不会诱导过拟合的正式门槛。

## 12. 实施顺序

1. 建立当前基线快照并固定数据 SHA-256；
2. 向量缓存 schema、迁移和遗忘联动；
3. 有界回填 worker、状态接口与 CLI；
4. 查询单向量 + 持久候选向量路径；
5. 独立检索器接口与 RRF；
6. 查询路由、强命中保护和选择性图谱；
7. Profile Block；
8. Agent 采用与任务效果遥测；
9. 本地消融与失败分析；
10. openKylin 实机性能与真实 Agent 对照；
11. LongMemEval-V2/MemoryAgentBench；
12. 最终证据、文档、提交包和 UI 展示更新。

## 13. 设计依据

本设计借鉴但不直接绑定于以下成熟方法：Mem0 的多信号检索和实体链接、Graphiti 的时间有效性与来源追踪、LangMem 的前台/后台记忆形成、Letta 的常驻 Memory Blocks、Qdrant 的 RRF、Voyager 的可验证技能经验，以及 OpenTelemetry/OWASP 的 Agent 观测与记忆投毒治理。所有借鉴都必须通过 MemGuardOS 自身的端侧约束、精准遗忘和 openKylin 实机测试后才能进入默认路径。
