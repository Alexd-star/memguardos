# MemGuardOS 最终缺口补齐设计

## 1. 目标与边界

本轮在不伪造双人标注的前提下，补齐严格资源对照、外部标准基准、记忆污染治理、遗忘边界、同一 Git HEAD 证据和企业交付安全能力。目标是让评分证据能够回答“功能是否真实、对照是否公平、数据是否外部、风险是否可控、结果是否来自当前代码”。

双人独立标注保留为唯一人工任务。系统只提供匿名标签模板、分歧检测、Cohen's kappa 和多数仲裁结果生成，绝不由程序复制预期答案冒充两名标注员。

## 2. 严格资源对照

新增成对 benchmark runner，以独立子进程分别执行 `memory_disabled` 与 `memguardos_enabled`。两组使用相同任务数据、相同 Python、相同迭代次数、相同预热和并发参数；父进程定时采集子进程 RSS 与 CPU 时间，报告峰值 RSS、平均 CPU 利用率、总 CPU 时间、P50/P95/P99、任务成功率与 token 估算。禁用组保留完整历史并执行相同任务，但不初始化、不写入、不检索 MemGuardOS，以形成可解释基线。

报告必须包含环境、数据 SHA-256、Git HEAD、命令行和每轮原始值，不以单次采样替代工作负载对照。

## 3. LongMemEval-V2 外部交叉验证

对接官方 `xiaowu0162/LongMemEval-V2`，固定代码 revision `be15ea6e995462f3391c1a610892df3f67dfa7bd`，数据 revision 由下载时解析并写入 manifest。适配器把 trajectory 中的文本事件按来源与轨迹标识写入独立 namespace，并将 `query()` 返回统一的非空文本 context items。

评测分两层：

1. 无需外部 LLM 的检索层，报告 evidence recall、MRR、查询延迟、上下文长度和失败样例；
2. 官方 harness 的端到端答案层，仅在配置固定 reader/judge 后报告准确率与 LAFS，未执行时明确标记 `not_run`，不得用检索指标冒充答案准确率。

为控制仓库体积，项目不提交官方大数据本体，只提交下载脚本、固定版本 manifest、适配器、测试夹具和运行报告。正式证据使用官方 small tier 的代表性子集或完整 small tier，记录样本选择规则。

## 4. 来源信誉与隔离审批

每条记忆增加来源治理元数据：`trust_level`、`trust_score`、`governance_state`、`governance_reason`。可信用户显式输入与已验证系统事件可直接激活；工具输出、网页内容、未知来源或命中提示注入/持久化操纵模式的内容进入 quarantine，不参与检索、冲突覆盖和 RAG 上下文。

管理员可列出隔离项，并执行 approve/reject。批准产生不可篡改审计事件并将记录纳入正常索引；拒绝执行逻辑删除并保留审计链。默认策略保守、离线、可解释，允许按来源 kind 配置阈值，但不引入不可复现的云端判定。

## 5. 企业交付能力

本地 Unix socket 继续作为默认接口。Web 控制台增加角色化 token：viewer 只读、operator 可写入与预览、admin 可确认遗忘和审批隔离项；鉴权采用 token 文件与常量时间比较，所有授权失败写审计。公网 TLS 不在 Python 内自造证书体系，而提供 systemd socket/reverse proxy 部署模板、最小 TLS 1.2 配置和 localhost 默认绑定。

新增健康/就绪端点、结构化 SLO 摘要、备份恢复校验脚本、灾备演练说明、制品 SHA-256 与可选 minisign 签名流程。单机比赛原型不宣称真正多节点 HA；交付能力准确表述为“具备备份恢复、故障检测和反向代理部署边界，未实现分布式一致性集群”。

遗忘保证限定为 MemGuardOS 管理的 SQLite、FTS、图谱、mmap segment 与审计可见索引；对外部 Agent 日志、备份、VM 快照和介质级清除输出 residue 清单。介质销毁遵循 NIST SP 800-88 Rev.2 的组织流程，不由本软件的逻辑删除冒充。

## 6. 验证与证据

所有行为变更先写失败测试，再实现最小代码。最终依次运行单测、ruff、compileall、文档链接、赛题门禁、Web smoke、严格资源对照、LongMemEval-V2 适配器 smoke、安全扫描、打包检查和压缩包 smoke。

本地通过后，把同一 Git HEAD 同步到 openKylin，确认源码语义哈希一致，再执行全量测试、资源对照、外部基准和正式证据采集。所有证据生成 manifest 与 SHA256SUMS，报告中同时记录当前 HEAD。

## 7. 验收标准

- 严格资源报告包含两种模式的同负载峰值 RSS、CPU 平均值、延迟和任务成功率；
- LongMemEval-V2 适配器满足官方 context item schema，报告固定上游 revision 和真实数据来源；
- quarantine 项不会出现在 search/build-context，批准后可检索，拒绝后不可恢复到活动索引；
- Web 权限矩阵由自动测试覆盖，高风险操作仅 admin 可执行；
- 遗忘报告明确 managed stores 与 external residues；
- 当前 HEAD 的本地和 openKylin 证据哈希可复验；
- 不把未运行的 reader/judge、未实现的多节点 HA、未执行的介质清除写成已完成。
