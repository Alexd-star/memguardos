# MemGuardOS 并发尾延迟优化与消融实验实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 降低六线程冷查询尾延迟，并建立使用统一数据、查询和统计口径的检索消融实验。

**Architecture:** 保留 FTS、图谱和最新记忆兜底三条召回路径，但把候选生成改成“按预算逐级补足”，避免每次冷查询无条件生成两倍候选。消融实验放入独立评测模块，通过受控检索配置比较文本、混合向量、图谱、缓存和完整系统，不改变默认生产行为。

**Tech Stack:** Python 3.10+、SQLite FTS5、`concurrent.futures`、pytest、现有 MemGuardOS 评测与 Markdown 报告体系。

---

## 文件结构

- 修改 `memguard/service.py`：候选预算控制、检索阶段计时和批量检索连接复用。
- 修改 `memguard/store/sqlite_meta.py`：提供按 ID 排除的最新记忆补足查询。
- 新建 `memguard/eval/ablation.py`：统一消融配置、运行器、统计和 Markdown 输出。
- 修改 `memguard/eval/run_eval.py`：接入消融摘要和更准确的并发指标。
- 修改 `tests/test_core.py`：候选预算、召回保持、并发连接复用和报告字段测试。
- 新建 `tests/test_ablation.py`：消融配置隔离、结果结构、缓存冷热对照测试。
- 更新 `docs/测试报告.md`、`docs/赛题要求逐句符合性核查.md` 和证据报告：写入实测结果与边界。
