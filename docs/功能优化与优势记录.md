# MemGuardOS 功能、优化与优势记录

日期：2026-05-19

本文是 MemGuardOS 当前成果的总记录，用于项目复盘、答辩准备、提交材料整理和后续开发接续。记录原则：只写已经实现或已经验证的内容；未稳定或未完成的能力必须明确标注为风险或后续计划。

## 1. 项目定位

MemGuardOS 是面向研究生操作系统开源创新大赛赛题 3 的 Linux/openKylin 智能体记忆系统。它不是普通 RAG 记忆库，而是把智能体记忆作为一种 OS 管理资源来设计，强调：

- 多源记忆提取；
- 偏好、知识、敏感策略记忆建模；
- 结构化检索与图谱关联；
- 结构化手动配置接入；
- shell 历史中的用户行为轨迹接入；
- 检索增强生成前上下文构建；
- 敏感记忆阻断与脱敏；
- 自然语言精准遗忘；
- 审计链与不可逆清除；
- openKylin 原生机制适配；
- 可复现评测和基线对比。

## 3. 关键优化记录

### 3.1 检索性能优化

早期检索对全量记忆直接混合打分，5k 记忆 openKylin P95 曾超过 500 ms。当前已改为：

- SQLite FTS 候选预筛选；
- 图谱候选补充；
- 少量最近记忆兜底；
- 候选集混合重排。

扩充 benchmark 后，openKylin 10k 记忆、150 次查询 P95 为 242.053 ms，低于 500 ms 目标。

### 3.2 检索可复现性优化

早期轻量向量使用 Python 内置 `hash()`，会受到进程随机种子影响。当前已改为 SHA-256 稳定哈希，使不同进程、不同平台上的排序更可复现。

### 3.3 敏感检测增强

已从基础 PII/凭据扩展到更贴近真实场景的敏感识别：

- 中文姓名；
- 中文地址；
- 银行卡号；
- AWS Access Key ID；
- GitHub/HuggingFace/API token；
- private key；
- OS 高风险路径。

为避免误报，中文姓名和地址采用上下文触发策略；`token bucket` 等非凭据场景被纳入负例。

### 3.4 精准遗忘增强

精准遗忘已覆盖：

- 中文偏好定向遗忘；
- 高风险操作确认策略遗忘；
- 普通缓存清理与精准遗忘的 hard negative；
- embedding SDK 维度信息与 vector SDK 信息区分；
- auditd shadow 案例和 journald 知识区分。

当前精准遗忘候选精确率、召回率、应保留成功率均为 1.0000。

### 3.5 冲突解决增强

冲突解决从基础 manual 胜过 inferred 扩展为可解释主题规则：

- `code_search_tool`
- `high_risk_confirmation`
- `linux_command_response`
- `response_language`
- `response_verbosity`

新增困难冲突：

- rg/grep 工具偏好冲突；
- 高风险操作是否确认；
- update 覆盖旧 manual；
- rollback 胜过 inferred。

当前冲突用例 6 条，openKylin 正确率 1.0000。

### 3.6 资源与存储指标增强

评测报告已新增：

- 进程 RSS；
- 段文件大小；
- SQLite 大小；
- 总存储 footprint；
- 单条存活记忆平均字节数；
- P50/P95/P99 延迟。

这能直接支撑端侧轻量化论证。

### 3.7 赛题逐句核查后的补强

根据 `docs/赛题要求逐句符合性核查.md` 的逐句核查，已补齐两个容易被评委追问的口子：

- `ingest-config`：从 JSON 或简单 YAML 手动配置中生成输出风格、工具偏好、安全策略、工作流知识等记忆。
- `build-context`：把统一检索结果整理成已脱敏的 RAG 上下文包，用于 OS Agent 的任务规划、工具调用和结果生成阶段。
- `build-prompt`：把上下文包渲染为 provider-neutral 的 LLM prompt，不调用外部 API，不增加比赛复现成本。
- `generate-answer`：提供默认关闭的可选 LLM adapter，支持 `dry-run`、本地命令和兼容 Chat Completions 的端点；比赛默认链路不依赖外部 API。
- `budget`：上下文包输出估算 token、显式 token 预算、截断状态；默认不启用预算裁剪，避免为了省 token 牺牲检索效果。
- `ingest-history`：接入 shell 历史中的用户行为轨迹，过滤低价值命令，保留调试、检索、服务管理、包安装、远程传输等对智能体有价值的行为记忆。

这些补强把赛题中的“手动配置信息统一接入”“用户行为数据接入”和“统一检索与生成链路”从部分满足提升为基本满足/已满足。

### 3.8 工程加固

经过代码和框架审计，补齐了以下成熟度问题：

- `memguardd.service` 从一次性 `doctor` 命令升级为常驻 `memguard.daemon`，openKylin 上已验证 `active (running)`。
- 自定义敏感正则增加名称、长度、编译、空匹配、过宽匹配校验，坏规则会被拒绝并审计。
- `ingest-config` 增加数据质量过滤，空值会进入 `skipped` 而不是污染记忆库。
- SQLite 元数据增加 `sensitivity_redacted`，RAG 上下文包可以解释敏感内容是否已脱敏。
- Unix socket API 增加可选令牌鉴权，演示环境可保持低摩擦，正式环境可用 `--auth-token-file` 加固。
- `Makefile` 增加 `clean`，用于清理 `__pycache__` 和 `.pytest_cache`。

## 5. 当前核心优势

### 5.1 赛题贴合度高

系统围绕“Linux 智能体记忆提取与精准遗忘”设计，包含记忆生命周期、OS 机制、敏感治理、遗忘验证和 openKylin 证据。

### 5.2 OS 证据比普通应用更强

项目已覆盖 mmap、systemd/cgroup、journald、auditd、Kylin embedding SDK 检测、Kylin vector SDK 真实 C++ 探针，能支撑操作系统赛题方向。

### 5.3 精准遗忘链路完整

遗忘链路为：

```text
自然语言请求 -> dry-run 候选 -> 用户确认 -> tombstone -> 元数据/FTS/图谱清理 -> compact -> 明文探针验证 -> 审计记录
```

它回答了“删得准不准”和“是否真的删除”两个核心问题。

### 5.4 指标和基线清楚

评测包含 text-only、无图谱混合检索、完整 MemGuardOS 三类对比，并覆盖 Recall、敏感 F1、遗忘指标、冲突指标、图谱指标、延迟和资源占用。

### 5.5 可靠性取舍诚实

Kylin embedding SDK 已检测到库、头文件和 768 维端侧模型，但真实推理在当前 VM 中超时。项目保留稳定 fallback，并用 Kylin vector SDK 真实探针补强 openKylin SDK 证据，避免过度宣称。

## 6. 当前剩余风险

| 风险 | 当前处理 |
|---|---|
| Kylin embedding SDK 推理超时 | 保留检测和探测命令，主路径使用稳定 fallback |
| fanotify/eBPF 未形成默认实时生产者 | auditd 已验证真实 OS 事件；已补默认关闭的 bpftrace openat 探针脚本 |
| benchmark 仍是开发规模 | 已扩充用户行为、API、UKUI、token 预算等 hard cases；后续可继续扩大自动生成数据 |
| 演示视频未录制 | 功能和指标稳定后再录制 openKylin 视频 |
| journald 最终日志 | 已采集到 `docs/evidence/latest/journald.txt` |
