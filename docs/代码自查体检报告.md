## 4. 精准遗忘复核

本轮重点复核了“预览内容”和“最终删除内容”是否可能发生偏移。当前自然语言请求只编译一次，形成带记忆类型、时间边界、关键词、保留条件和作用域标识的 `ErasurePlan`。候选查询先在 SQLite 层应用不可放宽的范围，再进入语义排序；缺少 Agent、session 或 project 标识时返回安全停止，不退化为全局删除。诸如“忘记上周关于 X 的偏好，但保留安全策略”会把时间、偏好类型和保留条件分别表达，不会把“安全策略”误当成删除目标。

删除确认后，系统不只设置逻辑删除标记，还会移除检索缓存、FTS 条目、持久向量、实体关系和 mmap 段明文。审计链保留事件存在性与删除证明，但相关详情替换为 SHA-256 承诺后重新构建哈希链。该保证覆盖 MemGuardOS 管理的数据库、索引、图谱和段文件，不等同于 SSD 介质销毁、虚拟机快照清除或外部 Agent 日志删除。

## 5. 评测可信度复核

16 组记忆价值场景是人工编写的固定三臂回归，用于验证指标计算和机制行为。输出已显式标记 `evidence_class=deterministic_authored_fixture`，不能再表述为真实模型因果实验。报告为完成率和工具选择准确率给出 Wilson 95% 区间，为二分类配对结果给出精确 McNemar 检验，为连续差值给出配对 bootstrap 区间和精确 Wilcoxon 符号秩检验。

真实 OpenHands runner 已支持 `--memory-mode on|off|paired`。`paired` 模式为同一案例建立相互独立的有记忆和无记忆工作目录，分别保存原始运行结果，再计算配对统计。代码与自动测试已经完成，但新的真实双臂结果必须在 openKylin 上实际运行后才能写入最终证据；历史 28 次真实运行可以证明闭环可执行，不能代替新双臂的因果比较。

## 7. 已知边界与后续增强

当前版本不宣称法证级介质擦除，也不删除虚拟机快照、备份或 OpenHands 外部日志。逐记录加密和 crypto-erasure 仍属于后续企业增强；多用户 RBAC、集群高可用、跨主机灾备和公网 TLS 网关也不属于本次 openKylin 单机赛题交付范围。冲突样例中的两个标注字段仍不能代替两名真人独立盲标，该项只能由人工流程补齐。

这些边界不影响本赛题主线功能，但答辩时应准确区分“MemGuardOS 管理范围内不可检索、不可恢复访问”和“介质级不可恢复”。对于真实 Agent 价值，应以新生成的 paired 原始运行和统计报告为准，避免只引用固定样例中的高分。

当前代码已经从原理型演示推进到具备明确安装、服务、桌面入口、Agent 适配、治理、评测和证据链的可交付单机产品。核心调用链没有发现仍以固定输出冒充功能的分支，关键按钮与 API 均有自动化和真实浏览器验证。发布前的主要风险已经从“功能是否实现”转为“最终证据是否与最终 Git HEAD 一致”，因此后续工作应严格按提交、同步、实机安装、全量复验、证据回传和提交包重建的顺序执行。
