# 竞品分析与借鉴清单（同赛题其他队伍作品）

分析对象为《其他队伍作品》目录中的三份材料：MemKylin 的两个版本仓库（旧版 CLI 架构 + 新版全栈架构，同一 gitee 仓库名的两次快照）与第三队 KylinAgentMemory（KAM）。本文回答两个问题：我们要不要做 CLI；对手有什么值得吸收。

## 一、三份竞品的真实水平

**MemKylin 旧版（FastAPI + CLI 演示 Agent）**：完成度最高的对手。真实的 BGE-M3+Qdrant 检索（Recall@5 0.9516、含 84 条难负例）、版本化记忆 + invalidate/erase 双删除语义、遗忘"dry-run→确认→级联擦除→删除后再检索三重验证"、openKylin 实机 P95 215ms（分段披露 embedding 是瓶颈）。评测方法论是全场最强：数据集带 manifest+sha256、盲测子集、每个未满分指标逐条归因失败样例。短板：无真实 Agent（自研 CLI 假工具）、零图形界面、零桌面集成、eBPF/mmap/deb 全部自认未做。

**MemKylin 新版（backend/frontend 全栈，自称 KylinMemGuard）**：设计野心最大但落地最差。亮点在"可验证性工程"：33 项能力六态注册表（verified/planned/failed…）+ 证据清单 API + 前端证据页；每条记忆独立 AES-256-GCM 密钥、遗忘时覆写擦除密钥（crypto-erase）；派生记忆联动遗忘（include_derived）；Agent 页六阶段轨道 + memory_influence 追踪 UI；560 条双人标注流水线；评测硬门槛红色阻塞。短板致命：Agent 全模拟、检索 Recall@5 只有 0.05（特征哈希假向量）、能力注册表里 openKylin 实机 verified=0、P95 560ms 超赛题硬指标、无桌面集成。

**第三队 KAM**：叙事激进（eBPF 在 write 系统调用处覆写脱敏、"写入即脱敏"），install.sh 系统工程细节像模像样（专用系统用户、auditd 规则、systemd 加固）。但核心造假：赛题核心"精准遗忘"零实现（连 delete 方法都没有）、评测系统性造假（查询向量=文档向量、测试不运行被测代码）、宣称 BGE-M3 实际全是随机向量、systemd/D-Bus 服务入口不存在不可启动。

## 二、全场格局：我们独有的三张牌

三家竞品**共同缺失**、而 MemGuardOS 已经做实的：

1. **真实 Agent 接入**：项目已接入真实 OpenHands，并保存 28 次历史真实运行；另有 16 组人工编写固定场景用于机制回归。两类证据必须分开陈述，不能把固定场景数字算作真实 Agent 配对实验。
2. **桌面集成**：三家的 UKUI 控制中心插件、Peony 右键、托盘全部为零（KAM 只有 YAML 开关）。我们三件套 + Web 控制台俱全且有实机截图。
3. **实机证据链**：新版 MemKylin 自己的注册表承认 verified=0；我们有 openKylin 实机 + 多发行版复验证据包 + deb 包。

对手比我们强、需要正视的：MemKylin 的**评测呈现方法论**（manifest、盲测、失败归因、延迟分段）和**答辩叙事结构**（六维对比表、诚实边界、负向结果当亮点）。产品弱但讲得好，是我们最该防的对手。

## 三、借鉴清单（按优先级）

### P0 答辩材料类（纯文档/PPT 工作，收益最高）

| 借鉴点 | 来源 | 做法 |
|---|---|---|
| 六维竞品对比表 | MemKylin PPT | PPT 加一页矩阵：真实Agent接入/遗忘可验证性/审计防篡改/内核防护/桌面集成/打包交付 六列，我们六列全勾，三家对手各自空一半以上 |
| 赛题指标达标清单 | KAM | 评测报告和 PPT 末尾按赛题原文口径逐条列"要求值 vs 实测值 ✅"，我们数字是真的，这张表就是压制性的 |
| 失败样例逐条归因 | MemKylin | 未满分指标列出具体失败样本和原因，把"不满分"讲成"评测严肃" |
| 诚实边界段落 | MemKylin | 文档明确区分生产级/原型级能力（如 BPF LSM 标注验证路径而非常驻防线），先于评委质疑声明边界 |
| 演示故障预案 | 新版 MemKylin | 录屏前备好 DEMO_FAILURE_FALLBACK：模型不可用→回放话术、服务未起→重启命令，避免现场翻车 |

### P1 评测可信度类（脚本级改动）

| 借鉴点 | 做法 | 成本 |
|---|---|---|
| 数据集 manifest | benchmark JSONL 附 manifest.json：随机种子、sha256、生成渠道（LLM 合成/规则/人工）披露 | 低 |
| 延迟分段化 | 检索报告把 P95 拆成 embedding/检索/融合各段并指出瓶颈 | 低 |

| 双人标注协议 | 冲突/偏好标注字段加 annotator_a/b + 裁决，对齐赛题"不少于2名标注员" | 中-高 |

### P2 功能补强类（代码改动，选 2-3 个做）

| 借鉴点 | 来源 | 为什么值得 | 成本 |
|---|---|---|---|
| 审计脱敏：遗忘审计只存指令哈希不存原文 | MemKylin | "审计通道不能成为二次泄露面"；我们审计哈希链更强，补这一条后两个卖点互相加强 | 低 |
| 派生记忆联动遗忘核查 | 新版 MemKylin | "忘了偏好，由它派生的知识还在吗"是评委最容易现场验证的漏洞；确认我们的 scope 遗忘覆盖派生链，未覆盖则补 include_derived | 中 |
| systemd 加固参数 | KAM/MemKylin | NoNewPrivileges/ProtectSystem=strict/ProtectHome/ReadWritePaths/TasksMax 几行 unit 配置，专业度可见 | 低 |
| auditd 目录监视规则 | KAM/MemKylin | `-w 记忆库目录 -p wa` 一条规则，构成"应用哈希链→auditd→BPF LSM"三层递进叙事 | 低 |
| 稳定偏好更新门控 | MemKylin | 一次性请求不得覆盖长期偏好，"LLM 建议、规则裁决、不确定则拒" —— 若我们目前是直接覆盖，这是真实缺口 | 中 |
| crypto-erase（每记忆独立密钥+遗忘时擦键） | 新版 MemKylin | 在"逐项复检证明查不到"之上叠加"残留密文也解不开"，遗忘不可恢复论证升一层 | 中 |

### P3 界面增强类（结合我们已有 Web 控制台）

- **Agent 页"记忆影响追踪"**（新版 MemKylin）：每条被召回记忆标注"改变了计划/工具选择/结果格式"及 why_retrieved 一句话，被排除的也列出原因。我们是真实 Agent，配上这个 UI 就是"全场唯一真实 + 全场最可解释"。
- **"命中 0 条但偏好仍生效"反例演示**（MemKylin）：他们的杀手级论证——行为约束与任务查询语义不相邻，按相似度召回原理上不成立，所以偏好走常驻注入。我们三阶段注入已实现该机制，把论证写进文档、演示里构造一个零命中场景。
- **能力状态/证据页**（新版 MemKylin）：把我们的实机证据包结构化成一页"OS 机制状态"（每项：状态/证据文件），对比对手 verified=0。

## 四、要不要做 CLI：不需要新做

我们已经有两个 CLI：`memctl`（管理员/脚本）和 `memguard`（普通用户交互式 shell，支持自然语言写入和 /search /forget 等命令）。竞品 MemKylin 的**唯一**界面就是 CLI，而我们 CLI 只是四种入口之一。

值得做的不是"新 CLI"，而是把 `memguard shell` 的演示观感向 MemKylin 看齐（他们在这上面打磨很久）：每轮交互显示"偏好约束表 + 记忆命中表 + 分段耗时"，让"记忆正在被使用"肉眼可见；可选做录屏用的脚本化场景（--no-pause 连播）。成本中等，优先级低于 P0/P1。

## 五、答辩防守准备

评委看过其他队材料后可能拿来问我们的问题：

1. "遗忘后数据真的不可恢复吗？"——先声明边界（受管范围内逐项复检可验证；磁盘镜像/外部副本不在保证内），若做了 crypto-erase 再加一层。
2. "你们的检索召回率为什么这么高/低？"——准备难负例说明和分段延迟数据。
3. "eBPF 拦截为什么不像某些方案在 write 处直接脱敏？"——答：全局拦截 write 无 pid 过滤会影响整机、前缀匹配可绕过，LSM 钩子才是正确路径（KAM 的实现正好是反面教材，可点到为止）。
4. "偏好会不会被一次性指令误覆盖？"——若补了更新门控，直接演示。
