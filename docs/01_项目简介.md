# 01 项目简介

本文档面向首次接触 MemGuardOS 的读者，说明项目是什么、解决什么问题、适合谁使用，以及和仓库中其他文档的关系。更完整的文件级索引见 [../PROJECT_INDEX.md](../PROJECT_INDEX.md)，正式评审视角的总览见 [项目介绍总览.md](项目介绍总览.md)。

## 1. 项目定位

MemGuardOS 是一个面向 Linux/openKylin 的智能体记忆系统。它服务的对象不是普通聊天机器人，而是在操作系统环境中长期执行任务的 OS Agent。这样的智能体会接触 shell 命令、配置文件、工具执行结果、服务日志、审计事件、用户偏好和项目知识。如果这些信息只被当作聊天上下文临时使用，Agent 会不断重复询问、重复踩坑，也无法证明某条记忆来自哪里、是否已经脱敏、是否可以被安全遗忘。

MemGuardOS 的目标是把这些输入转化为本地可管理的记忆资产。系统会判断一段信息是否值得长期保存，区分偏好记忆、知识记忆、策略记忆和程序性记忆，写入轻量化存储，并在后续检索、RAG 上下文构建、答复生成、自然语言遗忘和审计复核中持续使用。

## 2. 解决的问题

项目重点解决四类问题。第一，智能体需要从多源输入中提取真正有价值的记忆，而不是把所有文本无差别塞进向量库。第二，Linux 环境包含大量敏感路径、凭据和个人信息，系统必须在写入、检索和生成前进行敏感治理。第三，用户提出“忘掉某个项目代号”或“删除某类私人信息”时，系统要给出候选、解释原因、二次确认并验证明文不可再检索。第四，操作系统赛题要求作品体现 Linux 机制，因此项目不仅有应用层逻辑，也接入了 systemd、cgroup、auditd、journald、BPF LSM 和 UKUI/Peony 桌面集成。

## 4. 核心能力概览

MemGuardOS 已实现文本、文件、配置、shell 行为、工具执行结果、OS 事件和 auditd 日志接入。接入后，系统会进行文本质量校验、敏感识别、语义抽取、实体关系抽取、层级图谱构建、轻量向量表示和 FTS 索引。检索阶段采用全文、hash-vector、图谱关联、冲突处理、时间有效性过滤和可选 Kylin embedding 重排。生成阶段提供 RAG 上下文包和 provider-neutral prompt。治理阶段提供自然语言精准遗忘、tombstone、compact、审计哈希链和 verify-forget。

这些能力不是孤立功能。它们共同构成一条“多源输入—安全抽取—轻量存储—解释检索—上下文构建—精准遗忘—审计复核”的闭环。对于比赛而言，这条闭环比单个模型调用更重要，因为评委可以复验每一步是否真正可运行。

## 5. 项目边界

项目默认不依赖外部 LLM API，不要求 GPU，也不把云端大模型作为必需组件。语义抽取主链路采用可解释规则和轻量策略，这是为了端侧稳定、离线可复现和审计友好。系统提供可选的外部增强入口，例如本地命令式 NER/LLM JSON 增强器和 OpenAI-compatible 生成接口，但这些都不是默认依赖。

项目提供 Web 控制台、CLI、daemon 和 Unix socket API，但它不是公网 SaaS 平台。UKUI/Peony 集成已覆盖可见入口和文件扫描闭环，但不宣称已经替代完整桌面安全中心。BPF LSM 当前用于安全测试路径和可审查 denylist 策略验证，不默认拦截系统登录链路或高风险系统文件。
