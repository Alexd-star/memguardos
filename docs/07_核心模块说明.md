# 07 核心模块说明

本文档按业务能力说明 MemGuardOS 的核心模块，包括每个模块做什么、输入是什么、输出是什么，以及和其他模块的关系。

## 1. 多源接入模块

多源接入模块负责把不同来源的信息转成统一文本和结构化元数据。文本写入来自 `ingest`，配置写入来自 `ingest-config`，shell 行为来自 `ingest-history`，工具结果来自 `ingest-tool-result`，OS 事件来自 `ingest-os-event`，auditd 日志来自 `ingest-auditd`。输入格式不同，但最终都会交给 service 做质量校验和记忆建模。

该模块的关键价值在于让 OS Agent 的真实工作轨迹进入记忆系统，而不是只保存用户聊天文本。特别是工具结果和 shell 行为，能够沉淀“遇到什么状态、执行什么动作、得到什么结果、下次应如何处理”的程序性经验。

## 2. 质量治理模块

质量治理模块位于 `memguard/ingestion/quality.py`。它负责 Unicode 标准化、空输入拒绝、长度限制、低质量提示和来源质量记录。输入是一段原始文本和来源类型，输出是标准化文本和 QualityReport。该模块能减少脏数据进入后续抽取和检索链路。

## 3. 敏感治理模块

敏感治理模块位于 `memguard/sensitivity/`。它识别凭据、私钥、访问令牌、手机号、银行卡、中文地址、系统敏感路径和自定义规则。对于高风险内容，系统可以阻断；对于可保留但不宜明文暴露的内容，系统会脱敏并记录标签。该模块同时服务写入、检索、RAG 上下文和遗忘验证。

## 4. 记忆抽取模块

抽取模块位于 `memguard/extraction/`。它根据文本中的表达方式、技术词、命令结构、偏好句式和工具结果字段，判断记忆类型和标签。输出包括偏好记忆、知识记忆、策略记忆、程序性记忆、实体和关系。默认抽取可解释、可复现，适合端侧运行；可选增强器可以接入本地 NER/LLM，但不进入默认依赖。

## 5. 存储与索引模块

存储模块由 mmap 段文件和 SQLite 索引数据库组成。段文件保存记忆载荷，SQLite 保存 ID、来源、类型、标签、脱敏后的检索内容副本、FTS、图谱、版本、删除标记和审计事件。输入是 MemoryRecord，输出是可检索、可审计、可 compact 的本地存储。该模块与精准遗忘关系最紧密，因为删除和 compact 都依赖它提供正确的索引和载荷管理。

## 6. 混合检索模块

混合检索模块位于 `memguard/retrieval/`。它把全文匹配、hash-vector 相似度、图谱关系、跨语言技术词扩展、冲突处理和可选 Kylin embedding 重排结合起来。输出结果不仅有分数，还包含来源、层级和解释信息。该模块直接服务 `search`、`batch-search`、`build-context` 和 Web 控制台。

## 7. RAG 上下文模块

RAG 上下文模块负责从检索结果中选择适合交给 LLM 的片段。它考虑 token 预算、敏感脱敏、来源分布、记忆类型、层级图谱和选择轨迹。输出是结构化 context package 或 provider-neutral prompt。上游 Agent 可以把该包交给本地或远程模型，也可以只用它做解释和审计。

## 8. 精准遗忘模块

精准遗忘模块根据自然语言请求筛选候选记忆，并在用户确认后执行删除。它会记录 tombstone、更新索引、必要时 compact 段文件，并通过 `verify-forget` 检查明文是否仍可检索。该模块的关键要求是“精准”：既不能漏删目标记忆，也不能误删无关知识。

## 9. 审计与 OS 机制模块

审计模块在 SQLite 中维护哈希链，记录写入、更新、遗忘、检索、API 调用和系统事件。OS 机制模块负责 systemd/cgroup、auditd、journald、BPF LSM、Peony/UKUI 等 Linux/openKylin 集成。它们共同证明系统不是普通文本库，而是能够在操作系统环境中运行和复验的智能体记忆模块。
