# MemGuardOS 顶尖能力差距与开发规划

> 2026-07-27 状态更新：本文“零、五维度差距总览”保留的是修复前审计基线，不代表当前缺陷。P0-1 至 P0-5、P0-7、P0-8 已完成并纳入测试；P0-6 已完成真实双臂 runner 与统计代码，等待最终 openKylin 实跑；P0-9、P0-10 已完成服务单元、安装脚本和权限自收敛代码，等待最终 HEAD 实机评分与证据。P1-1 独立向量召回、P1-5 crypto-erase 等仍是后续能力，不得表述为已经交付。

本文回答一个问题：**要成为"面向 openKylin 的智能体记忆提取与精准遗忘机制"这个赛题下最顶尖的系统，我们还缺什么。**

结论由五路带行号证据的代码审计得出（提取与表示 / 检索与上下文 / 精准遗忘 / OS 集成 / 评测科学性），判据两条：赛题评分点是否被高质量满足；对照 mem0、Zep、Letta-MemGPT、MemoryBank、A-MEM 等业界系统是否存在代差。

## 零、修复前必须立刻处理的五个问题（历史基线）

这些不是"不够顶尖"，而是**会当场翻车或已构成错误行为**，性质与此前已修复的评分器基准泄漏同级。

### C1 精准遗忘存在超授权删除（最严重）

结构化遗忘意图被编译好之后，又被降维成自然语言字符串重新解析，**时间范围、作用域、类型条件全部静默丢弃**。

- 证据：`memguard/forgetting/natural_intent.py:117-140` 的 `to_forget_request` 把已解析的 intent 拼回字符串；`memguard/service.py:3012-3106` 用该字符串重走文本匹配。
- 后果："忘掉**最近三天**关于 systemd 修复流程的知识"会删掉所有同主题记忆，包含三个月前的。用户在 dry-run 里看到 time_range 被正确解析，会误以为它生效。
- 这是精准遗忘最不该犯的错——删除超出用户授权范围，且赛题 R30"精准"二字在此失守。

### C2 遗忘的否定/保留语义反向

- "忘记 A 的偏好但**保留** A 的知识" → 整条请求变成 no-op（要删的 topic 被塞进保留约束，`_violates_retention_constraints` 对 memory_types 与 topic 取或语义，导致含该 topic 的记录全被保护）。
- "**除了** X 以外" → 被解析成 target=X，即打击目标反了。
- 证据：`memguard/forgetting/planner.py:252-264`、`natural_intent.py:199-240`。

### C3 遗忘判定含 14 个 benchmark 字面分支（与已修复的评分器泄漏同性质）

`_anchor_policy_passes`（`memguard/forgetting/planner.py:29-47,126-149,267-328`）的分支与 `data/benchmarks/forgetting.jsonl` 的 29 条请求逐条对应，代码里直接出现 `"peony/右键"`、`"768"+"embedding"`、`"auto retrieval"`、`"审计链"+"失败"+"恢复"` 等字面串；而 `tests/test_forgetting_quality_gate.py` 又用同一份 29 条做发布门禁——**调参集与验收集完全重合**。因此"遗忘精确率/召回率 1.0000"属于自证。

### C4 SQLite 明文残留，但探针报告"不可恢复"

`service.py:3176` 把 `memguardos_sqlite_metadata` 列为遗忘已覆盖对象，`docs/安全与遗忘保证边界.md:7,17-18` 承诺"已从 SQLite 元数据、FTS 索引移除"，但字节级不成立：`mark_deleted` 未清空 `preference_value/source_uri/governance_reason` 等列，entity 表留孤儿行，FTS 未 rebuild，无 `secure_delete`/`wal_checkpoint`/`VACUUM`。评委一条 `strings memguard.sqlite3 | grep <已遗忘内容>` 即可现场证伪。

### C5 文档与最新评测结果自相矛盾

同一仓库里同时存在"全线 1.0000"（`docs/赛题要求逐句符合性核查.md:39-40`、`docs/超标准交付评分矩阵.md:21-23`）和"回落到 0.7333 / 0.0000"（`docs/eval_v2_report.md`）两套说法。评委并排看 30 秒即发现口径冲突，届时所有指标可信度一起塌方。

**另有一项已在本轮修复**：桌面入口经 `/usr/bin/memctl` 强制 `PYTHONPATH=/opt/memguardos`，而 `/opt` 副本停留在 7 月 10 日——这是"代码改了界面没变"的根因，已同步并固化为 `scripts/deploy_to_openkylin.sh`。

## 一、修复前五维度差距总览（历史基线）

| 维度 | 核心差距 | 与顶尖的代差 |
|---|---|---|
| 提取与表示 | 偏好提取是 7 槽位封闭域状态机，封闭集合在抽取/注入/遵循检查/修复话术四层重复硬编码 | mem0 是开放域自由抽取 + ADD/UPDATE/DELETE/NOOP 裁决；A-MEM 自动生成 keywords/tags。评委现场说"以后 diff 用 delta"即静默不提取 |
| | 无记忆整合/摘要压缩/去冗余；去重是精确字符串等值，而工具结果正文内嵌 duration_ms，保证近重复永不命中 | mem0 update 阶段、MemoryBank 日摘要+用户画像、Letta recursive summarization、A-MEM memory evolution 都是一级能力 |
| | 实体被模板字段名污染（`command`/`status`/`cwd` 入图），关系只有全对 co_occurs，`importance`/`language` 是死字段 | Zep/Graphiti 是 bi-temporal + 边级失效；mem0^g 存带时间戳三元组；Generative Agents 是 recency×importance×relevance |
| 检索与上下文 | **没有向量召回通道**——向量只是候选集内的重排器，候选来自 FTS，语义召回上限被词面匹配锁死 | mem0/Zep/Letta 第一召回通道都是 ANN 向量检索。零 token 重叠的改写查询根本进不了候选池 |
| | Kylin embedding 每次 fork 一个 Python 进程重建 SDK session，模型加载成本无法摊销，实机常年熔断降级 | 实机 `embedding-cache status` 为 `ready:0, pending:2`，语义路径在交付态实际关闭 |
| | 上下文是"贪心填充+硬截断"，会产出半句话证据；无 MMR 去冗、无按阶段预算分配 | 应为 token 预算下的最优选择（背包/MMR） |
| 精准遗忘 | 见 C1–C4 | mem0/Zep 把删除条件下推为存储层结构化过滤 |
| | 无 crypto-erase，对 WAL/freelist/compact 旧块/备份只能靠免责声明 | 合规删除（GDPR 被遗忘权）的通行答案是密钥销毁；项目零依赖恰好可用 hashlib/hmac/secrets 实现 |
| | 审计链是被遗忘内容最持久的副本：遗忘请求原文永久明文入链 | 顶尖做法是只存承诺值（HMAC+长度+标签），或证明性审计与取证性明细分层 |
| OS 集成 | BPF LSM 是一次性验证探针而非常驻防线，且拦的是 `/tmp` 合成文件，真正的记忆库 `~/.memguardos/memory.segment` 无内核侧保护 | 这恰是纯应用层记忆系统做不到、OS 级系统唯一能立住的差异点，目前被浪费 |
| | 核心 `memguardd.service` 零硬化且以 root 运行，硬化程度低于外围 agent 桥接单元 | 一条 `systemd-analyze security memguardd.service` 即暴露（核心 9.x UNSAFE vs 边缘 2.x） |
| | 本地 socket API 无对端身份校验与角色模型，forget/evict 与只读检索同一无鉴权命令面 | 项目自带的 SO_PEERCRED 实现只用在验证别人身上 |
| 评测科学性 | "记忆价值"这一核心因果命题无真实对照：16 组配对实验的三臂结果是数据集里**手写的常数**，28 组真实会话无 no-memory 对照臂 | 两层各缺一半，合起来不构成因果证据。评委问"0.75→1.00 是谁测出来的"即暴露 |
| | "双人标注"是脚本把 gold 标签复制两份，200 条样例只有 31 条唯一文本 | 连分歧的可能性都不存在，比不写更危险 |
| | 无任何统计推断：无置信区间、无配对显著性检验、关键评测只跑一次 | holdout 20 条报 0.3 的点估计，95% Wilson 区间实际宽到 0.15–0.52 |
| | 消融只覆盖检索通道且跑在饱和的 v1 数据集上；被主张为创新的机制无一条有"去掉会怎样"的数据 | 三阶段注入、偏好门控、别名表、时效窗口、热度、遗忘复检全无消融 |

## 二、开发规划（按优先级）

### P0 — 诚实性与正确性（必须在答辩前完成）

| 编号 | 任务 | 关键验收 |
|---|---|---|
| P0-1 | **结构化 ErasurePlan 下推**：新增 `forgetting/plan.py`，编译器直接产出 ErasurePlan，`sqlite_meta` 新增 `select_forget_candidates(plan)` 把 scope/time/type 做成 SQL WHERE，删除字符串回环 | 种入 T-1d/T-5d/T-40d 同主题记忆，"最近三天"只命中 T-1d |
| P0-2 | **修正否定/保留/例外语义**：retention 约束不再携带遗忘 topic；"除了…以外"生成排除而非目标 | "忘记 X 偏好但保留 X 知识"执行后 preference 删、knowledge 留 |
| P0-3 | **删除 `_anchor_policy_passes` 字面分支**，改用 IDF 判别度 + 锚点覆盖率；新增 30 条未参与调参的 holdout | `grep 'peony\|768\|auto retrieval' planner.py` 为空；原 29 条 P/R ≥0.90，holdout 如实报告 |
| P0-4 | **补齐受管面明文清理**：孤儿 entity GC、清空残留列、FTS rebuild、`secure_delete`+`wal_checkpoint`+`VACUUM`；探针新增字节扫描 | 哨兵串在 MEMGUARD_HOME 全部文件中命中数为 0 |
| P0-5 | **指标单一真值源**：文档数字全部由结果 JSON 渲染，新增 `check_metric_consistency.py` 进 CI | 故意改一处文档数字必须使 CI 失败 |
| P0-6 | **真实 A/B 配对实验**：`run_openhands_behavior_suite.py` 增加 `--memory-mode {on,off,paired}`，同模型同 workspace 成对运行，做 McNemar/Wilcoxon 检验 | 每 case 含 memory_on/memory_off 两条真实记录；p 值如实写入 |
| P0-7 | **确定性配对层去伪装**：标注 `arm_source="authored_fixture"`，禁止再以其数字作为记忆价值的独立主张 | `grep "0.7500→1.0000"` 每处上下文都出现"固定场景定义"字样 |
| P0-8 | **统计推断层**：新增 `eval/stats.py`（Wilson/bootstrap/McNemar/Wilcoxon，纯标准库），所有比率指标输出 point/ci_low/ci_high/n | 报告显示 `0.7333 [0.6116, 0.8266] n=60` |
| P0-9 | **memguardd 服务硬化**：User=memguard、StateDirectory、NoNewPrivileges、ProtectSystem=strict、SystemCallFilter 等 | `systemd-analyze security` 总分 ≤3.0（当前 9.x） |
| P0-10 | **记忆库权限收敛 + 自审计**：目录 0700 / 文件 0600，把自身库纳入 auditd 规则 | 人为 chmod 0644 后启动自动收敛并写审计 |

| 编号 | 任务 | 关键验收 |

| P1-2 | **Kylin embedding 常驻服务**：daemon 内 worker 复用 session，入库即入队后台建向量 | 实机 `embedding-cache status` 从 `ready:0` 变为 `ready==活跃记忆数` |

### P2 — 加分与长期

多跳类型化图谱遍历（`WITH RECURSIVE`）、伪相关反馈替代手工别名表、学习式排序替代手工魔数、层次化摘要与用户画像、D-Bus 服务接口取代 QProcess 冷启动、audisp 实时流、规范 Debian 源码包 + lintian + piuparts、LongMemEval/LoCoMo 外部基准首个真实数字、mem0/Zep 风格本地复现基线横向对照。

## 三、执行顺序建议

1. **第一批（诚实性）**：C1–C5 对应的 P0-1~P0-5、P0-7。这批不做，任何指标都不可信。
2. **第二批（能力）**：P1-1 向量召回 + P1-2 常驻 embedding。这两项是检索维度所有短板的共同根因（`cross_language_recall_at_1=0.0` 就是它的直接后果）。
3. **第三批（OS 差异化）**：P0-9、P0-10、P1-5。把"OS 级"从口号变成可现场验证的事实——这是我们相对三家竞品唯一无法被追平的护城河。
4. **第四批（说服力）**：P0-6、P0-8、P1-9、P1-10、P1-11。

## 四、我们已经领先的地方（不要在这些上再投入）

三家竞品**全部缺失**、而我们已做实的：真实 OpenHands 接入、UKUI/Peony/托盘桌面三件套、openKylin 实机证据链与多发行版复验、遗忘逐项复检 + 检索面真探测、审计哈希链、偏好更新裁决、命中热度。这些是答辩时的主攻方向，本规划中的工作是补短板而非替换长板。
