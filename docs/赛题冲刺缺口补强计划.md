# 赛题冲刺缺口补强计划

本文记录本轮对七个高风险缺口的处理方案和完成口径，避免最终提交时出现“实现已做但证据或表述没跟上”的问题。

## 1. 最终提交分支

最终提交以 `feature/real-agent-foundation` 为准。该分支已经取消 draft 状态并推送到 GitHub。若评审平台默认拉取 `main`，应在提交说明和压缩包清单中明确填写本分支；若需要合并到 `main`，应等待 GitHub Actions 最新运行完成后再执行合并，避免把未完成 CI 的提交直接作为主分支。

## 2. 性能证据 latest 口径

`docs/evidence/latest/` 只保留优化后的 10k 性能结果作为当前口径。优化前并发 P95 超过 500 ms 的文件已归档到 `docs/evidence/historical/performance_before_optimized_20260607/`。正式答辩只引用 `docs/evidence/latest/eval_result_openkylin_10k.json` 和 `docs/evidence/performance_latest/`。

## 3. openKylin 安装证据

五包拆分、桌面包卸载重装、用户数据保护、Polkit 资产、Peony/UKUI/托盘资产已经在 `docs/evidence/openkylin_native_latest/` 中保存。后续如果 Git HEAD 继续变化，应重新在 openKylin 维护模式采集证据。

## 4. 自然语言精准遗忘

新增对现场常见表达的解析：近 N 天、过去 N 天、显式日期范围、显式会话号、当前项目、OpenHands Agent、工具偏好、敏感标签和保留约束。所有自然语言请求仍默认 dry-run，并要求用户确认后才执行。

## 5. BPF LSM 边界

BPF LSM 能力按“路径 denylist 内核态拦截”表述，不包装成通用内容级 DLP。内容级敏感识别由用户态检测器、自定义规则、审计链和遗忘流程共同完成。新增 JSON denylist 示例用于演示和复核。

## 6. 工具结果反推偏好

新增工具执行结果统计沉淀模块。它会从成功/失败次数、平均耗时和替代工具失败记录中生成偏好候选，例如“代码搜索优先使用 rg，避免 grep”。该模块用于证明工具调用执行结果不是只被存档，而能转化为后续 Agent 可复用的操作习惯。

## 7. 抗定制质疑

EvidenceBench v2 已覆盖 holdout、hard negative、跨语言、冲突、自然语言遗忘、敏感治理和 OS Agent 场景。v2 报告保留边界失败样例，不追求所有指标 1.0000，用于降低“只为固定样例调规则”的质疑。
