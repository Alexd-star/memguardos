# 03 操作手册

本文档面向安装部署、运行维护和演示复验人员，说明 MemGuardOS 的部署、启动、停止、验证和日常维护流程。更正式的部署说明见 [部署手册.md](部署手册.md)。

## 1. 操作角色与范围

MemGuardOS 支持三种运行形态：本地开发运行、openKylin 服务化运行和 `.deb` 安装运行。本地开发运行适合调试和单元测试；openKylin 服务化运行适合赛题复验；`.deb` 安装运行适合演示产品化交付能力。

操作人员应区分“完整工程仓库”和“正式竞赛提交包”。完整工程仓库包含打包、自检、CI、研究资料和过程文档；正式提交包只包含评审需要的代码、脚本、数据、正式文档和最新证据。

## 2. 本地安装

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python scripts/demo_smoke.py
```

如果 `pytest` 通过，说明核心写入、检索、遗忘、审计、API、Web 控制台和脚本 smoke 均具备基础可运行性。若失败，应先阅读错误栈，再查看 [14_常见问题FAQ.md](14_常见问题FAQ.md)。

## 3. openKylin 部署

在 openKylin 中建议使用：

```bash
sudo bash scripts/install_openkylin.sh "$(pwd)"
sudo systemctl daemon-reload
sudo systemctl enable --now memguardd
systemctl status memguardd --no-pager
```

`install_openkylin.sh` 会安装 systemd 单元和必要运行入口。维护人员可使用 `journalctl -u memguardd` 查看服务日志，使用 `systemctl show memguardd -p MemoryMax -p CPUQuotaPerSecUSec` 检查 cgroup 限制。

## 4. namespace 模板服务

```bash
sudo systemctl enable --now memguardd@demo-a
sudo systemctl enable --now memguardd@demo-b
systemctl status memguardd@demo-a --no-pager
```

模板服务用于验证多会话隔离。每个 namespace 使用独立数据目录、段文件、SQLite 元数据和审计链，避免不同 Agent 的记忆互相污染。

## 5. 证据采集

```bash
bash scripts/openkylin_verify.sh
bash scripts/collect_openkylin_evidence.sh --with-10k
```

证据采集完成后，应检查 `docs/evidence/latest/` 是否包含 `pytest.txt`、`eval_10k.txt`、`sdk_status.txt`、`verify_audit.txt`、`systemd_cgroup.txt`、`deb_apt_install_*.txt`、`ukui_*` 等文件。正式文档中的性能指标必须来自最新证据包。

## 6. `.deb` 安装复验

```bash
bash scripts/build_deb.sh
sudo apt install ./dist/memguardos_0.1.0_amd64.deb
memctl doctor
sudo systemctl start memguardd
```

openKylin 普通模式可能存在系统保护策略，完整安装复验建议在维护模式下执行。安装后应验证 `dpkg` 状态、`memctl` 命令、systemd 服务和 SDK 检测结果。

## 7. 安全操作注意事项

精准遗忘加 `--compact` 会改写段文件。BPF LSM 测试会验证安全测试路径的强制拒绝。auditd 规则会记录敏感路径访问事件。这些操作都应在可控演示环境中进行，正式环境中先备份数据并确认规则范围。

## 8. 日常维护检查

日常维护建议每次发布前执行：

```bash
python -m ruff check .
python -m pytest -q
python scripts/check_docs_links.py
python scripts/check_competition_ready.py --output docs/competition_ready.json --markdown docs/竞赛就绪自检报告.md
python scripts/package_submission.py
python scripts/inspect_submission_package.py
python scripts/smoke_submission_archive.py
```

如果只修改文档，至少应执行链接检查和竞赛就绪检查。如果修改代码、脚本或数据，必须执行完整测试。
