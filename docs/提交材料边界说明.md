# 提交材料边界说明

本文用于区分“研究生操作系统开源创新大赛提交作品主体”和“GitHub 工程化支撑材料”，避免评审或后续维护时混淆。

## 1. 作品主体

以下内容属于参赛作品主体，应随最终提交包提交：

| 路径 | 说明 |
|---|---|
| `memguard/` | 核心实现代码，包括记忆模型、存储、检索、敏感检测、精准遗忘、OS 适配和本地 API。 |
| `scripts/` | openKylin 安装、验证、证据采集、SDK 探针、演示和打包脚本。 |
| `tests/` | 单元测试和回归测试。 |
| `data/demo/` | 演示输入数据。 |
| `data/benchmarks/` | 标准化评测样例。 |
| `docs/` | 中文设计文档、测试报告、评测报告、证据包和答辩材料。 |
| `README.md` | 项目入口说明。 |
| `pyproject.toml` | Python 包配置。 |
| `Makefile` | 本地开发、测试、评测、打包命令。 |
| `LICENSE` | 开源许可证。 |

## 2. 工程化支撑材料

以下内容属于 GitHub/开源协作支撑材料，可以随源码提交到 GitHub，也可以放入最终提交包，但答辩时不应把它们包装成功能本体：

| 路径 | 说明 |
|---|---|
| `.github/workflows/ci.yml` | GitHub Actions CI，用于自动运行 lint、test、docs-check 和评测 smoke。 |
| `.github/ISSUE_TEMPLATE/` | GitHub issue 模板。 |
| `.github/pull_request_template.md` | GitHub PR 模板。 |
| `.github/CODEOWNERS` | GitHub 代码所有者配置。 |
| `.github/dependabot.yml` | GitHub 依赖更新提醒配置。 |
| `.devcontainer/` | VS Code Dev Container 配置。 |
| `CONTRIBUTING.md` | 贡献和维护指南。 |
| `SECURITY.md` | 安全问题报告和处理策略。 |
| `CHANGELOG.md` | 版本变更记录。 |
| `CODE_OF_CONDUCT.md` | 协作行为准则。 |
| `requirements-dev.txt` | 开发依赖清单。 |
| `Dockerfile`、`.dockerignore` | 可选容器化开发环境。 |
| `.gitattributes` | Git 换行和文本规范。 |
| `.gitignore` | 忽略缓存、构建产物、虚拟环境和临时数据。 |

## 3. 不进入提交包的内容

以下内容不应进入比赛提交包，也不应进入 Git：

| 路径/模式 | 原因 |
|---|---|
| `.git/` | Git 内部历史，不属于作品源文件。 |
| `.venv/` | 本地虚拟环境，可由依赖重新安装。 |
| `dist/` | 生成的提交包，避免包中套包。 |
| `*.egg-info/` | Python 本地安装生成的包元数据，可重新生成。 |
| `__pycache__/`、`.pytest_cache/`、`.ruff_cache/` | 缓存文件。 |
| `*.sqlite3`、`*.segment` | 本地运行时数据库和段文件，可能含敏感数据。 |
| 真实 token、密码、私钥、PII | 安全风险。 |

## 4. 推荐提交包口径

最终提交包建议以 `scripts/package_submission.py` 生成的 `memguardos_competition_submission_*.zip` 为准。该脚本会自动排除缓存、虚拟环境、Git 内部目录、临时数据库和构建产物，并生成 manifest。

脚本会同时生成两类包：

| 包名模式 | 用途 |
|---|---|
| `memguardos_competition_submission_*.zip` | 竞赛提交包，只包含作品主体、中文文档、证据包和项目配置。 |
| `memguardos_full_repository_*.zip` | 完整开源仓库包，额外包含 GitHub、Dev Container、Docker 和开源协作支撑材料，用于 release 或备份。 |

答辩时建议这样说明：

> 作品主体是 `memguard/`、`scripts/`、`tests/`、`data/` 和中文 `docs/`。`.github/`、`.devcontainer/`、`CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`、`CODE_OF_CONDUCT.md`、`Dockerfile` 属于开源工程化支撑材料，用于持续维护和回溯，不替代功能证据。
