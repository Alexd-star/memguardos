# MemGuardOS 平台摘要

本文提供可直接复制到竞赛平台、作品申报系统、开源仓库 Release 或答辩材料首页的项目摘要。不同平台字段长度不同，本文同时提供短版、中版、长版和创新点版。

## 1. 作品名称

MemGuardOS：面向 Linux 的智能体记忆提取与精准遗忘机制

## 2. 一句话摘要

MemGuardOS 是一套面向 openKylin/Linux OS Agent 的本地智能体记忆系统，支持多源偏好与知识记忆提取、敏感治理、RAG 上下文构建、精准遗忘、审计验证和操作系统机制集成。

## 3. 200 字摘要

MemGuardOS 面向研究生操作系统开源创新大赛赛题 3，构建了一套可在 openKylin/Linux 本地运行的智能体记忆系统。系统已接入现有 OpenHands Agent，自动采集用户消息、纠正反馈、工具调用和工具结果，提取偏好、习惯、知识和安全策略，并在后续会话的任务规划、工具选择和结果生成阶段注入脱敏、可解释的记忆上下文。用户可按 Agent、会话、轮次、主题或时间范围发起精准遗忘，系统完成候选预览、事件与派生记忆清理、索引清理、段文件 compact 和明文泄漏验证。项目还集成 mmap、SQLite FTS、systemd/cgroup、journald、auditd、BPF LSM、UKUI/Peony 和 Kylin SDK，形成可复验的 OS Agent 记忆基础设施。

## 4. 500 字摘要

MemGuardOS 是面向 Linux/openKylin 的智能体记忆提取与精准遗忘系统，聚焦 OS Agent 在长期运行中如何安全、轻量、可审计地管理用户偏好、系统知识、工具轨迹和敏感信息。与普通聊天记录库或单纯 RAG demo 不同，MemGuardOS 把记忆系统放在操作系统环境中设计：数据来源覆盖用户文本、文件、结构化配置、shell 行为历史、工具执行结果、OS 事件、journald/auditd 日志；记忆模型覆盖偏好记忆、知识记忆和敏感策略记忆，并支持 working、session、long_term 三层生命周期。

系统采用默认离线可复现的可解释抽取策略，记录抽取信号和置信度，并保留本地 NER/LLM JSON 增强入口。存储层使用 mmap 追加式段文件保存正文，SQLite 管理元数据、FTS、版本、图谱和审计哈希链；检索层结合 FTS、稳定 hash-vector、图谱召回、跨语言技术词扩展和冲突解决，为上游 Agent 输出已脱敏、带 token 预算估算的 RAG 上下文包。精准遗忘链路支持自然语言 dry-run、确认删除、tombstone、FTS/图谱清理、段文件 compact 和泄漏探针验证，避免只做搜索层隐藏。

在 OS 机制方面，项目实现了 namespace 多会话隔离、systemd daemon 与 Agent bridge、cgroup 资源限制、journald、auditd、BPF LSM、JSON denylist，以及 Peony 右键菜单和 UKUI 控制中心双入口；同时提供 CLI、Unix socket API 和 localhost Web 控制台。当前工作树本地全量测试为 635 passed、14 skipped；openKylin 上一次实机快照已归档，本轮将在最终源代码 HEAD 下重采。优化后 10k 负载检索 P95 为 10.105 ms、P99 为 75.255 ms、RSS 为 130444 KB。200 条 Agent 抽取专项指标保持 1.0000；16 组记忆价值配对实验中任务完成率由 0.7500 提升至 1.0000，Prompt token 较完整历史减少 61.1264%；原 12 组真实 OpenHands 会话与新增 R13-R20 扩展会话合计 28 组均已归档（含 8 组 holdout 留出盲测），记忆系统层与 Agent 行为层均为 28/28。系统默认不依赖 GPU、外部 LLM API 或重型向量数据库。

## 5. 1000 字摘要

MemGuardOS 是面向研究生操作系统开源创新大赛赛题 3 的 Linux/openKylin 智能体记忆系统，核心目标是解决 OS Agent 在真实操作系统环境中长期运行时面临的“记什么、怎么用、如何忘、如何证明”的问题。智能体在执行系统管理、代码构建、命令调试和桌面任务时，会持续接触用户偏好、命令习惯、工具执行结果、配置片段、系统日志和潜在敏感凭据。如果这些内容只是堆放在普通文本库中，系统很难区分长期偏好和一次性上下文，也难以在 RAG 生成前控制敏感信息、上下文长度和冲突指令，更无法在用户提出遗忘要求后证明相关明文已被清理。

MemGuardOS 围绕“多源提取、轻量存储、混合检索、精准遗忘、OS 机制、可复验证据”构建完整链路。接入层支持文本、文件、结构化配置、shell history、工具执行结果、OS event、journald/auditd 日志等来源；清洗层完成 Unicode 标准化、空输入拒绝、低质量告警和质量分审计；抽取层把输入建模为偏好记忆、知识记忆和敏感策略记忆，并记录抽取方法、信号和置信度。系统默认采用端侧可解释抽取，保证比赛环境可复现，同时通过 `MEMGUARD_EXTRACTOR_COMMAND` 预留本地 NER/LLM JSON schema 增强入口，增强失败时自动回退。

在存储和检索上，系统选择适合端侧的 mmap 追加式段文件与 SQLite 组合：正文写入段文件，元数据、FTS、版本、图谱关系和审计链写入 SQLite。检索层结合全文检索、稳定 hash-vector、图谱实体召回、跨语言技术词扩展、冲突解决、缓存和批量检索，支持面向任务规划、工具调用和结果生成的 Agent 批量查询。RAG 上下文构建阶段会对候选记忆排序、脱敏、裁剪并估算 token 预算，输出 provider-neutral prompt，方便上游本地模型或远程模型接入。系统默认不绑定外部 LLM API，降低部署成本，也避免评审复验依赖网络和云服务。

精准遗忘是项目的核心亮点之一。用户可以用自然语言提出“忘掉某项目代号”“删除某类临时凭据”等请求，系统先生成 dry-run 候选计划，展示可能被删除的记忆和依据；用户确认后，系统写入 tombstone、清理 FTS 和图谱索引、更新审计链，并在 compact 后通过探针验证元数据和段文件中是否仍存在目标明文。该设计强调“可证明的遗忘”，不是简单把记录从搜索结果中隐藏。安全治理贯穿写入和使用两端：系统内置 PII、凭据、私钥、银行卡、中文地址、OS 高风险路径等检测规则，支持自定义正则和受限自然语言敏感规则，高风险内容阻断，中低风险内容脱敏后进入记忆。

作为操作系统赛题作品，MemGuardOS 不停留在应用层算法演示，而是与 Linux/openKylin 机制结合。项目实现了 namespace 多会话隔离，显式 namespace 使用独立段文件、SQLite、敏感规则和审计链；提供 systemd daemon 和模板服务，支持不同 namespace 的独立 cgroup；通过 cgroup 设置 MemoryMax 和 CPUQuota，体现资源约束；接入 journald 和 auditd，把真实 OS 审计事件转为安全记忆输入；提供 BPF LSM `file_open` 安全测试路径，对 `/tmp/memguardos_lsm_secret` 完成强制拒绝验证，并支持从 JSON 生成可审查静态 denylist；提供 Peony 右键菜单和 UKUI 控制中心插件源码，已在 openKylin 上构建 `.so`，其中 Peony 右键菜单项和 UKUI 控制中心入口均已完成桌面可见验证，用于展示与桌面环境集成的可扩展方向。项目还对 Kylin embedding SDK 和 vector SDK 做了探测，可在 SDK 可用时作为可选重排增强，默认仍保留 FTS/hash/graph fallback，确保跨环境稳定运行。

当前工程提供 OpenHands runner/Hook、CLI、daemon、Unix socket JSON API 和本地 Web 控制台，覆盖用户-Agent 交互采集、偏好证据、三阶段上下文、范围化精准遗忘、审计和诊断。openKylin 上一次实机快照已归档，本轮将在最终源代码 HEAD 下重采；10k 负载检索 P95 为 10.105 ms，P99 为 75.255 ms，RSS 为 130444 KB；Agent 批量检索 P95 为 11.699 ms。统一消融中纯文本 Recall@5 为 0.8426，混合检索和完整系统均为 1.0000。记忆价值双层评测进一步证明系统不只“检索到记忆”：固定配对层减少交互、错误命令和历史回放 token，真实 Agent 层在 28/28 场景中形成正确工具调用、安全拒绝、合规修复或直接经验复用。MemGuardOS 以真实 Agent 闭环、端侧稳定、系统机制、可解释安全和证据闭环为核心竞争力。

## 6. 创新点摘要

1. **把真实 Agent 交互记忆做成 OS 组件**：接入 OpenHands 用户消息、反馈、工具事件，并结合 auditd、journald、systemd/cgroup、BPF LSM 和 UKUI。
2. **精准遗忘具备可验证闭环**：自然语言候选、dry-run、确认删除、tombstone、索引清理、compact 和明文探针验证组成完整链路。
3. **端侧轻量可复现**：默认不依赖 GPU、外部 LLM API 或重型向量数据库，使用 mmap + SQLite FTS + hash-vector + 图谱召回实现低成本部署。
4. **敏感治理覆盖写入与生成前上下文**：高风险内容阻断，中低风险内容脱敏，RAG 上下文输出前再次处理并保留审计证据。
5. **用户-Agent 习惯自动提取**：从真实交互中提取显式偏好、隐式习惯与纠正反馈，并防止 Agent 角色污染。
6. **面向 Agent 的批量检索和上下文预算**：支持任务规划、工具调用、结果生成等多查询场景，生成可交给 LLM 的脱敏上下文包。
7. **openKylin 原生适配证据充分**：包含 Kylin SDK 探针、systemd/cgroup、auditd、BPF LSM、Peony 右键菜单、UKUI 控制中心和证据包。
8. **工程交付完整**：提供源码、测试、评测、部署脚本、证据采集、中文文档、用户手册、答辩材料和正式提交包。
