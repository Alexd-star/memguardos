# 08 算法说明

本文档说明 MemGuardOS 的主要算法和策略。项目默认选择“端侧可复现、可解释、可审计”的算法路线，同时为 Kylin SDK 和本地/远程 LLM 留出可选增强接口。

## 1. 语义抽取算法

默认抽取器采用规则、词典、结构化字段和轻量语义模式结合的方式。它会识别偏好表达、知识陈述、风险策略、工具执行结果、状态—动作—结果结构和 Linux 技术实体。规则型抽取的优势是稳定、快速、离线、可解释；不足是泛化能力不如大型 NER/LLM。项目将其作为默认主链路，是为了符合端侧系统原型的可复验要求。

抽取结果包含记忆类型、标签、实体、关系、重要性、置信度和解释。评委追问“为什么不用大模型抽取”时，应说明：外部大模型可以作为显式增强器接入，但默认链路必须在 openKylin 离线环境中稳定复现。

## 2. 敏感检测算法

敏感检测采用正则、上下文词、风险路径表和自定义规则组合。私钥、访问令牌、密码等高风险内容倾向阻断；手机号、银行卡、地址等内容倾向脱敏保存；系统敏感路径会结合 OS 事件和 auditd 事件做风险判断。自定义规则支持用户通过自然语言生成候选正则，再经验证后保存。

## 3. 轻量向量算法

默认向量表示是稳定 hash-vector。系统对查询和文本分词后映射到固定维度向量，再用余弦相似度计算语义近似。它不是深度语义模型，但速度快、无依赖、结果可复现，适合默认 fallback。openKylin 存在 Kylin embedding SDK 且真实推理可用时，系统可以启用可选重排路径。

## 4. 混合检索排序

混合检索综合 FTS 分数、hash-vector 相似度、图谱邻接关系、实体命中、时间有效性和冲突处理。FTS 负责精确词项命中，hash-vector 负责轻量语义召回，图谱负责关联扩展，冲突处理负责同主题偏好中选取当前有效版本。

排序不是黑盒分数。`build-context` 和层次图谱检索会输出 selection_trace、source_distribution、type_distribution、layer_distribution 等解释字段，便于复核每条结果的来源。

## 5. 层次图谱检索

层次图谱检索把结果组织为摘要层、实体关系层和原文 chunk 层。摘要层回答“这批记忆大致说明什么”，实体关系层回答“哪些概念相互关联”，原文层保留可追溯文本。该策略借鉴 Agent Memory 研究中对长期记忆分层、知识图谱和上下文压缩的思路，但实现保持轻量，不要求独立图数据库。

## 6. 程序性记忆建模

当工具结果包含状态、动作、结果和经验字段时，系统会将其建模为程序性记忆。这类记忆适合保存“服务失败后如何恢复”“测试失败后如何定位”“依赖缺失后如何安装”等操作经验。检索时，Agent 可以根据当前状态召回历史动作和结果，从而减少重复试错。

## 7. 精准遗忘算法

遗忘规划器会解析自然语言请求中的关键词、专名、路径、代号和敏感锚点，再对候选记忆进行匹配。系统强调 distinctive anchors，即必须有足够具体的锚点才能高置信删除，避免“忘掉 Linux”这类宽泛请求误删大量知识。执行删除前默认 dry-run，确认后写 tombstone、更新 FTS/图谱、可选 compact，并用 verify-forget 复核。

## 8. 时间有效性和版本策略

每条记忆带有有效时间窗口。更新、回滚、提升和遗忘会关闭旧版本窗口，普通检索只返回当前有效记录。这样可以避免旧偏好和新偏好同时影响 Agent，也能在审计时追溯历史演化。

## 9. 审计哈希链

审计事件按顺序写入 SQLite，每条事件包含前序哈希和当前哈希。`verify-audit` 会从头计算链路，发现篡改、缺失或顺序错误时返回失败。该机制用于证明关键操作可追溯，是精准遗忘和安全治理的重要证据。
