# 外部标准基准说明

MemGuardOS 使用 LongMemEval-V2 作为外部交叉验证来源。该基准由其官方仓库提供 451 个手工整理问题、五类长期记忆能力、Web 与企业两个领域，并同时关注答案能力和查询延迟。项目固定官方代码 revision `be15ea6e995462f3391c1a610892df3f67dfa7bd`，下载时还会把 Hugging Face 数据 revision、文件大小和 SHA-256 写入 `manifest.json`。

## 获取数据

```bash
python scripts/fetch_longmemeval_v2.py \
  --output-dir ~/.cache/memguardos/longmemeval-v2 \
  --proxy http://127.0.0.1:7897
```

默认只下载问题、small tier haystack、schema、data card、许可证和官方校验清单。完整 `trajectories.jsonl` 约 1.2 GB，需要显式增加 `--include-trajectories`。截图包合计约 5.9 GB，纯文本 MemGuardOS 后端不下载截图，也不把外部数据本体提交进源码仓库。

## 运行检索层交叉验证

```bash
python scripts/run_longmemeval_v2.py \
  --trajectories ~/.cache/memguardos/longmemeval-v2/trajectories.jsonl \
  --questions ~/.cache/memguardos/longmemeval-v2/questions.jsonl \
  --work-dir outputs/longmemeval-v2/work \
  --output outputs/longmemeval-v2/result.json \
  --markdown outputs/longmemeval-v2/report.md
```

适配器实现官方定义的 `insert(trajectory)` 与 `query(question, query_image)` 形状，返回非空 `text/image` context items。报告中的“答案短语词面覆盖率”只是检索代理指标，用来检查上下文中是否出现参考答案短语；它不是官方答案准确率。只有配置官方 reader、答案评估器并运行完整 harness 后，才能报告准确率或 LAFS。

## 口径边界

外部交叉验证解决“全部样例由项目自行编写”的质疑，但不能单独证明生产环境泛化。文本后端忽略截图，因此多模态问题应在报告中单列；未配置 reader/judge 时，答案层状态必须保持 `not_run`。这一区分确保检索证据、生成答案和裁判指标不会被混为一谈。
