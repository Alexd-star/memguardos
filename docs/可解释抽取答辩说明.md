# MemGuardOS 可解释抽取答辩说明

本文用于回答评委关于“为什么默认抽取器主要采用规则、结构化语义信号和轻量策略，而不是默认调用大模型”的追问。结论是：MemGuardOS 的默认抽取路径是一个面向端侧操作系统环境的可复现基线，不是为了回避模型能力；系统同时保留本地 NER/LLM JSON 增强入口，并在增强器失败、超时或不可用时自动回退。

## 1. 设计选择

赛题要求作品能够在 openKylin 上正常编译、运行和测试，并强调端侧部署、低延迟、敏感治理、精准遗忘和 OS 机制结合。基于这个目标，MemGuardOS 将默认抽取器设计为“可解释混合抽取”：先做输入清洗、来源识别和敏感检测，再根据工具结果、手动配置、shell 行为、OS event、auditd 日志等来源提取偏好记忆、知识记忆和敏感策略记忆，并记录 `method`、`signals`、`confidence`、`quality` 等可审计信息。

这种设计的优势是评审环境可复现、离线可运行、延迟稳定、成本可控，并且便于解释每条记忆为什么被归为偏好、知识或安全策略。对操作系统赛题来说，稳定复验和审计链比一次性生成效果更重要。如果默认依赖外部 LLM API，评委复验时会受到网络、账号、余额、模型版本和随机输出影响；如果默认依赖本地大模型，又会提高硬件门槛，削弱端侧轻量化目标。

## 2. 不是简单正则

默认抽取器不是只靠孤立正则匹配。它结合了来源类型、文本结构、关键词簇、配置字段、命令语义、OS 路径风险、时间有效性和冲突处理策略。例如，手动配置中的 `answer.style=concise_with_risk` 会被识别为输出风格偏好；工具执行结果中的 `state_before`、`state_after` 和 `lesson` 会形成状态-动作-结果程序性记忆；auditd 中访问 `/etc/shadow` 的 PATH 事件会进入敏感 OS 事件链路；高风险 shell 命令会归入敏感策略或行为风险记忆。

系统还提供 `memctl explain-extraction`，用于展示抽取前的质量校验、敏感检测结果、记忆类型、子类型、摘要、置信度和命中的语义信号。这个解释能力能直接支撑答辩：评委不仅能看到最终结果，还能看到系统为什么这样抽取。

## 3. 与模型增强的关系

MemGuardOS 并不排斥模型增强。系统提供 `MEMGUARD_EXTRACTOR_COMMAND` 入口，可显式接入本地 NER、领域分类器或 LLM JSON 增强器。增强器必须返回约定 JSON schema，系统会校验输出结构、类型和字段。如果增强器超时、失败或返回不合法 JSON，系统会自动回退到默认可解释抽取器，保证核心功能和评测不会因为模型环境波动而失效。

答辩时建议这样表达：默认链路选择端侧可解释抽取，是为了满足 openKylin 可复验、低资源、低延迟和安全审计要求；模型增强作为可插拔能力存在，用于提升复杂自然语言泛化能力，但不作为默认依赖。这样既体现工程可靠性，也保留未来扩展空间。

## 4. 当前证据

当前 benchmark 已扩展到 217 条用例/种子，覆盖真实风格 auditd PATH 日志、shell history 行为、手动配置冲突、systemd exit-code 排障、Kylin SDK 超时修复、Peony 可见性刷新、Web 控制台 smoke 修复、精准遗忘 hard negative、中文偏好遗忘、自然语言敏感规则和状态-动作-结果程序性轨迹。本地评测中，类型识别准确率、子类型识别准确率、Recall@5、跨语言 Recall@5、敏感阻断 F1、精准遗忘候选精确率、精准遗忘候选召回率、图谱实体 Recall@5 和程序性记忆 Recall@5 均为 1.0000。

这些指标说明默认抽取器在赛题要求的 Linux/openKylin OS Agent 场景中不是演示级占位，而是可测试、可解释、可复现的工程基线。后续如果接入本地模型，评测方式也应保留默认链路作为对照基线，避免只展示不可复验的单次生成效果。

## 5. 答辩建议

被问到“为什么不用大模型抽取”时，不建议回答“规则已经够了”。更好的回答是：本作品的核心目标是构建操作系统级智能体记忆基础设施，默认链路必须离线可复验、低延迟、可审计、可部署；大模型适合做增强器，但不适合作为唯一默认依赖。我们已经预留本地 NER/LLM JSON 增强入口，且通过 fallback 保证模型失败时系统仍然可用。

被问到“规则泛化会不会弱”时，可以承认边界：复杂开放域表达上，大模型增强会更有优势；当前项目通过多源结构化信号、真实风格 benchmark、解释输出和可选增强接口降低这个风险。比赛阶段选择默认可复现链路，是为了让评委能在 openKylin 上稳定复验每一项指标和 OS 机制。
