# MemGuardOS 演示与测试实操手册

本手册回答三个问题：这个项目实际怎么用、你自己测试时按什么顺序做、录演示视频时每一步点什么说什么。已有的《演示视频脚本.md》给的是时间轴和台词要点，本手册给的是可以照着操作的具体步骤。

## 一、先建立正确的理解：搜索/遗忘不是主功能

网页里的"搜索记忆、查看记忆、精准遗忘"只是管理面。这个项目的主功能是一条**隐形循环**：

```
你和 Agent 正常干活 → 系统自动从交互中提取偏好和知识 → 下次任务自动注入上下文
→ Agent 不用你重复交代就按你的习惯做事 → 你偶尔收到"已记住 ××"的通知
→ 需要时才打开界面查看或遗忘
```

所以演示的主线是**让观众看到 Agent 因为记忆而变好**，管理界面只在"透明与控制"环节出场。围绕这条主线，项目有三层使用入口：

| 层 | 入口 | 谁在用 | 覆盖的功能 |
|---|---|---|---|
| 日常层 | 什么都不用点（自动）+ 托盘通知 | 普通用户 | 记忆自动产生、自动生效 |
| 控制层 | 托盘菜单、UKUI 设置页、Peony 右键、网页控制台 | 普通用户 | 查看、搜索、遗忘、内容保护 |
| 管理层 | 网页管理员视图、UKUI 管理员/系统维护页、CLI | 管理员/评委 | 审计链、证据导出、系统检查 |

命令行只在两处**必须**用：运行真实 OpenHands Agent、交互式 shell 体验。其余全部可以用桌面和网页完成。

## 二、自己测试时的完整流程（约 15 分钟）

在 openKylin 虚拟机上按顺序做一遍，每步都写了"预期看到什么"，看不到就是环境有问题。

### 第 1 步：确认服务健康（1 分钟）

打开 UKUI 设置 → 安全 → MemGuardOS 记忆安全（或托盘右键 → 打开记忆安全中心）。

预期：状态横幅显示"本机记忆安全状态正常"，就绪度进度条有数值，四个状态卡（记忆服务/安全记录/本机智能检索/桌面入口）都是"正常"。

### 第 2 步：一键闭环体验（2 分钟，命令行）

```bash
cd ~/memguardos
python3 -m memguard.cli.memguard demo
```

预期输出依次是：记忆注入（工具选择阶段命中 code_search_tool 偏好）→ 工具调用（`rg -n "MemGuardService" memguard`）→ 新增记忆 → 偏好生效证明 → 敏感保护 → 精准遗忘和逐项验证。这一条命令走完"产生→生效→保护→遗忘→留证"全链路，是理解项目最快的方式。

### 第 3 步：交互式体验，模拟真实使用（3 分钟，命令行）

```bash
python3 -m memguard.cli.memguard shell
```

在 shell 里依次输入：

```
以后回答 openKylin 问题时，先给 systemctl 命令，再解释原因
/preferences          # 看到刚才这句话被提取成偏好
/context 检查 memguardd 服务状态    # 看到偏好被注入上下文
/search systemctl     # 检索命中
/forget 忘掉 systemctl 相关偏好      # 先预览后确认，看逐项验证
/exit
```

这一步演示的就是"用户随口一句话 → 变成受管记忆 → 下次任务生效 → 可精准撤销"。

### 第 4 步：真实 OpenHands Agent（5 分钟，命令行，需要模型可用）

```bash
.venv-agent/bin/python scripts/run_openhands_memguard_demo.py \
  --namespace video-agent --session-id demo-a \
  --task "以后搜索代码使用 rg，先给命令再解释。请查找 build_agent_context 的定义。" \
  --max-iterations 8
```

预期：OpenHands 真实调用终端执行任务，交互事件自动进入 MemGuardOS；跑完后用**同一 namespace 开第二个会话**（`--session-id demo-b`，任务换成"查找 MemGuardService 的定义"），观察 Agent **没有被提醒就直接用了 rg、先给命令再解释**——这就是记忆价值的直接证据。

模型不可用时的兜底：网页控制台 → Agent 工作台 → 运行方式选"本地回放（可复现）"。回放会明确标注不是真实模型运行，演示时也要如实说明。

### 第 5 步：桌面集成（2 分钟，纯点击）

1. Peony 文件管理器里新建一个文本文件（内容写一条使用习惯 + 一行假 API Key），右键 → "使用 MemGuardOS 检查记忆内容"。预期：检查表格里习惯行"可导入"、密钥行"已保护"；勾选导入后弹出结果，可一键"撤销本次导入"。
2. 托盘右键 → 最近变化 → 五个入口逐个点。预期：每个都落到网页对应页面并有"已按桌面入口打开×××"提示。

### 第 6 步：网页控制台的管理面（2 分钟，纯点击）

托盘右键 → 打开本地控制台。总览确认状态 → 记忆中心搜索刚才的记忆 → 点"查看详情"核对来源和版本 → 内容保护页测试一段敏感文本 → 精准遗忘页预览并确认一次遗忘 → 管理员视图看审计链"完整"、导出证据包。

## 三、演示视频分镜脚本（3-5 分钟）

| 分镜 | 时长 | 画面与操作 | 台词要点 |
|---|---|---|---|
| 1 开场 | 20s | openKylin 桌面，打开 UKUI 设置页状态卡 | Agent 每次重启都失忆、还可能记住不该记的。MemGuardOS 把记忆做成 OS 管理的资源：可解释提取、可验证遗忘、全程审计 |
| 2 记忆产生 | 40s | 终端跑第 4 步会话 A（或 shell 输入一句习惯） | 用户只是正常交代任务，系统自动提取出工具偏好和回答习惯，不需要手动录入 |
| 3 记忆生效 | 50s | 会话 B：新会话不提醒，Agent 直接用 rg、先命令后解释；切网页 Agent 工作台展示"偏好生效证明：已观察到并通过" | 重点：我们只在观察到真实工具命令时才判定生效，注入不等于遵循 |
| 4 敏感保护 | 30s | Peony 右键扫描含假密钥的文件 | 高风险凭据在入口就被拦下，不进长期记忆、不进 Agent 上下文，动作全部留痕 |
| 5 精准遗忘 | 50s | 网页遗忘页：预览候选 → 确认 → 逐项复检；再回 Agent 工作台看该偏好从三阶段上下文消失、无关偏好仍在 | 遗忘是范围化的：删掉指定内容，保留其他；主记录、索引、段文件、上下文逐项验证 |
| 6 审计与 OS 集成 | 40s | 管理员视图审计链"完整"+ 导出证据包；快速闪过 systemd 服务、cgroup 资源限制、托盘通知 | 全链路操作可追溯；作为系统服务受资源限制管理，桌面三入口开箱即用 |
| 7 收尾 | 20s | 总览页 | 一句话：让 openKylin 上的 Agent 越用越懂你，同时每一条记忆可见、可控、可被验证地遗忘 |

录制注意：分辨率 1920×1080；画面里不出现真实密钥和个人信息（演示密钥用 `sk-demo-xxxx` 这类明显假值）；回放模式必须口头说明"这是可复现事件回放，不代表实时模型能力"；每个分镜之间留 1 秒停顿方便剪辑。

## 四、常见问题

- **网页打不开**：托盘右键 → 打开本地控制台会自动拉起并带凭证跳转；手动开的话需要 `memctl web` 并从终端输出里拿带 token 的地址。
- **真实 Agent 跑不动**：先确认模型配置（见《真实Agent接入使用说明.md》），确认 `.venv-agent` 存在；不行就用本地回放并如实标注。
- **虚拟机重启后桌面插件失效**：`/usr` 只读，插件用 bind-mount 安装，重启后执行 `sudo bash scripts/install_ukui_plugins.sh --no-build` 和 `sudo mount --bind /var/tmp/memguardos-ukui-visible/memguardos-tray /usr/bin/memguardos-tray` 恢复。
- **演示前想要干净数据**：换一个新 namespace（如 `--namespace video-agent`），不要删默认库。
