# 16 历史文件说明

本文档记录当前仓库中可能属于历史、过程、缓存或生成产物的文件类别。本文档只提出整理建议，不要求立即删除或移动任何文件。

## 1. 历史证据

`docs/evidence/latest/` 是当前最新证据入口，必须保留。若仓库中存在 `docs/evidence/openkylin_*` 或 `docs/evidence/kylin_embedding_diag_*` 目录，它们通常是历史 openKylin 证据或专项诊断证据。建议保留用于回溯，但正式提交包只应引用最新证据。

长期维护时，可建立 `archive/evidence/` 保存旧证据，并在 README 或本文件中说明最新证据仍以 `docs/evidence/latest/` 为准。

## 2. 研究资料

`docs/research/` 保存论文调研、网页内容、PDF、文本抽取和研究总结。它们对方案设计有价值，但不是正式竞赛主体。`docs/research/sources/` 尤其偏原始资料缓存，体积可能较大，适合完整仓库保留，不建议放入正式提交包。

## 3. 打包产物

`dist/` 保存 `memguardos_competition_submission_*.zip` 和 `memguardos_full_repository_*.zip`。这些文件可重新生成。发布前只需保留最新有效包，旧包可归档到 `archive/dist/` 或通过 GitHub Release 管理。

## 4. 本地缓存

`.pytest_cache/`、`.ruff_cache/`、`memguardos.egg-info/` 是本地开发产物，不属于作品主体。它们可由工具重建，正式提交包会排除。若需要清理仓库体积，可在确认无运行进程占用后删除这些缓存，但本次整理不执行删除。

## 5. 个人过程资料

`local_notes/` 若存在，属于个人过程记录。它可以帮助回顾开发过程，但不应进入正式评审材料。若其中有仍有价值的内容，应整理为正式中文文档后再引用，不应直接让评委阅读零散过程记录。

## 6. 疑似无用文件判断规则

判断文件是否无用不能只看名称，应结合引用关系、打包脚本、测试和文档链接。建议按以下顺序确认：先用 `rg` 查引用，再看是否进入正式包，再看是否属于测试数据或证据，最后才决定归档。未经确认不要删除。
