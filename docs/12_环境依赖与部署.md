# 12 环境依赖与部署

本文档汇总 MemGuardOS 的环境要求、依赖、部署路径和兼容性说明。详细命令见 [部署手册.md](部署手册.md)。

## 1. 基础环境

项目要求 Python 3.10+。默认核心依赖为空，目的是降低端侧部署难度。开发和测试需要 `pytest`、`pytest-cov`、`ruff`。Linux/openKylin 是主要复验环境，Windows 可用于源码开发和文档维护，但 systemd、auditd、BPF LSM、UKUI/Peony 等能力需要 Linux/openKylin。

## 2. openKylin 依赖

openKylin 复验建议安装 systemd、auditd、编译工具、UKUI/Peony 开发依赖、Kylin AI SDK 相关包和 BPF 工具链。并非所有依赖都是默认主链路必需项。例如 Kylin embedding SDK 是可选增强，缺失时系统应自动回退；BPF LSM 是安全测试路径，不影响普通写入检索。

## 3. 本地开发部署

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python scripts/demo_smoke.py
```

本地开发部署适合快速验证核心能力。若只使用 CLI、检索、遗忘、Web 控制台和测试数据，不需要 GPU，也不需要购买 LLM API。

## 4. 服务化部署

```bash
sudo bash scripts/install_openkylin.sh "$(pwd)"
sudo systemctl enable --now memguardd
systemctl status memguardd --no-pager
```

服务化部署会让 `memguardd` 作为 systemd 服务运行，并可通过模板服务验证多 namespace。服务日志进入 journald，资源限制可通过 cgroup 查看。

## 5. `.deb` 部署

```bash
bash scripts/build_deb.sh
sudo apt install ./dist/memguardos-core_0.1.0-2_amd64.deb \
  ./dist/memguardos-ukui_0.1.0-2_amd64.deb \
  ./dist/memguardos-agent-bridge_0.1.0-2_amd64.deb \
  ./dist/memguardos-doc_0.1.0-2_all.deb \
  ./dist/memguardos_0.1.0-2_all.deb
memctl doctor
```

`.deb` 部署用于展示产品化安装能力。当前交付采用五包拆分：`memguardos-core`、`memguardos-ukui`、`memguardos-agent-bridge`、`memguardos-doc` 和 `memguardos` 元包。openKylin 普通模式可能存在系统保护，完整 `apt install` 证据建议在维护模式下采集；不能进入维护模式时，应使用 `scripts/verify_deb_lifecycle.sh` 验证离线安装、包边界和用户数据保护。安装成功后应检查 `/usr/bin/memctl`、systemd 单元、Peony/UKUI/托盘资产、Polkit policy、插件依赖和 SDK 状态。

## 6. 兼容性边界

项目核心 Python 功能可在常见 Linux 环境运行。systemd/cgroup/auditd/BPF/UKUI/Kylin SDK 等功能依赖目标系统能力，缺失时应以诊断报告说明，而不是让主链路崩溃。Windows 环境适合开发和测试部分 Python 逻辑，但不代表 OS 集成能力。
