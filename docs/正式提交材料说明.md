# MemGuardOS 正式提交材料说明

本文说明竞赛正式提交包与完整工程仓库包的边界，避免把开发过程记录、协作模板或临时自检材料混入评审材料。

## 1. 正式竞赛提交包

正式提交包由 `scripts/package_submission.py` 生成，文件名形如：

```text
dist/memguardos_competition_submission_<时间戳>.zip
```

该包只包含以下内容：

| 类型 | 内容 |
|---|---|
| 作品主体代码 | `memguard/` |
| 部署、验证与 OS 集成脚本 | `scripts/` 中的安装、运行、验证、证据采集、auditd、BPF LSM、BPF 策略生成、UKUI、Web 控制台 smoke、Kylin SDK 探针脚本 |
| 原生增强源码 | `native/`，包含 BPF LSM、Peony 插件、UKUI 控制中心插件 |
| 测试与评测数据 | `tests/`、`data/` |
| 项目配置 | `pyproject.toml`、`LICENSE` |
| 正式中文文档 | README、最终提交说明、平台摘要、项目介绍、概要设计、详细设计、安全设计、OS 机制、部署手册、用户手册、企业级中文操作手册（Markdown、Word、PDF）、测试报告、赛题符合性说明、答辩提纲、答辩稿、演示视频脚本 |
| 评测报告 | `docs/eval_report*.md`、`docs/eval_result*.json` |
| openKylin 证据 | `docs/evidence/latest/` |

正式提交包不包含 Git 历史、虚拟环境、缓存、临时数据库、运行时段文件、个人笔记、过程追踪表、GitHub 协作模板、完整仓库维护材料，以及仅服务于开发过程的打包脚本、链接检查脚本、归档包 smoke 脚本和竞赛自检脚本。

## 2. 完整工程仓库包

完整仓库包文件名形如：

```text
dist/memguardos_full_repository_<时间戳>.zip
```

该包用于 GitHub Release、回溯备份和工程协作，除正式提交材料外，还包含：

| 类型 | 内容 |
|---|---|
| 工程协作材料 | `.github/`、`.devcontainer/`、Issue/PR 模板、CI 配置 |
| 维护文档 | `CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`、`CODE_OF_CONDUCT.md` |
| 自检与追踪材料 | 竞赛就绪自检报告、赛题逐句核查追踪表等 |
| 质量保证工具 | 提交包内容审计、release preflight、归档包解压 smoke 等脚本 |
| 开发环境支撑 | `Dockerfile`、`.dockerignore`、`.gitattributes` |

这些材料有利于代码维护和复现，但不作为正式参赛作品主体提交给评委。

## 3. 生成方式

正式提交包由完整工程仓库中的打包脚本生成。生成后的竞赛包不依赖打包脚本本身，也不包含打包脚本、自检脚本、链接检查脚本、归档包 smoke 脚本、CI 配置或过程追踪文档。竞赛平台提交优先使用 `memguardos_competition_submission_*.zip`；如需 GitHub Release、备份或工程协作，再使用 `memguardos_full_repository_*.zip`。

交付前建议在完整工程仓库中运行 `scripts/inspect_submission_package.py` 和 `scripts/smoke_submission_archive.py`。前者检查正式包内容边界，后者将正式包解压到临时目录并从解压后的源码运行核心 smoke，用于确认上传压缩包自身具备基础可运行性。
