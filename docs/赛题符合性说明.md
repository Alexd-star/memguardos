# MemGuardOS 赛题符合性说明

本文面向正式评审，按赛题核心要求说明 MemGuardOS 已完成的功能、指标和证据位置。

## 1. 总体符合性

MemGuardOS 已实现一套面向 Linux/openKylin 的智能体记忆系统，并接入现有 OpenHands Agent，覆盖用户-Agent 交互采集、偏好与知识记忆、三阶段上下文、敏感治理、范围化精准遗忘、OS 机制和量化评测。

| 赛题方向 | 完成情况 | 主要证据 |
|---|---|---|
| 多源数据整合 | 以 OpenHands 用户消息、反馈、工具调用和工具结果为主，文本、配置、shell、OS 事件和 auditd 为补充 | `memguard/integrations/`、`memguard/ingestion/` |
| 数据清洗与质量校验 | Unicode 标准化、空输入拒绝、低质量警告、质量分入审计 | `memguard/ingestion/quality.py`、`data/benchmarks/quality_validation.jsonl` |
| 偏好记忆动态捕捉 | 支持显式偏好、隐式习惯、纠正反馈、角色污染防护、版本回溯和时间有效性 | `interaction_extractor.py`、`habit_aggregator.py`、`docs/evidence/agent_latest/` |
| 知识记忆结构化 | 支持工作流、历史案例、模板、实体图谱、关联检索和冲突处理 | `memguard/extraction/`、`memguard/retrieval/conflict.py` |
| 跨语言检索 | 中文查询可召回英文 Linux/openKylin 历史案例 | `data/benchmarks/retrieval.jsonl`、`docs/eval_report.md` |
| RAG 生成链路 | 构建已脱敏上下文包、prompt 渲染和可选 LLM adapter | `memguard/llm/`、`memctl build-context`、`memctl build-prompt` |
| 端侧轻量部署 | 默认不依赖 GPU 和云端 API，使用 mmap 段文件、SQLite FTS、稳定 hash-vector | `memguard/store/`、`memguard/retrieval/hybrid.py` |
| openKylin SDK 适配 | Kylin 文本向量化 SDK 探针、可选重排后端、向量数据库 SDK 探针 | `docs/麒麟SDK集成证据.md` |
| 敏感识别 | 支持 PII、凭据、私钥、OS 高风险路径、自定义正则和自然语言敏感规则 | `memguard/sensitivity/`、`docs/安全设计说明书.md` |
| 精准遗忘 | 自然语言 dry-run、确认遗忘、旧版本有效窗口关闭、审计、compact、明文探针验证 | `memguard/forgetting/`、`memctl forget`、`memctl temporal-status`、`memctl verify-forget` |
| OS 机制 | mmap、namespace、systemd/cgroup、journald、auditd、BPF LSM、BPF JSON 策略生成、UKUI 原生插件源码 | `docs/操作系统机制说明.md`、`docs/evidence/latest/` |
| 产品化入口 | CLI、daemon、Unix socket API、本地 Web 控制台和 openKylin/Debian `.deb` 安装包 | `memguard/api/server.py`、`memguard/web/dashboard.py`、`scripts/build_deb.sh`、`memctl web` |
| 量化评测 | 覆盖准确率、Recall@5、F1、冲突正确率、延迟、资源、存储 | `memguard/eval/run_eval.py`、`docs/eval_report*.md` |

## 3. OS 机制覆盖

| OS 机制 | 赛题要求对应 | 完成情况 |
|---|---|---|
| mmap + 页缓存 | 版本化记忆存储、端侧轻量加载 | 已用于追加式段文件读取和 compact 后明文清除验证 |
| namespace 隔离 | 多会话记忆隔离 | 显式 namespace 使用独立段文件、SQLite、敏感规则和审计链 |
| systemd/cgroup | 资源管控 | 服务文件设置 `MemoryMax=512M`、`CPUQuota=50%`，模板服务支持多 namespace 实例 |
| journald | 记忆操作审计 | 关键操作镜像到 journald，并保留 SQLite 哈希审计链 |
| auditd | OS 安全事件结合 | 真实 auditd 敏感路径日志可转为 OS event 并触发高风险阻断 |
| BPF LSM | 可选强制拦截增强 | openKylin 上对安全测试文件完成 `file_open` 强制拒绝验证；支持 JSON 生成可审查静态 denylist |
| UKUI 联动 | 鼓励项 | Peony 右键菜单和 UKUI 控制中心入口均已在 openKylin 桌面可见验证 |

## 5. 表述边界

为保证评审材料准确，项目采用以下表述边界：

| 方向 | 准确表述 |
|---|---|
| 语义抽取 | 默认使用离线可复现的可解释混合抽取；显式配置后可调用本地 NER/LLM JSON 增强器，失败时回退 |
| Kylin embedding SDK | 已完成真实向量探针和可选重排后端；默认主路径保留稳定 FTS/hash/graph fallback |
| BPF LSM | 已在 openKylin 对安全测试文件强制拒绝；支持可审查策略生成；默认不拦截登录链路相关文件 |
| UKUI/Peony 插件 | Peony 右键菜单和 UKUI 控制中心入口均已在 openKylin 桌面可见验证 |
| 用户行为 | 支持 shell 行为、工具结果、OS 事件和 auditd 事件；不宣称全量桌面行为捕获 |
| 外部 LLM | 默认不依赖外部 API；可选 adapter 仅在显式配置后调用 |
| Web 控制台 | 本地演示和评审入口，默认绑定 `127.0.0.1`；不宣称公网 SaaS 或多租户管理台 |
