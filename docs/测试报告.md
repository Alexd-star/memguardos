困难样例覆盖：当前 benchmark 包含 45 条种子记忆、40 条检索用例、25 条敏感检测用例、20 条精准遗忘用例、10 条冲突解决用例、13 条图谱检索用例、6 条数据质量用例，覆盖真实风格 auditd PATH 日志、shell history 行为、手动配置冲突、生产 OOM 故障、可选语义抽取、fanotify/eBPF 风格事件、精准遗忘 hard negative、中文偏好定向遗忘、rg/grep 冲突、高风险确认策略冲突、上下文 token 预算、UKUI 轻量通知、本地 Agent API、自然语言敏感规则、Kylin 可选检索、并发审计、namespace/cgroup、AWS/Kubernetes/service account 高风险路径、空输入拒绝、无信号输入拒绝、文本标准化等场景。原生增强证据另外覆盖 BPF LSM 强制拒绝、BPF denylist 策略生成、Peony/UKUI 插件构建和 Peony 右键菜单可见验证。

Agent 批量检索评测覆盖任务规划、工具调用、结果生成和安全策略四类查询：4 个子查询、4 个 worker、每个子查询至少命中 1 条记忆。本地基准 P95 为 3.580 ms；最新 openKylin 10k 评测中的 Agent 批量检索 P95 为 19.257 ms，采证脚本中的 3 查询 smoke P95 为 6.754 ms，审计链均验证通过。该能力用于证明真实 OS Agent 不必逐次串行调用记忆系统，也不必为每个只读子查询写一条审计事件；系统以一次 `batch_search` 审计事件记录整批读操作，降低并发读路径开销。

扩充 benchmark 后的 openKylin 10k 规模评测：150 次查询，P95 为 23.112 ms，P99 为 119.567 ms，RSS 为 128764.0 KB，仍低于 500 ms 目标。并发检索评测中，6 worker、150 次查询的 P95 为 233.232 ms，P99 为 325.842 ms，二者均低于 500 ms；后续仍可把 P99 作为持续优化观察项，但当前已经不再是提交前风险。该报告已包含 10 条冲突解决用例和 6 条数据质量用例。
