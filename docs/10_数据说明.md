# 10 数据说明

本文档说明项目中的数据目录、数据对象、benchmark 文件和运行时数据位置。项目严禁把真实凭据、真实隐私或私人日志作为样例提交。

## 1. 仓库内数据

`data/demo/` 保存演示输入，适合快速验证写入和检索。`data/benchmarks/` 保存评测样例，供 `memguard/eval/run_eval.py` 读取。样例文件均应使用脱敏、合成或可公开的内容。

| 文件 | 作用 |
|---|---|
| `data/demo/user_config.json` | 配置导入演示。 |
| `data/demo/tool_result_success.json` | 工具执行结果和程序性记忆演示。 |
| `data/demo/linux_workflow.md` | Linux 工作流文本演示。 |
| `data/demo/bpf_lsm_policy.json` | BPF LSM denylist 策略生成演示。 |
| `data/benchmarks/memory_seed.jsonl` | 评测前写入的基础记忆样例。 |
| `data/benchmarks/retrieval.jsonl` | 检索 Recall@5 样例。 |
| `data/benchmarks/forgetting.jsonl` | 精准遗忘候选样例。 |
| `data/benchmarks/sensitive_detection.jsonl` | 敏感检测样例。 |
| `data/benchmarks/procedural_memory.jsonl` | 程序性记忆样例。 |
| `data/benchmarks/graph_retrieval.jsonl` | 图谱检索样例。 |

## 2. 运行时数据

默认运行时数据不应写入仓库。根据当前代码推断，系统会根据 `memguard/config.py` 选择本地用户目录，并按 namespace 创建段文件、SQLite 数据库和自定义敏感规则文件。运行时数据包括记忆段文件、元数据数据库、审计链和 namespace 状态。

## 3. 数据对象

核心数据对象是 MemoryRecord。它包含 ID、来源、类型、文本、标签、敏感信息、版本信息、审计信息、时间有效性和扩展字段。存储层会把载荷写入段文件，把索引字段写入 SQLite。检索结果通常由 MemoryRecord 派生，但会增加分数、匹配来源和解释字段。

## 4. 数据导入规则

文本导入要求非空、长度可控、编码可处理。配置导入会展开 JSON/YAML 类结构，形成键值路径记忆。工具结果导入会读取命令、退出码、标准输出、标准错误、状态前后和经验字段。shell history 导入会过滤明显噪声命令，保留具有记忆价值的行为。

## 5. 数据导出与证据

评测结果导出到 `docs/eval_result*.json` 和 `docs/eval_report*.md`。openKylin 证据导出到 `docs/evidence/latest/`。正式竞赛提交包会包含必要数据样例、评测结果和最新证据，但不包含运行时数据库、段文件、缓存或个人笔记。

## 6. 数据安全要求

新增样例前必须检查是否包含真实手机号、真实地址、真实 token、真实私钥、真实账号密码或私人路径。如果必须展示敏感治理效果，应使用合成数据或明显无效的示例。提交前应运行测试和提交包审计，确保正式文档不包含本机绝对路径和个人信息。
