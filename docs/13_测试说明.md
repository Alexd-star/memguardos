# 13 测试说明

本文档说明 MemGuardOS 的测试体系、指标口径和发布前验证步骤。详细指标见 [测试报告.md](测试报告.md)。

## 1. 单元测试

核心单元测试位于 `tests/test_core.py`，覆盖 namespace、写入检索、敏感治理、精准遗忘、compact、版本回滚、审计链、OS 事件、auditd、冲突处理、Kylin SDK fallback、程序性记忆、图谱检索、API、daemon 和 demo smoke。

```bash
python -m pytest -q
```

当前工作树最近一次本地全量口径为 `627 passed, 14 skipped`。`docs/evidence/openkylin_native_latest/` 保留上一次 openKylin 实机快照；本轮最终源代码提交后会重新执行目标系统全量测试，并由同目录 `source_revision.json` 与 `pytest_openkylin.txt` 固化新结果。本地跳过的是 Linux 专属测试，目标系统会实际执行，因此两端计数不同是预期行为。真实 Agent 专项 benchmark 另含 200 条交互样例，不与通用 217 条用例/种子和检索消融实验简单相加。

## 2. Lint 检查

```bash
python -m ruff check .
```

Lint 用于检查 Python 代码风格和潜在问题。它不能替代测试，但可以在提交前提前发现导入、格式和简单错误。

## 3. 评测脚本

```bash
python -m memguard.eval.run_eval --latency-size 1000 --latency-queries 120 --output docs/eval_result.json --markdown docs/eval_report.md
python -m memguard.eval.run_eval --latency-size 10000 --latency-queries 150 --output docs/eval_result_openkylin_10k.json --markdown docs/eval_report_openkylin_10k.md
```

评测覆盖偏好/知识抽取、检索 Recall、跨语言召回、敏感检测、精准遗忘、冲突处理、程序性记忆、上下文解释性、负载延迟、资源占用和并发检索。

## 4. 文档链接检查

```bash
python scripts/check_docs_links.py
```

该脚本扫描 Markdown 中的本地链接，发现断链时返回失败。新增文档或重命名文件后必须运行。

## 5. 竞赛就绪检查

```bash
python scripts/check_competition_ready.py --output docs/competition_ready.json --markdown docs/竞赛就绪自检报告.md
```

该脚本检查必须文档、真实 Agent 源码与证据、通用指标、openKylin 证据、`.deb` 安装证据和仓库卫生。门禁项数量随新增能力动态生成，应以 `python scripts/check_competition_ready.py` 的最新输出为准，不在文档中固化过期总数。

## 6. 提交包审计

```bash
python scripts/package_submission.py
python scripts/inspect_submission_package.py
python scripts/smoke_submission_archive.py
```

打包后应审计正式包是否缺文件、是否混入过程材料、是否包含本机绝对路径，随后从解压后的提交包运行 smoke，证明上传包具备基础可运行性。

## 7. openKylin 证据复跑

通用证据复跑使用 `scripts/openkylin_verify.sh` 和 `scripts/collect_openkylin_evidence.sh --with-10k`；真实 Agent 证据复跑使用 `scripts/collect_agent_evidence.sh`。正式材料分别引用 `docs/evidence/latest/` 与 `docs/evidence/agent_latest/`。
