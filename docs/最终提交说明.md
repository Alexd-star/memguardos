# MemGuardOS 最终提交说明

本文面向竞赛平台提交和评审材料核对，说明 MemGuardOS 作品的提交内容、阅读顺序、运行验证方式、关键指标和能力边界。本文可以作为平台附件说明、作品压缩包说明或提交页“项目说明”长文本使用。

## 1. 作品基本信息

| 项目 | 内容 |
|---|---|
| 作品名称 | MemGuardOS |
| 赛题方向 | 研究生操作系统开源创新大赛赛题 3：面向 Linux 的智能体记忆提取与精准遗忘机制 |
| 作品类型 | Linux/openKylin 本地智能体记忆系统原型 |
| 推荐运行环境 | openKylin 2.0 SP2 / Linux，Python 3.9+ |
| 核心技术路线 | OpenHands 事件适配、分阶段上下文注入、mmap 追加式存储、SQLite FTS、稳定 hash-vector、图谱关联、审计哈希链、systemd/cgroup、auditd、BPF LSM、UKUI 原生插件 |
| 默认部署方式 | 本地命令行、后台 daemon、Unix socket API、本地 Web 控制台、openKylin/Debian `.deb` 安装包 |
| 外部依赖边界 | 默认不依赖外部 LLM API、GPU 或云端向量数据库 |
| 开源许可证 | MIT License |

最终提交代码分支以 `feature/real-agent-foundation` 为准。该分支包含真实 Agent 接入、openKylin 原生化、EvidenceBench v2、自然语言遗忘意图编译器、桌面集成和最新证据包。若平台或评委默认拉取 `main`，请先合并该分支，或在提交材料中明确声明评审分支与对应提交号。

MemGuardOS 的目标是为 Linux/openKylin 上的 OS Agent 提供一套可落地的记忆基础设施。系统已接入现有 OpenHands Agent，从用户消息、Agent 消息、纠正反馈、工具调用和工具结果中自动提取偏好、习惯、知识和安全策略，并在后续会话的任务规划、工具选择和结果生成阶段注入经过脱敏、预算控制和来源解释的上下文。文本、配置、shell 和 OS 审计数据作为补充来源。当用户要求遗忘某类交互时，系统支持按 Agent、会话、轮次、主题和时间范围定位，清理事件载荷、派生记忆、索引、图谱与 compact 后段文件明文。

## 4. 核心能力摘要

MemGuardOS 已完成以下能力闭环：

| 能力域 | 完成内容 |
|---|---|
| 多源记忆提取 | 以 OpenHands 用户-Agent 消息、反馈、工具调用和工具结果为主，支持文本、配置、shell、OS 事件和 auditd 补充数据 |
| 记忆类型建模 | 支持偏好记忆、知识记忆、敏感策略记忆，支持 working/session/long_term 三层记忆 |
| 可解释抽取 | 默认使用离线可复现的规则与结构化语义信号，记录 `method`、`signals`、`confidence`，可显式接入本地 NER/LLM JSON 增强器 |
| 轻量存储 | mmap 追加式段文件存放正文，SQLite 存放元数据、FTS、版本、图谱和审计链 |
| 混合检索 | FTS、稳定 hash-vector、图谱实体召回、跨语言技术词扩展、冲突解决和批量检索 |
| RAG 上下文 | 构建脱敏后的上下文包，输出 token 预算估算和 provider-neutral prompt |
| 精准遗忘 | 自然语言与 Agent/session/turn/topic/time 范围 dry-run、确认删除、事件载荷清理、tombstone、索引/图谱清理、compact、泄漏探针验证 |
| 来源信誉治理 | 外部网页、远程抓取和提示注入类内容进入隔离区，审批通过后才进入检索/RAG，拒绝写入 tombstone 和审计 |
| 敏感治理 | PII、凭据、私钥、银行卡、中文地址、OS 高风险路径、自定义规则和自然语言敏感规则 |
| 多会话隔离 | namespace 独立段文件、SQLite 元数据、敏感规则和审计链；systemd 模板服务独立 cgroup |
| OS 集成 | systemd、cgroup、journald、auditd、BPF LSM 安全测试强制拦截、UKUI/Peony 原生插件源码 |
| Agent 接入 | OpenHands runner/Hook、统一事件协议、跨会话三阶段上下文、systemd bridge、CLI、Unix socket API 和 Web Agent 治理页 |
| openKylin SDK | Kylin embedding/vector SDK 探测，可选 embedding 重排后端，默认保留稳定 fallback |
| Web 与企业交付 | viewer/operator/admin 角色 token、health/readiness、拒绝审计、严格资源对照、SLO 门禁、可校验备份恢复、release attestation 和 Nginx HTTPS 模板 |
| 外部基准适配 | LongMemEval-V2 官方 schema 兼容后端，记录上游 revision，检索层与答案生成层指标分开报告 |

## 6. 快速复验命令

### 6.1 本地复验

```powershell
cd <项目目录>
python -m pip install -e ".[dev]"
python scripts\release_preflight.py
```

`release_preflight.py` 会依次运行编译检查、ruff、单元测试、文档链接检查、本地 Web 控制台 smoke、竞赛就绪自检和提交包生成。若只想快速复验而不重新打包，可追加 `--skip-package`。该脚本输出的 `docs\release_preflight.json` 属于本地自检报告，不作为正式提交包主体。

提交包生成后建议再运行内容审计：

```powershell
python scripts\inspect_submission_package.py
```

审计脚本会核对正式包是否包含核心代码、部署脚本、原生增强源码、中文文档和 openKylin 证据，并确认未混入 `.github`、预检脚本、过程自检报告、缓存、虚拟环境、SQLite 数据库、mmap 段文件等不应提交的材料。

为进一步确认“上传到平台的 zip 本身”可以独立完成核心演示，可继续运行归档包 smoke：

```powershell
python scripts\smoke_submission_archive.py
```

该脚本会选择最新 `memguardos_competition_submission_*.zip`，先执行正式包内容审计，再把压缩包解压到临时目录，并在解压后的目录内运行编译检查、CLI 演示 smoke 和 Web 控制台 smoke。该步骤用于交付前质量保证，不属于评审阅读材料，也不会进入正式竞赛提交包。

### 6.2 openKylin 复验

```bash
cd ~/memguardos
source .venv/bin/activate
python -m pytest -q
bash scripts/openkylin_verify.sh
bash scripts/collect_openkylin_evidence.sh --with-10k
bash scripts/collect_agent_evidence.sh
```

### 6.3 生成最终提交包

```powershell
cd <项目目录>
python scripts\release_preflight.py

python scripts\inspect_submission_package.py
```

执行后在 `dist/` 目录生成竞赛提交包和完整仓库包。竞赛平台优先上传 `memguardos_competition_submission_*.zip`。

## 8. 现场答辩建议

答辩时建议先讲“为什么这是操作系统赛题作品”，再讲“智能体记忆系统如何闭环”，最后讲“指标和证据如何复验”。推荐主线如下：

3. 系统接入了真实 OpenHands Agent，覆盖用户交互自动采集、偏好与习惯提取、三阶段上下文复用、范围化精准遗忘、审计和 OS 机制。
