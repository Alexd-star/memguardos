# MemGuardOS 最终提交说明

本文面向竞赛平台提交和评审材料核对，说明 MemGuardOS 作品的提交内容、阅读顺序、运行验证方式、关键指标和能力边界。本文可以作为平台附件说明、作品压缩包说明或提交页“项目说明”长文本使用。

## 1. 作品基本信息

| 项目 | 内容 |
|---|---|
| 作品名称 | MemGuardOS |
| 赛题方向 | 研究生操作系统开源创新大赛赛题 3：面向 Linux 的智能体记忆提取与精准遗忘机制 |
| 作品类型 | Linux/openKylin 本地智能体记忆系统原型 |
| 推荐运行环境 | openKylin 2.0 SP2 / Linux，Python 3.9+ |
| 核心技术路线 | mmap 追加式存储、SQLite FTS、稳定 hash-vector、图谱关联、审计哈希链、systemd/cgroup、auditd、BPF LSM 可选增强、UKUI 原生插件源码 |
| 默认部署方式 | 本地命令行、后台 daemon、Unix socket API、本地 Web 控制台、openKylin/Debian `.deb` 安装包 |
| 外部依赖边界 | 默认不依赖外部 LLM API、GPU 或云端向量数据库 |
| 开源许可证 | MIT License |

MemGuardOS 的目标是为 Linux/openKylin 上的 OS Agent 提供一套可落地的记忆基础设施。系统从文本、文件、结构化配置、shell 行为、工具执行结果、OS 事件和 auditd 日志中提取偏好、知识和安全策略记忆，并在生成式智能体使用这些记忆前完成检索、脱敏、上下文预算控制和审计记录。当用户要求遗忘某类信息时，系统支持自然语言定位候选、dry-run 预览、确认删除、墓碑标记、索引清理、段文件 compact 和明文泄漏探针验证。

## 4. 核心能力摘要

MemGuardOS 已完成以下能力闭环：

| 能力域 | 完成内容 |
|---|---|
| 多源记忆提取 | 支持文本、文件、结构化配置、shell 行为、工具执行结果、OS 事件和 auditd 审计日志 |
| 记忆类型建模 | 支持偏好记忆、知识记忆、敏感策略记忆，支持 working/session/long_term 三层记忆 |
| 可解释抽取 | 默认使用离线可复现的规则与结构化语义信号，记录 `method`、`signals`、`confidence`，可显式接入本地 NER/LLM JSON 增强器 |
| 轻量存储 | mmap 追加式段文件存放正文，SQLite 存放元数据、FTS、版本、图谱和审计链 |
| 混合检索 | FTS、稳定 hash-vector、图谱实体召回、跨语言技术词扩展、冲突解决和批量检索 |
| RAG 上下文 | 构建脱敏后的上下文包，输出 token 预算估算和 provider-neutral prompt |
| 精准遗忘 | 自然语言 dry-run、确认删除、tombstone、索引清理、段文件 compact、泄漏探针验证 |
| 敏感治理 | PII、凭据、私钥、银行卡、中文地址、OS 高风险路径、自定义规则和自然语言敏感规则 |
| 多会话隔离 | namespace 独立段文件、SQLite 元数据、敏感规则和审计链；systemd 模板服务独立 cgroup |
| OS 集成 | systemd、cgroup、journald、auditd、BPF LSM 安全测试强制拦截、UKUI/Peony 原生插件源码 |
| Agent 接入 | CLI、daemon、Unix socket JSON API、本地 Web 控制台 |
| openKylin SDK | Kylin embedding/vector SDK 探测，可选 embedding 重排后端，默认保留稳定 fallback |

## 6. 快速复验命令

### 6.1 本地复验

```powershell
cd <项目目录>
python -m pip install -e ".[dev]"
python scripts\release_preflight.py
```

`release_preflight.py` 会依次运行编译检查、ruff、单元测试、文档链接检查、本地 Web 控制台 smoke、竞赛就绪自检和提交包生成。若只想快速复验而不重新打包，可追加 `--skip-package`。该脚本输出的 `docs\release_preflight.json` 属于本地自检报告，不作为正式提交包主体。

提交包生成后建议再运行内容审计：

```powershell
python scripts\inspect_submission_package.py
```

审计脚本会核对正式包是否包含核心代码、部署脚本、原生增强源码、中文文档和 openKylin 证据，并确认未混入 `.github`、预检脚本、过程自检报告、缓存、虚拟环境、SQLite 数据库、mmap 段文件等不应提交的材料。

为进一步确认“上传到平台的 zip 本身”可以独立完成核心演示，可继续运行归档包 smoke：

```powershell
python scripts\smoke_submission_archive.py
```

该脚本会选择最新 `memguardos_competition_submission_*.zip`，先执行正式包内容审计，再把压缩包解压到临时目录，并在解压后的目录内运行编译检查、CLI 演示 smoke 和 Web 控制台 smoke。该步骤用于交付前质量保证，不属于评审阅读材料，也不会进入正式竞赛提交包。

### 6.2 openKylin 复验

```bash
cd ~/memguardos
source .venv/bin/activate
python -m pytest -q
bash scripts/openkylin_verify.sh
bash scripts/collect_openkylin_evidence.sh --with-10k
```

### 6.3 生成最终提交包

```powershell
cd <项目目录>
python scripts\release_preflight.py
python scripts\package_submission.py
python scripts\inspect_submission_package.py
python scripts\smoke_submission_archive.py
```

执行后在 `dist/` 目录生成竞赛提交包和完整仓库包。竞赛平台优先上传 `memguardos_competition_submission_*.zip`。

## 8. 现场答辩建议

答辩时建议先讲“为什么这是操作系统赛题作品”，再讲“智能体记忆系统如何闭环”，最后讲“指标和证据如何复验”。推荐主线如下：

1. OS Agent 的记忆问题不是普通聊天记录问题，它涉及长期偏好、工具轨迹、系统事件、敏感凭据和可证明删除。
2. MemGuardOS 采用本地轻量架构，默认不依赖云端 API 或 GPU，适合 openKylin 端侧部署。
3. 系统覆盖多源接入、记忆抽取、敏感治理、混合检索、RAG 上下文、精准遗忘、审计和 OS 机制。
4. 与一般 RAG demo 相比，MemGuardOS 的差异在于 mmap 段存储、SQLite FTS、namespace 隔离、systemd/cgroup、auditd、BPF LSM、Peony 右键菜单可见验证、UKUI 控制中心可见验证和可复验证据包。
5. 指标以 openKylin 复验为准，10k 规模 P95 为 19.115 ms，关键准确率和 F1 指标均在当前 benchmark 上达到 1.0000。

## 9. 准确边界

为避免能力夸大，正式提交和答辩中请保持以下表述：

| 方向 | 准确表述 |
|---|---|
| 默认抽取器 | 默认是端侧可解释抽取，适合稳定复现；可显式配置本地 NER/LLM 增强器 |
| 外部 LLM | 默认不依赖外部 API；生成回答由可选 adapter 或上游 Agent 完成 |
| Kylin embedding SDK | 已完成真实向量探针和可选重排后端；默认检索仍保留 FTS/hash/graph fallback |
| BPF LSM | 已在 openKylin 对安全测试文件完成强制拒绝；默认不拦截 `/etc/shadow`、SSH、sudo 或 PAM 链路 |
| UKUI/Peony 插件 | Peony 右键菜单已在 openKylin 桌面可见验证；UKUI 控制中心入口“MemGuardOS 记忆安全”已在设置界面可见验证，当前源码提供本机运维面板 |
| Web 控制台 | 是 localhost 评审演示和本地调试入口，不是公网 SaaS 管理台 |
| 用户行为采集 | 支持 shell 行为、工具结果、OS 事件和 auditd 事件，不宣称全量桌面行为捕获 |

这些边界不会削弱作品价值，反而能体现工程真实性：系统把稳定可复现的主链路做好，并对更深层系统集成给出可验证、可扩展的增强路径。
