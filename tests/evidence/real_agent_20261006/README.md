## 运行情况

第一轮使用原配置 `openai/gpt-5.4`，接口报告该模型停用，七次会话均未通过。该轮只有接口失败和本地产品检查，不能作为模型成功效果。

第二轮临时使用同接口列出的 `openai/gpt-5.5`，在第 8 修订版上运行七次真实会话。关闭记忆查函数、采用更新后的事实回答、参数化流程复用与来源撤回三次通过；其余四次未通过。原始 JSON 包含任务、SDK 事件、完整可见文本、文件变化和失败判定，模型名称指接口报告的标识。

这一轮实际发现了复合命令的工具识别偏差、工具输出误形成用户偏好，以及流程任务在六次迭代上限内未完成最终回答的问题。第 9 修订版统一了 Hook、行为判定和反馈的引号感知解析，按调用编号对应并行结果，将工具文本固定归为执行知识，并显示 SDK 错误原因。展示脚本的会话上限统一调整为十次，不把模型已修改文件但仍未完成回答的情况判成完整任务成功。第 9 修订版在 openKylin 的成组回归为 171 项通过。

第三轮在第 9 修订版的正常模式启动后，虚拟机失去 SSH 与 VMware Tools 响应。恢复后取得两条原始记录，其中开启记忆的 A01 已通过，关闭记忆的一侧仍未完成；这轮作为中断记录保留，没有补写成功汇总。上一启动的系统日志记录了内存压力和页面分配失败，恢复后还观察到系统自带推理服务占用约 3.9 GB 内存，因此临时停止该服务，并为后续验证设置内存、CPU、进程数及总时限约束。该服务没有卸载或永久禁用。

第四轮使用正常模式下的第 9 修订版，临时任务内存上限为 1600 MB、交换上限为 256 MB、CPU 配额为单核、进程上限为 128、总时限为 20 分钟。七次真实模型会话全部通过，详细结果位于 `real-agent-showcase-20261006-attempt4`。开启记忆的会话实际使用 rg，关闭记忆的一侧使用 grep，两侧均完成任务；自然语言纠正后采用 grep；单项遗忘撤回工具偏好并保留回答偏好。事实冲突处理后，模型使用更新后的周五回答。流程任务由 Agent 实际修改文件，并由独立后置条件核验；新参数复用、来源更新停用、旧上下文失效与派生清理同时通过。

短密码拒存与会话临时记忆隔离来自正式产品 API 检查，不计入七次模型会话。以上是这组具体真实任务的结果，尚不足以推导任意任务成功率或主流 benchmark 的总体提升。验证完成后，经用户同意，日常 CLI 默认模型改为 `openai/gpt-5.5`，原密钥和接口地址保持不变；实际默认配置和恢复状态见 `recovery_and_model_20261006.json`。
